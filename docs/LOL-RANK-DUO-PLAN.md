## A. 리더보드 채우기 — 연결된 279명부터

### 무엇을 하나

1. **랭크 스냅샷 매일** (`npm run worker -- rank`) — 계정 321개 × 하루 1회. 하루 안 쌓으면 그날은 영원히 구멍이다(CLAUDE.md 시한부 2)
2. **솔랭 경기 수집** (`worker -- loop`: 신규 경기 + 2년 백필) — match-v5 보존이 2년이라 미룬 만큼 영구히 사라진다(시한부 1)
3. **조우 파생**(Engine D)이 같은 팀·맞대결을 만든다 — B 의 듀오 전적이 바로 이 "같은 팀" 조우다

### 키 종류가 운영 방식을 정한다

| | Development 키 | Personal 키 |
|---|---|---|
| 수명 | **24시간** — 매일 재발급해 갈아 끼워야 한다 | 만료 없음 |
| 한도 | 20/s · 100/2분 | 더 넉넉하다 |
| 랭크 321개 | 약 7분/일 — 충분하다 | 충분하다 |
| 2년 백필 | 계정 321개면 **며칠~몇 주**(문서 실측: 44계정에 33시간) | 현실적 |
| 운영 | 매일 사람이 키를 바꿔야 하고, 끊긴 날은 랭크가 빈다 | 워커를 상시로 돌릴 수 있다 |

### 순서

1. **확인** — 키 종류(Personal 신청 상태), 예전 수집분이 왜 0건인지
2. **랭크부터** — 하루치가 가장 싸고 가장 시한부다. 매일 같은 시각에 돌도록 걸어 둔다(`ck-auto.sh` 를 거는 방식과 같은 systemd 타이머)
3. **백필은 최근부터 2년 쪽으로** — 이번 시즌 솔랭이 먼저 차야 목록·듀오가 의미가 생긴다. 백필 커서는 이미 "최근 → 과거" 로 내려간다
4. **목록 화면 조정** — 티어가 차면 `/lol/streamers` 의 정렬·표시를 실데이터로 본다(PLAN §M2.5 "데이터 채운 뒤 UI 조정")
5. **(선택) 계정 연결 넓히기** — 279명 밖은 근거가 있을 때만 연결한다(원칙 2). 다른 사이트를 긁어 계정을 찾지 않는다(원칙 9)

- 첫날: 스냅샷 321행(언랭도 행이 남는다 — 구멍과 구분), `/lol/streamers` 티어 칸이 찬다

## B. 듀오 특별 콘텐츠 모듈

### 무엇을 보여주나

"둘이 같은 팀으로 솔랭을 몇 판 했고 어떻게 됐나" 만. (아래 숫자·이름 조합은 **화면 모양을 보이기 위한 예시**다) 개인 전적 사이트를 또 만드는 게 아니라, **스트리머끼리의 관계**(이 사이트의 정의)를 콘텐츠 단위로 보여준다.

```
뜨교듀오  (뜨뜨뜨뜨- × 김민교)          2026-09-14 ~ 진행 중 · 공지 ↗
────────────────────────────────────────────────────────
 함께한 솔랭  86판   52승 34패   보정 승률 59%  (표본 86)
 지금 티어    뜨뜨뜨뜨- D2 34LP  ·  김민교 P1 70LP   (매일 스냅샷)
 [티어 추이 — 두 사람 LP 를 한 그래프에, 콘텐츠 시작일 표시]
 조합 TOP      리븐+리신 9판 6승 · …
 포지션        탑/정글 61% · …
 연승·연패     최장 7연승 · 지금 2연패
 최근 경기     10/2 승 리븐/리신 12/3/5 · …
```

- **기간을 콘텐츠로 자른다** — 듀오 콘텐츠 시작일(~ 종료일)부터. 그 전의 우연한 같은 팀 판은 섞지 않는다
- **표본이 작으면 작다고 말한다** — 승률은 베이지안 보정(α=4, μ=0.5) + 판수 표기(원칙 3). 기존 `affinity` 를 쓴다
- **티어 추이는 매일 스냅샷**으로만 그린다 — Riot 은 판마다 LP 를 주지 않고, 과거 티어도 주지 않는다. 수집 시작 전 날짜는 비워 두고 "기록 시작" 을 표시한다

### "듀오" 를 어떻게 판정하나 — 추정이라고 말한다

- match-v5 에는 **"같이 큐를 돌렸다" 는 표시가 없다.** 솔랭(420)은 2인 파티만 허용하므로, 등록 스트리머 둘이 **같은 판 같은 팀**이면 듀오일 가능성이 매우 높지만, 우연히 같은 팀에 걸린 판도 섞일 수 있다(같은 티어대 스트리머끼리는 드물지 않다)
- 그래서 화면 문구는 **"같은 팀 솔랭(듀오 추정)"** 이다. 콘텐츠 기간으로 자르면 우연한 판은 거의 빠진다
- 데이터는 **이미 있는 조우(`streamer_encounter`, relation=ally, queue 420)** 를 그대로 쓴다. 새로 수집할 것은 없다

### 어떤 듀오를 콘텐츠로 올리나 — 사람이 정한다

- **후보 자동 찾기**: 최근 N일 같은 팀 솔랭이 K판 이상인 쌍을 관리자에게 보여 준다(조우에서 계산 — 비용 0)
- **올리는 건 사람**: 이름("뜨교듀오")·두 사람·시작일(~종료일)·근거(공지·VOD 주소)·소개를 적는다. 근거 없는 콘텐츠는 만들지 않는다(원칙 2 와 같은 이유 — 둘의 관계를 공개적으로 말하는 것이다)
- 저장 위치: 듀오 정의는 **편집 판단**이라 모듈 것이다 → `mod_duo.feature` (모듈 자기 스키마). 관리자 입력은 처음엔 **설정 파일**(`packages/modules/duo/features.json`, 커밋으로 관리)로 시작한다. 콘텐츠가 몇 개 수준이라 폼이 필요 없다 — 늘어나면 관리자 화면을 붙인다

### 화면·위치

| 부분 | 위치 |
|---|---|
| 듀오 목록 `/lol/duo` · 듀오 하나 `/lol/duo/[slug]` | 롤 공간 모듈 `packages/modules/duo` (`site: lol`) |
| 데이터 | 계약의 기존 함수(`listEncountersBetween` · `listMatchRosters` · `listRankSeries` · `affinity`) — 모자라면 계약에 추가한다 |
| 진입 | 롤 머리말 메뉴 "듀오", 두 사람 프로필, 상대전적 화면의 "같은 팀" 탭에서 역할 `duo` 로 링크 |

### 순서

1. A 의 랭크·솔랭 수집이 돌기 시작한다(B 의 선행 조건). 두 사람의 롤 계정이 연결돼 있어야 한다 —
   **뜨뜨뜨뜨-(`seokwngud`)는 지금 롤 계정이 연결돼 있지 않다**(듀오 상대가 맞다면 근거와 함께 먼저 연결)
2. 모듈 뼈대 + 설정 파일 + `/lol/duo/[slug]` (함께한 판·보정 승률·조합·포지션·연승·최근 경기)
3. 티어 추이(매일 스냅샷이 며칠 쌓인 뒤)
4. 후보 자동 찾기(관리자용 목록)

### 확인할 것

- 단위 테스트: 기간 자르기, 조합·포지션 집계(포지션 불일치 판은 포지션 집계에서 뺀다 — 원칙 10), 연승·연패, 보정 승률
- `verify:modules`: 계약·`core_public` 만 읽는다
- 화면: 표본 작은 듀오(3판)에서 "승률 100%" 가 아니라 보정값 + 판수, 숨긴 스트리머가 낀 듀오는 안 보인다

**PUUID 44개가 이 키로 안 풀렸다 → 고쳤다**
- 증상: 저장된 puuid 로 부르면 `400 Exception decrypting`. puuid 는 **API 키(앱)마다 다르게 암호화**된다
- 원인: `seed/streamers.json` 에 예전 키로 받은 puuid 44개가 박혀 있었고, 시드 스크립트는 puuid 가 있으면 Riot ID 조회를 건너뛰었다.
  DB 를 새로 채울 때 낡은 값이 그대로 들어갔다(첫 시드 40명·44계정과 숫자가 같다)
- 조치: `npm run repair:puuid -- --apply` 로 44개를 Riot ID 로 다시 풀어 옮겼다(정상 277 · 옮김 44 · 실패 0, 고아 행 0).
  **재발 방지**: 시드 스크립트가 키가 있으면 항상 Riot ID 로 puuid 를 받고, 시드 파일에서 puuid 값을 지웠다(파일은 git 밖 로컬 데이터)
- 남은 위험: 옮길 때 저장된 Riot ID 를 믿었다. 그 사이 원래 주인이 이름을 바꾸고 다른 사람이 같은 이름#태그를 가졌다면 남의 계정이 붙는다 —
  예전 puuid 를 이 키로 풀 수 없어 API 로 대조할 방법이 없다. 시드 근거(2026-07~08 확인)가 최근이라 가능성은 낮다

**일회성 백필 — 실행 중**
- 사용자 systemd 일회성 서비스 `soop-lol-backfill` (`npm run worker -- backfill --all`). 세션과 무관하게 돌고, 로그는 journal
  - 상태: `systemctl --user status soop-lol-backfill` · 로그: `journalctl --user -u soop-lol-backfill -f` · 멈춤: `systemctl --user stop soop-lol-backfill`
  - 멈춰도 계정마다 위치(`ingest_cursor`)를 기억한다 — 같은 명령으로 다시 띄우면 이어서 한다
  - ⚠ WSL 이 내려가면(모든 터미널을 닫거나 PC 를 끄면) 같이 멈춘다
- 실측 속도: 2분 한도 100회를 몰아 쓰고 기다린다 → **분당 약 48경기, 하루 약 6.7만 경기**. 계정을 돌아가며 최근 25판씩 → 과거로
- 모든 큐(솔랭·자유랭·일반·칼바람)를 가져온다. 끝까지 걸리는 시간은 계정당 경기 수에 달렸다 — 첫 바퀴(321계정 × 25판 ≈ 2시간 40분) 뒤 다시 잰다
- 랭크 스냅샷(`worker -- rank`)은 돌리지 않았다(결정대로 백필만). 티어 칸은 랭크를 한 번이라도 돌려야 찬다
