# ck-local 최적화 계획

작성: 2026-10-01. 대상: `.claude/skills/ck-local/`, `scripts/ck-local/`, `scripts/ck-backfill.sh`(선택 인자 하나).
전제: [CK-LOCAL-FIX-PLAN.md §9](CK-LOCAL-FIX-PLAN.md) 의 구조(로컬=롤 화면 표시, Claude=몽타주·띠·원본 판독)는 그대로다.
이 문서는 **그 구조 안에서 Claude 세션이 쓰는 토큰을 줄이는 계획**이다. 판단 기준·판독 규칙은 건드리지 않는다.

## 0. 요약

2개 VOD 시험(Sonnet 5, dry-run)에서 ck-local 은 4판 VOD 를 **-65%**($5.26 → $1.85), FC 만 한 VOD 를 **-12%**($0.94 → $0.82) 줄였다.
세션 기록을 턴 단위로 뜯어 보니 남은 비용은 **사진이 아니라 사진 밖의 일**이다:
① 매번 읽는 긴 문서 ② Claude 가 손으로 조립하는 기록 초안 ③ 도구가 불명확해 소스를 읽는 왕복.
**원칙 하나로 줄인다: Claude 는 판단만, 기계적인 조립은 도구가 한다.** 예상 효과는 FC VOD ≈ -40%, 4판 VOD ≈ -20%(추정, §4).

## 1. 측정된 사실 (세션 기록 `~/.claude/projects/…/*.jsonl`)

### 비용 식

단가는 새 세션의 실제 청구액으로 역산해 검증했다(계산값 $0.82389 ↔ 청구 $0.82395): 입력 $2 · 출력 $10 · 캐시 읽기 $0.2 · 캐시 쓰기(1h) $4 (백만 토큰당).

**컨텍스트에 한 번 들어온 토큰은 쓰기 $4 + 남은 턴마다 읽기 $0.2 를 낸다.** 16턴 세션에서 2번째 턴에 읽은 문서 1만 토큰 ≈ $0.07.
그래서 (a) 일찍 들어온 큰 내용, (b) 턴 수, (c) 컨텍스트가 큰 구간의 턴이 비싸다.

세션 기본 컨텍스트는 **약 41.6k 토큰**(시스템·도구·CLAUDE.md·메모리·스킬 목록)이고, 세션을 여는 것만으로 $0.075 다.
`--strict-mcp-config` 를 주면 36.4k 로 줄어든다(-5.2k, 실측). `--bare` 는 인증(OAuth)을 못 읽어 쓸 수 없다(실측: 빈 응답).

### FC 만 한 VOD — 16턴, $0.82 (컨텍스트 44.6k → 114k)

| 턴 | 한 일 | 문제 |
|---|---|---|
| 2 | ck-research SKILL.md 전체 읽기 — 20,648자 ≈ **14k 토큰** | 롤이 없는 VOD 는 이 문서가 거의 필요 없는데 "끝까지 읽는다"고 써 있다 (≈ $0.09, 11%) |
| 9–10 | `scan-draft.json` 2개 + `.latest.json` 읽기 | 최종 초안이 어느 것인지 불명확 (3턴) |
| 11–12 | `ls scripts/ck-local`, `package.json`, **`scan.mjs` 소스 14.8k자 읽기** | 도구 사용법이 문서에 없어 소스를 읽음 (2턴 + 약 5k 토큰) |
| 13 | `scan-draft.json` 을 **손으로 작성 — 출력 4.6k 토큰** | 롤이 없으면 내용은 거의 정해져 있다 (lead·범위·opened·note) |
| 16 | 최종 요약 출력 3.3k | 백필 지시문이 요구한 것 — 필요한 만큼만 |

### 4판 VOD — 35턴, $1.85 (컨텍스트 44.9k → 171.6k)

| 구간 | 턴 | 비용 | 내용 |
|---|---|---|---|
| 준비·확인 | 1–6 | 작음 | ck-research 읽기 14k 토큰 포함 |
| **판독** (몽타주 → 판마다 띠 → 원본) | 7–22 (16턴) | 중간 | 판당 약 5턴(띠·원본 받기·보기). 사진은 몽타주 2 + 띠 3 + 원본 12. **설계한 대로 잘 돌았다** |
| **기록** | 23–33 (**11턴**) | **≈ $0.55 (30%)** | 컨텍스트가 143k~169k 로 가장 큰 구간. 출력 2만 토큰: 초안 손작성 9.5k, 조립용 `node -e` 스크립트 3번(4.2k·0.3k·2.4k), 저장 검사 오류 뒤 `Edit` 3번, `scan.mjs` 를 grep 해 옵션 찾기 |

비교: 기존 스킬의 같은 VOD 는 69턴, 컨텍스트가 **35만 토큰**까지 커졌다(캐시 읽기 1,443만). 새 구조가 줄인 건 판독 구간이고, 남은 큰 덩어리는 기록 구간이다.

### 사진 비용

원본 한 장 ≈ 2.7k 토큰, 몽타주 한 장 ≈ 1.3k 토큰. FC VOD 는 14장 → 3장으로 줄었지만 **턴 수는 18 → 16 으로 거의 안 줄어서 비용이 12% 만 줄었다.**
경기가 없는 VOD 가 전체의 93% 라서, 사진이 아니라 **턴 수와 기본 컨텍스트**가 비용을 정한다.

## 2. 원인

| | 원인 | 뿌리 |
|---|---|---|
| A | 롤이 없어도 ck-research 439줄을 전부 읽는다 | ck-local 이 "정본을 끝까지 읽는다"를 일괄 지시 — 읽는 시점을 나누지 않았다 |
| B | 기록 초안을 Claude 가 JSON 으로 조립한다 | 초안의 기계적인 부분(lead·범위·probes·failed·signals·version·frames 목록)과 판단하는 부분(후보·경기)이 한 파일에 섞여 있다 |
| C | 사용법을 소스에서 찾는다 | `ck:local` 에 `--help` 가 없고, 스킬이 옵션을 다 싣지도 않는다 |
| D | 세션 기본 컨텍스트 | MCP 서버 설명 5k (줄일 수 있는 것은 이만큼) |

A·C 는 문서 문제, B 는 도구 경계 문제, D 는 실행 인자 하나다. 모델·프롬프트·사진 해상도는 원인이 아니다.

## 3. 최적화 — 흐름은 더 짧아지고 순서는 그대로다

최종 Claude 흐름 (앞 단계가 뒤 단계의 입력, 갈림길은 "롤이 보이나" 하나):

```
0. 준비 확인 (run_id)
1. 이전 기록 (ck:record · find-match)
2. 개요 몽타주를 그림으로 보고 "롤이 있나"를 정한다
   ├ 없음 ─ 3. 파일 끝 원본 1장 ─ 4a. --finish-none 으로 초안 생성 ─ ck:merge
   └ 있음 ─ (이때 ck-research 를 읽는다) ─ 4b. 판마다 띠 → 원본 판독
            ─ 5. 경기 내용만 games.json 에 쓴다 ─ --draft 로 초안 생성 ─ ck:merge
```

### O1. 읽는 시점을 나눈다 (원인 A)

- ck-local SKILL 에서 "먼저 ck-research 를 끝까지 읽는다"를 **"롤이 보이면 그때 읽는다"** 로 바꾼다.
- 롤이 없는 경로에 필요한 것은 도구가 검사한다: `ck:merge` 가 저장을 받아 주거나 거부한다. 거부 사유를 읽고서 모자란 규칙만 ck-research 에서 찾는다.
- ck-research 의 규칙을 ck-local 에 **복사하지 않는다**(두 벌이 어긋나는 사고를 막는다). 읽는 시점만 바뀐다.
- 효과: FC VOD 에서 14k 토큰 × 남은 14턴 ≈ $0.09.

### O2. 기록 초안의 기계적인 부분을 도구가 만든다 (원인 B)

새 하위 명령 두 개. 둘 다 **파일만 쓴다**(DB 저장은 여전히 `ck:merge` 한 창구).

- `ck:local -- --vod N --run R --finish-none --opened 7572[,…] --note "본 것"` — 롤이 없는 VOD 의 초안을 완성한다.
  `status: done` 으로 쓰지만 **Claude 가 이 명령을 부르는 것이 "롤 없음을 확인했다"는 선언**이다(명령을 안 부르면 초안은 `running`).
  `opened` 는 Claude 가 실제로 연 시각을 넣는다 — 도구가 지어내지 않는다.
- `ck:local -- --vod N --run R --draft [--games out/ck/N/local/games.json]` — 롤이 있는 VOD 의 초안을 만든다.
  도구가 채우는 것: lead, 범위, probes, failed, signals, version, note 첫 줄, **`ck:probe` 가 받은 프레임 목록(경로·시각)**.
  Claude 가 `games.json` 에 쓰는 것: **후보와 경기(match)·참가자·근거 프레임 경로** — 읽은 결과뿐이다.
  결과창 프레임 표시(`kind: "result"`)는 `games.json` 의 근거 프레임 경로에서 도구가 붙인다.
- 효과: 손작성 출력 4.6k~9.5k → 경기 내용만 약 3~4k, `node -e` 조립 스크립트와 오류 수정 `Edit` 왕복 6~7턴 제거.
  도구가 만든 초안이 `ck:merge --dry-run` 을 통과하는지는 시험으로 확인한다.

### O3. 사용법을 문서와 `--help` 에 싣는다 (원인 C)

- `ck:local --help`: 명령 세 개(준비·띠·검산/초안)와 `scan.json` 필드(`lol_ranges`·`failed`·`file_tails`·`overview`) 설명.
- 준비 명령의 마지막 출력에 "다음에 쓸 명령" 세 줄을 싣는다. Claude 가 소스를 읽을 일이 없어진다.
- 효과: FC VOD 에서 2~3턴 + 5k 토큰, 4판 VOD 에서 grep 왕복 1~2턴.

### O4. 세션 기본 컨텍스트 (원인 D)

- `ck-backfill.sh` 에 자식 세션 추가 인자 `CK_BACKFILL_CLAUDE_ARGS` 를 둔다(기본 비어 있음 → 기존 동작 그대로).
  ck-local 백필에서는 `--strict-mcp-config` 를 준다. 효과: 세션당 5.2k 토큰 ≈ $0.02 + 턴당 $0.001.

### 하지 않는 것

| | 이유 |
|---|---|
| 로컬이 "롤 없음"이면 Claude 를 안 부르기 | 로컬이 조용히 놓치는 VOD 를 잡을 길이 없다. 몽타주 검산을 안전장치로 둔 결정과 충돌 |
| `--bare` | 인증을 못 읽는다(실측) |
| Haiku 로 기록 | 스키마 오류로 한 번 전부 되돌린 전례 |
| 원본·몽타주 해상도 낮추기 | 판독 정확도가 먼저다. 사진은 비용의 주된 원인이 아니다 |
| ck-research 수정 | 이 최적화는 ck-local 안에서 끝난다 |

## 4. 기대 효과 (추정 — 구현 뒤 같은 VOD 로 다시 잰다)

| | 지금 | 예상 | 줄어드는 곳 |
|---|---|---|---|
| FC VOD | $0.82 (16턴) | **≈ $0.50** (≈ 8턴) | O1 -$0.09 · 초안 손작성 -$0.05 · 소스·초안 읽기 -$0.08 · O4 -$0.03 · 턴 감소로 기본 컨텍스트 읽기 -$0.03 |
| 4판 VOD | $1.85 (35턴) | **≈ $1.4~1.5** (≈ 26턴) | 기록 구간 11턴 → 5턴 · 손작성·조립·수정 출력 2만 → 약 0.5만 · O4 |

4판 VOD 의 판독 구간(16턴)은 줄이지 않는다 — 판마다 띠와 원본을 읽는 일은 판단이라 그대로 둔다.
세션 기본 컨텍스트 36k 이상은 세션을 여는 한 줄일 수 없다: **FC VOD 는 $0.22 가 바닥**이다.

⚠ 위 수치는 기존 기록이 있는 VOD 에서 나왔다. 기록이 없는 새 VOD 는 탐색이 더 길다(이전 기록을 못 보므로). 비교는 새 VOD 로 다시 한다.

## 5. 순서와 검증

| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | O1·O3 — 스킬 문서 + `--help` + 준비 출력의 다음 명령 | 같은 두 VOD 를 같은 스크립트로 다시 돌려 턴 수·토큰 비교 |
| 2 | O2 — `--finish-none`·`--draft` | 도구가 만든 초안이 `ck:merge --dry-run` 을 통과하는지, 기존 DB 값과 같은 경기를 내는지 |
| 3 | O4 — `CK_BACKFILL_CLAUDE_ARGS` | 기본 동작(인자 없음)이 안 바뀐 것 |
| 4 | **기록이 없는 새 VOD 10개**로 기존 스킬과 나란히 비교 | 비교표(토큰·비용·연 이미지·시간·판독 결과 일치 여부)를 사용자가 보고 이 스킬로 계속 갈지 정한다 |

측정 스크립트(준비 → Claude 세션 dry-run → JSON 사용량 수집)는 스크래치에서 `scripts/ck-local/measure.sh` 로 옮겨 실험 폴더와 함께 지워지게 한다.
"몇 % 줄면 합격" 같은 기준은 만들지 않는다 — 표를 보고 판단한다.

## 6. 위험

- O2 의 `--finish-none` 이 "롤 없음 확인"을 쉽게 만들어 **몽타주를 안 보고 부를 위험**: 초안 `note` 첫 줄에 Claude 가 연 몽타주 목록을 넣도록 요구하고(`--opened` 와 별개로 `--montages overview-1.jpg,…` 필수), 없으면 명령이 거부한다.
- O1 로 ck-research 를 안 읽은 세션이 기록 규칙을 놓칠 위험: 도구(`ck:merge`)가 거부하는 것은 잡히고, 거부 사유가 읽을 곳을 알려 준다. 시험에서 실제 거부 빈도를 센다.
- `games.json` 형식을 잘못 쓸 위험: 도구가 필드를 검사해 오류 위치를 한국어로 알려 준다(`ck:merge` 검사의 앞단).
