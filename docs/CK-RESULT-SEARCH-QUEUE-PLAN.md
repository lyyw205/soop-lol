# CK 결과 화면 탐색·검수 큐 개편 계획

작성: 2026-09-23. 같은 날 아래 계획을 구현하고 회귀 검증했다.

구현 결과: 새 DB 테이블이나 마이그레이션 없이 후보의 선택 필드, 큐 투영 순수 함수,
프레임 추출 편의 옵션과 경고로 반영했다. 기존 운영 후보·프레임 원본은 일괄 수정하지 않았다.

## 1. 결론

이번 수정은 화면만 고치는 작업이 아니다. 다음 네 부분을 한 번에 맞춘다.

1. `ck-research` 스킬에 **경기 종료 뒤 결과 화면을 찾는 탐색 방법**을 추가한다.
2. 후보를 더 자세히 조사할 때 기존 구간 위에 새 후보를 계속 얹지 않고, **기존 후보를 세분화한 현재 작업 단위**로 정리한다.
3. 검수 큐는 원본 데이터를 전부 독립 행으로 나열하지 않고 **경기 > 미해결 후보 > 실제 미배정 구간** 순으로 한 번만 보여 준다.
4. 결과 화면을 찾으려고 추가로 뽑은 프레임은 별도 미배정 항목이 아니라 해당 경기·후보 안에서 좌우 키로 넘겨 보는 **문맥 프레임**으로 취급한다.

원본 후보와 프레임은 조사 이력으로 보존한다. 없애는 것은 중복 UI이지 근거 데이터가 아니다.

## 2. 가장 중요한 불변 원칙 — 탐색을 강제 판정으로 바꾸지 않는다

새 절차는 결과 화면을 **잘 찾기 위한 기본 전략**이지 경기 인정 조건이나 조사 완료 조건이 아니다.

- 결과 화면을 찾아보는 행동과, 실제로 결과 화면을 확보하는 성공은 구분한다.
- 결과 화면을 못 찾았다는 이유만으로 경기가 아니라고 결론 내리지 않는다.
- 결과 화면을 찾을 때까지 무한 반복하거나 정해진 횟수를 채우게 하지 않는다.
- `N초 간격`, `N장 확인`, `N회 재시도`, `신호 N개` 같은 합격선을 만들지 않는다.
- 결과 화면이 나올 확률을 수치로 규칙화하지 않는다. 자주 나온다는 경험은 탐색 우선순위를 정하는 참고일 뿐이다.
- 결과 화면이 가려졌거나 일부만 보이면 확인된 값만 기록한다. 사람·승패·챔피언·KDA를 추측해 채우지 않는다.
- 결과 화면이 없더라도 채팅·음성·다른 시점 등으로 승패를 판단했다면 그 사실과 한계를 그대로 기록할 수 있다.
- 승자를 판단할 수 없으면 경기 행을 억지로 만들지 않고 미해결 후보로 남긴다.

`ck:merge`는 위 판단을 막는 하드 게이트를 추가하지 않는다. 빠뜨린 탐색 지점이 있으면 경고할 수는 있지만, 조사자가 근거를 보고 내린 결론을 횟수 규칙으로 거부하지 않는다.

## 3. 현재 겹침이 생기는 이유

현재 검수 화면은 서로 성격이 다른 세 자료를 같은 수준의 행과 막대로 펼친다.

- 후보: 조사할 시간 범위. 넓은 시리즈 후보와 세트 후보가 함께 남아 서로 포함될 수 있다.
- 경기: 연결된 근거 프레임의 최소·최대 시각으로 폭을 만든다.
- 미배정: `match_id`가 없는 프레임을 앞 프레임과 90초 이내라는 이유로 묶는다.

따라서 한 시각이 넓은 후보, 세트 후보, 확정 경기, 결과 화면 탐색용 프레임 묶음에 동시에 들어갈 수 있다. 이는 같은 경기가 여러 번 있다는 뜻이 아니라, **조사 범위·판정 결과·추출 산출물을 한 UI에 중복 투영한 결과**다.

특히 현재 미배정 묶음은 중간에 경기 근거 프레임이 있어도 `match_id` 없는 프레임끼리의 시간 차만 본다. 그래서 경기 전후로 촘촘하게 뽑은 프레임이 하나의 긴 미배정 구간으로 이어진다.

## 4. 변경할 조사 절차

### 4-1. 전체 탐색은 그대로 유지한다

- VOD 전체에 대표 프레임을 배치하고 실제로 연다.
- 10분은 도구의 시작 기본값일 뿐 경기 판정 규칙이 아니다.
- 못 받은 지점은 실패 범위로 남긴다.
- 픽셀·채팅·음성 신호는 추가로 볼 위치를 제안할 뿐 자동 확정하지 않는다.

### 4-2. 경기 종료 후보를 발견하면 결과 화면 탐색으로 전환한다

조사자는 마지막으로 확실한 게임 진행 화면과, 처음으로 확실한 종료 후 화면 사이를 잡는다. 그 사이에 프레임을 추가로 뽑고 실제로 연다.

1. 마지막 게임 진행 화면과 첫 종료 후 화면으로 탐색 범위를 잡는다.
2. 범위가 넓으면 중간 지점을 추가해 전환 지점을 좁힌다.
3. 결과 화면이 보이면 바로 한 장에 고정하지 않고, 인접 프레임 중 가림이 적고 점수판·10명·챔피언·KDA가 가장 잘 보이는 화면을 근거로 고른다.
4. 결과 화면이 일부만 보이면 승패와 읽힌 항목만 기록하고 나머지는 비운다.
5. 소스 종료, 강제 종료, 화면 가림, HLS 누락, 반복해도 같은 화면뿐인 상황 등에서는 조사자가 더 보는 가치가 낮다고 판단하면 멈추고 시도 범위와 남은 질문을 적는다.

이 과정은 고정된 이분 탐색 알고리즘이 아니다. 전환이 분명하면 바로 가까운 시각을 볼 수 있고, 채팅이나 음성이 정확한 시각을 알려 주면 그 지점을 먼저 볼 수 있다.

### 4-3. 탐색 결과는 세 형태로 기록한다

- 충분한 결과 화면: 승패와 읽힌 로스터 정보를 근거로 사용한다.
- 부분 결과 화면: 확인 가능한 승패·일부 값만 사용하고 가림이나 누락을 기록한다.
- 결과 화면 미발견: 어디를 확인했는지와 대신 사용한 근거, 남은 불확실성을 기록한다.

세 번째도 정상적인 조사 결과다. 실패를 숨기지 않되 작업 자체를 실패 처리하지 않는다.

## 5. 후보 모델 정리

### 5-1. 후보의 역할

후보는 앞으로 **현재 결론을 내려야 하는 하나의 조사 구간**을 뜻한다. 시리즈 전체를 표시하기 위한 컨테이너는 후보로 계속 노출하지 않는다. 시리즈 관계는 경기의 `series_id`가 담당한다.

넓은 후보를 조사해 여러 세트나 작은 구간으로 나누면 다음처럼 처리한다.

- 새 후보가 `supersedes: <부모 후보 id>`로 원래 넓은 후보를 가리킨다. 부모 후보는 한 글자도 고치지 않는다.
- 새 후보들이 현재 작업 단위가 된다.
- `대체됨`을 부모에 저장하지 않는다. 자신을 `supersedes`로 가리키는 후보가 하나라도 있으면 화면의 순수 투영이 부모를 검수 큐와 기본 타임라인에서 숨긴다.
- 저장 형식은 숫자 쌍 그대로 두고, 모든 구간은 옛것과 새것을 구분하지 않고 반열린 구간 `[start, end)`로 해석한다. 경계 한 점은 양쪽에 동시에 속하지 않는다.
- 실제로 어느 쪽인지 불명확해 의도적으로 겹쳐야 한다면 겹침 자체를 금지하지 않는다. 이유를 미해결 기록에 남기고 UI가 겹침 경고를 보여 준다.

`supersedes`는 `event_lead.raw.candidates` 안의 선택 필드로 추가할 수 있어 새 DB 테이블은 필요하지 않다. 자기참조·없는 부모 참조·순환은 구조 오류로 거부한다. 기존 후보에는 이 값이 없어도 지금처럼 읽히도록 하위 호환한다.

### 5-2. 후보가 경기로 해결된 뒤

- 후보 원본과 관찰·판단 기록은 보존한다.
- 검수 큐에서는 후보 행을 따로 하나 더 만들지 않고 경기 행 하나로 합친다.
- 후보의 관찰·판단·남은 질문은 해당 경기의 `조사 기록 및 결과 근거` 안에서 계속 볼 수 있다.
- 흡수된 후보의 결론 편집도 경기 행 안에서 가능해야 한다. 경기 확정을 되돌리거나 `대상 아님`으로 바꾸는 길을 후보 행과 함께 없애지 않는다.
- `match` 또는 `linked` 결론인데 실제 `match_id`가 없는 오래된 자료는 자동 추측해 연결하지 않고 데이터 점검 대상으로 표시한다.

## 6. 검수 큐와 타임라인의 최종 규칙

화면에 보여 줄 항목은 원본 배열을 그대로 합치는 대신 별도의 순수 함수에서 계산한다. 우선순위는 다음과 같다.

1. 확정 경기
2. 아직 해결되지 않은 활성 후보
3. 위 두 범위에 속하지 않는 실제 미배정 프레임 묶음
4. 못 받은 구간은 큐 행이 아니라 우측 상태 안내와 미니맵 경고로 표시

구체적인 동작은 다음과 같다.

- 해결된 후보는 연결된 경기 행으로 흡수한다.
- 대체된 넓은 후보는 기본 큐에서 제외한다.
- 경기 폭은 `연결된 후보 구간 → 근거 프레임의 min~max → 명시적으로 확인된 VOD 시작시각에 game_creation + duration을 투영 → 점 마커` 순서로 정한다. `observed_at`처럼 의미가 다른 절대시각을 VOD 시작으로 추측하지 않는다.
- 어느 fallback 단계에서도 경기를 큐에서 빼지 않는다. 시간 근거가 전혀 없으면 `시각 미상` 큐 행과 시간축 밖의 점 마커로 남겨 선택·편집할 수 있게 한다.
- 활성 후보나 경기 범위 안에서 추가로 뽑은 `match_id` 없는 프레임은 미배정 행을 새로 만들지 않고 그 항목의 프레임 스트립에 포함한다.
- 정말 어느 후보·경기 범위에도 속하지 않는 프레임만 미배정으로 표시한다.
- 미배정 프레임의 단순 `90초 이하` 연결은 폐기한다. 같은 소유 범위 안인지 먼저 보고, 소유 범위가 없을 때만 작은 시각 묶음으로 표시한다.
- 타임라인에서는 경기를 가장 위와 가장 높은 클릭 우선순위로 둔다. 후보는 그 아래, 미배정 프레임은 얇은 보조 표시로 둔다.
- 한 번 클릭하면 하나의 대표 항목만 선택된다. 같은 시각에 여러 원본이 있어도 경기와 후보와 미배정이 동시에 선택 표시되지 않는다.
- 좌우 키는 선택한 경기·후보 안의 모든 문맥 프레임을 시간순으로 이동한다. 위아래 키는 대표 큐 항목 사이만 이동한다.

이 계산은 새 파일의 순수 함수로 분리해 실제 6시간 20분 이후 자료를 fixture로 고정한다. UI 컴포넌트 안에서 다시 임의의 포함 관계를 계산하지 않는다.

## 7. 도구와 스킬의 수정 범위

### 스킬·문서

- `.claude/skills/ck-research/SKILL.md`
  - 위 결과 화면 탐색 절차를 `후보 조사` 아래에 추가한다.
  - 결과 화면 탐색은 필수 행동이지만 발견 성공은 완료 조건이 아니라는 문장을 바로 옆에 둔다.
  - 고정 횟수·고정 합격선·자동 결론 금지를 반복해서 명시한다.
  - 넓은 후보를 세분화할 때 대체 관계를 기록하고 해결된 후보를 경기와 중복 노출하지 않는 계약을 추가한다.
- `docs/CK-RESEARCH-PLAN.md`
  - 후보 생명주기와 결과 화면 탐색의 설계 이유를 보강한다.
- `docs/CK-COLLECTION.md`
  - 결과 화면이 나오는 일반적인 흐름, 강제 종료·가림·탭 차이 같은 실측 함정만 참고 사례로 추가한다.

### 프레임 추출·반영 도구

- `scripts/ck-probe.mjs`
  - 기존 `--at`은 유지한다.
  - 종료 전환 범위를 여러 지점으로 뽑기 쉬운 범위 옵션을 추가하되, 간격은 조사자가 선택하거나 도구 기본값을 바꿀 수 있게 한다.
  - 범위 추출도 `probe.json.probes.targeted`에 누적하고 DB에는 자동 기록하지 않는다.
- `scripts/ck-merge.mjs`
  - 추출된 targeted 프레임 중 실제 `scan.opened`에 없는 지점을 경고한다.
  - targeted 미열람 확인은 `probe.json`이 있을 때만 한다. 수동 결과처럼 파일이 없으면 확인을 생략했다고 알리고 저장은 계속한다.
  - 경고는 저장 거부 조건이 아니다.
  - `supersedes` 후보 필드를 검증·병합한다.

### 데이터 계약

- `packages/core/lib/db/ck.ts`
  - `LeadCandidate.supersedes?: string`을 추가한다.
  - 자기 자신 참조, 존재하지 않는 후보 참조, 순환 대체는 거부한다. 이는 경기 의미 판정이 아니라 데이터 구조 무결성 검사다.
  - 기존 후보와 검수된 후보를 자동 재수집이 덮지 않는 현재 계약은 유지한다.
  - 경기와 연결된 후보 구간을 검수 화면에 전달한다.

### 검수 UI

- `apps/web/components/admin/ck-review-queue.ts`와 테스트 파일을 새로 두어 대표 항목 계산을 분리한다.
- `CkReviewer.tsx`는 계산된 큐와 소유 프레임만 렌더링한다.
- `ck-selection.ts`는 반열린 범위와 단일 소유자 선택 규칙을 사용한다.
- `admin.css`는 경기·후보·미배정의 시각적 우선순위만 조정한다. 폭을 키워 겹침을 가리는 방식은 쓰지 않는다.

## 8. 기존 데이터 처리

기존 데이터를 시간 포함 관계만 보고 일괄 수정하지 않는다. 먼저 읽기 전용 점검 결과를 만든다.

- 해결된 후보와 경기의 중복
- 다른 후보를 완전히 포함하는 넓은 후보
- `match`·`linked`인데 `match_id`가 없거나 존재하지 않는 경우
- 후보·경기 범위 안에 있는 미배정 프레임
- 경계 한 점 때문에 두 구간에 들어가는 경우
- 실제로 설명이 필요한 활성 후보 간 겹침

점검은 변경 예정 항목을 출력하는 dry-run부터 수행한다. 확실한 구조 중복만 자식의 `supersedes`로 정리하고, 경기 소유가 불명확한 프레임은 DB에서 자동 연결하지 않는다. 프레임을 문맥으로 묶는 것은 우선 UI 투영에서 처리한다. 기존 데이터 수정도 일회성 SQL이 아니라 `ck:merge --result`라는 유일한 쓰기 창구를 사용한다.

현재 VOD `207602969`의 6시간 20분 이후 구간은 첫 회귀 fixture이자 수동 확인 대상이다. 넓은 `s2` 후보는 세트 후보로 대체하고, `s2g1`·`s2g2` 결과 탐색 프레임은 각 경기 안에서 넘겨 보이게 하되 근거 프레임 연결 자체는 화면 내용을 확인한 뒤에만 고친다.

## 9. 구현 순서

1. 현재 6시간 20분 이후의 후보·경기·미배정 겹침을 순수 함수 테스트 fixture로 옮긴다.
2. 활성 후보, 대체 후보, 경기 소유 범위, 문맥 프레임을 계산하는 큐 모델을 구현한다.
3. 검수 큐·미니맵·키보드 선택을 새 모델로 교체한다.
4. 후보의 `supersedes` 계약과 병합 검증을 추가한다.
5. `ck:probe`의 범위 추출 편의와 `ck:merge`의 미열람 경고를 추가한다.
6. 마지막에 스킬과 조사 문서를 실제 구현과 같은 표현으로 갱신한다. 문서가 아직 없는 기능을 먼저 약속하지 않게 한다.
7. 기존 데이터 점검을 dry-run하고, 현재 VOD의 확실한 구조 중복만 근거를 확인해 정리한다.

## 10. 필수 회귀 검사

- 넓은 부모 후보와 두 세트 후보가 있어도 큐에는 현재 두 세트만 나타난다.
- 해결된 후보와 경기가 별도 행으로 동시에 나타나지 않는다.
- 경기 범위 안의 촘촘한 targeted 프레임이 미배정 행을 만들지 않는다.
- 후보 밖의 읽지 않은 대표 프레임은 미배정으로 남아 놓치지 않는다.
- 인접한 `[start, end)` 구간의 경계 프레임은 한쪽에만 속한다.
- 의도적인 미해결 겹침은 삭제되지 않고 경고와 기록을 유지한다.
- 경기 클릭 시 후보·미배정이 함께 선택되지 않는다.
- 위아래 키 이동 시 큐 스크롤이 따라오고, 좌우 키는 현재 항목의 프레임만 이동한다.
- 결과 화면을 찾지 못한 후보도 `done` 조사로 기록할 수 있다.
- targeted 프레임 미열람 경고가 있어도 정당한 부분 근거 저장은 막지 않는다.
- 프레임 0장·후보 0개인 경기(수동 생성·시드)도 큐에 나타나고 선택·편집 가능하다.
- 기존 `supersedes` 없는 조사 자료도 동일하게 열린다.

검증은 관련 단위 테스트, `npm test`, `npm run typecheck`, `npm run verify:db`, production build와 실제 브라우저 키보드 왕복까지 수행한다. 실제 PostgreSQL 브라우저 왕복은 `CK_PG_BIN`이 가리키는 `initdb`·`pg_ctl`이 필요하다. 현재 기계처럼 `initdb`가 없으면 단위·PGlite·빌드 검증을 수행하고 브라우저 저장 왕복을 실행하지 못한 이유를 명시한다. 스키마를 바꾸지 않으므로 DB 마이그레이션은 만들지 않는다. 구현 중 새 테이블이 필요해지는 설계가 나오면 이 계획을 멈추고 먼저 재검토한다.

## 11. 완료 기준

- 결과 화면 탐색 절차가 스킬에 들어가 있고, 발견 성공을 강제하지 않는 문장이 같은 절에 있다.
- 4:40:25처럼 이미 뽑힌 좋은 결과 프레임을 열지 않고 지나갈 가능성을 미열람 경고와 절차로 낮춘다.
- 6시간 20분 이후처럼 같은 시간대가 경기·후보·미배정으로 세 번 보이지 않는다.
- 원본 조사 기록은 보존되며, 큐에서 숨긴 후보도 조사 기록에서 추적할 수 있다.
- 기존 데이터에 대한 자동 추측 연결이나 일괄 파괴적 정리를 하지 않는다.
- 결과 화면이 없거나 부분적인 경기 역시 근거와 불확실성을 정직하게 남길 수 있다.

## 12. 구현·검증 기록

- `ck-review-queue.ts`에 경기 > 활성 후보 > 실제 미배정 순서의 단일 소유권 계산을 추가했다.
- 대체 방향을 자식의 `supersedes` 단일 참조로 바꿨다. 화면과 목록 집계가 역참조로 부모를
  숨기며 부모 원본과 `reviewed_at`은 수정하지 않는다.
- 경기 폭 fallback을 후보 → 직접 근거 프레임 → 확인된 `vod_started_at`과 경기시각·길이 →
  `시각 미상` 점으로 구현했다. 프레임·후보가 없는 경기도 큐와 편집 경로에 남는다.
- 경기 행의 조사 기록에서 그 경기를 가리키는 모든 후보를 보고 결론을 다시 편집할 수 있다.
- 현재 VOD의 구형 시리즈 컨테이너는 UI 호환 규칙으로 숨기고 원본은 보존했다.
- 다음 경기 시작 뒤까지 남은 늦은 결과 프레임은 앞 경기 안에서 계속 볼 수 있지만 대표
  막대는 다음 경기 시작에서 끝나도록 했다.
- 현재 페이지에서 `3:50:00–4:40:12 후보 → 4:40:12–4:41:40 경기 →
  4:41:40–5:28:00 경기`, `5:40:50–6:26:00 경기 → 6:26:40–7:16:40 경기`로
  겹침 없이 표시되는 것을 Chromium에서 확인했다.
- 좌우 문맥 프레임 이동, 위아래 큐 이동과 자동 스크롤, 단일 선택 표시를 확인했다.
- VOD `207602969`의 `s2g1`·`s2g2`에 `supersedes: ck20260919-s2`를
  `ck:merge --result`로 반영하고 재조회했다. 부모는 그대로이며 활성 후보 집계만 7건으로 줄었다.
- 전체 단위 테스트, 타입 검사, CK/PGlite 회귀, 전체 DB 검증, production build를 통과했다.
  이 기계에는 `initdb`가 없어 `verify:ck:browser` 실행은 생략했으며, 스크립트의 오래된 선택자는
  현재 인라인 경기·로스터 UI에 맞게 갱신하고 타입 검사했다.
- 단위 테스트 137개, 전체 typecheck, `verify:ck`, `verify:db`, production build를 통과했다.
- production build에는 기존 프레임 라우트의 동적 파일 접근에 관한 Turbopack 경고 2개가
  남아 있다. 이번 변경에서 새로 생긴 오류는 아니다.
