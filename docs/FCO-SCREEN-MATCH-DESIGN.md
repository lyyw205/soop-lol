# FC 온라인 — 화면으로만 아는 경기의 저장 설계

> **이 본문이 현재 설계다**(2026-10-01, 구현 커밋 `3f8a7ed`·`d36ee1a` 기준). 바뀐 결정과 그 이유는 맨 끝 [이력](#이력--바뀐-결정)에만 있다 —
> 이력의 옛 규칙을 따르지 않는다.
> 구현: `db/migrations/0050_fco_screen_match.sql` · `packages/core/lib/games/fconline/screen.ts` · 검증 `npm run verify:fco-screen`.
> **실DB 적용 전**이다(0050·0051 대기).

## 0. 한 줄

넥슨 목록 API 는 한국 날짜 기준 **최근 30일**만 준다(`docs/FCO-TIME-SAMPLES.md`). 그 이전 경기와, 등록 계정의 API 기록에서 빠진 경기는
**VOD 결과 화면으로만** 알 수 있다. 롤이 이미 쓰는 방식(모르는 값은 NULL, `match.source='manual'` + `origin='vod_scan'`)으로 저장하고,
**읽은 관측은 항상 먼저 숨긴 채 저장한 뒤** 같은 경기의 API 기록과 안전하게 연결한다. 기존 API 경기의 결과는 한 글자도 바뀌지 않는다.

## 1. 저장 모양

### 경기 — `match` (새 열 없음)

| 열 | 값 |
|---|---|
| `match_id` | `fcs:<VOD번호>@<결과 화면 초>` — 같은 화면을 다시 읽으면 같은 ID(멱등) |
| `game_code` · `source` · `origin` | `fconline` · `manual` · `vod_scan` |
| `game_creation` | 결과 화면이 뜬 시각(≈ 경기 종료, API 의 matchDate 와 같은 뜻) |
| `mode_key` | 화면에서 읽었으면 그 값, 아니면 NULL |
| `visibility` | **`hidden`** — 검수 전까지 공개하지 않는다 |
| `source_url` | VOD 주소 |

`fco_match_detail`(넥슨 원본) 행은 **만들지 않는다** — `provider_match_id`·`payload` 를 지어내지 않는다.

### 참가자 — `fco_match_participant` (0050 에서 제약을 풀었다)

| 열 | 화면 경기 | API 경기 |
|---|---|---|
| 키 | `(match_id, side_no)` | 같다 |
| `ouid` | **NULL** — 화면에선 계정 번호를 모른다. 닉네임으로 계정을 단정하지 않는다 | 넥슨 계정 번호 |
| `nickname` | 화면에 보인 이름 그대로 | 경기 당시 닉네임(같은 뜻) |
| `streamer_id` | 근거가 있을 때만(아래) | 계정 연결로 |
| `identity_basis` | `nickname_match`(등록 계정 닉네임과 **정확히 하나만** 일치, 동명이면 안 붙임) · `vod_owner`(방송 주인 본인 시점) · `manual` | NULL(ouid 가 근거) |
| `score_display` · `outcome` | 화면 스코어. 같은 점수·못 읽은 점수는 `unknown`(승부차기 가능). `goals` 는 NULL | 넥슨 값 |
| `match_info` | `{}` | 넥슨 원본 |

DB 제약(`fco_participant_identity`)이 "ouid 도 근거도 없이 스트리머를 붙이는 행"과 "ouid 가 있는데 근거를 단 행"을 거부한다.
참가자 FK 는 `match` 를 가리킨다(전엔 `fco_match_detail` 이었다 — 화면 경기는 그 행이 없다).
"같은 사람인가" 비교에는 `fco_participant_key(ouid, streamer_id, nickname)` 를 쓴다(ouid → 스트리머 → 화면 이름 순).

## 2. 저장 순서 — `saveFcoScreenMatch`

```
① 숨긴 채 저장 (경기·참가자·근거 프레임)   ← 무엇이 이미 있든 항상 먼저. 관측을 버리지 않는다
② 같은 경기 후보 찾기 — API 경기 + 아직 연결 안 된 다른 화면 경기, 종료 시각 ±9분 안
③ 후보가 정확히 하나이고 세 조건이 모두 맞으면 연결(linked)
   그 밖에 후보가 있으면 검수 대기(needs_review) — 먼저 찾은 것을 고르지 않는다
   후보가 없으면 created/updated (+ expect_api: 최근 30일 안이고 등록 계정이 있어 자동 수집이 곧 가져올 수 있음)
```

**세 조건**(`compareMatches`): ① 두 참가자가 같다(순서 무관) ② 종료 시각 차 ≤ 3분 ③ 스코어가 같다(둘 다 읽었을 때).
조건 하나가 모자라면 `maybe`, 어긋나면 다른 경기다.

**연결**(`fco_screen_link`): 화면 경기는 지우지 않고 숨긴 채 남기고, 근거는 연결 대상 경기로 **복사**한다.
다른 VOD 가 같은 경기를 찍으면 정본 경기에 근거가 모인다. 같은 화면을 다시 저장해도 연결은 한 번이다.

**나중에 API 경기가 들어오면** `reconcileFcoScreenMatches()` 가 같은 규칙으로 연결한다(후보가 하나이고 `same` 일 때만).
API 저장 경로(`saveFcoMatch`)에서는 부르지 않는다 — API 경로를 건드리지 않기 위해서다.

**검수 대기 목록** `findFcoScreenSuspects()`: `maybe`(조건 부족) 와 `ambiguous`(세 조건이 맞는 후보가 둘 이상 — **둘 다** 보여 준다).

검수된(`reviewed_at`) 화면 경기는 다시 저장해도 덮어쓰지 않는다(`protected`).

## 3. 공개 조회에 미치는 영향 — 없다 (단계 1)

기존 공개 조회는 전부 `JOIN fco_match_detail` 또는 `streamer_fco_account` 를 **ouid 로** 이어서 시작한다. 화면 경기는 detail 행이 없고 ouid 가 NULL 이라
**구조상 공개 조회에 안 나온다.** 공개 쿼리는 한 줄도 고치지 않았다.
검증: `scripts/fco-public-snapshot.ts` 로 공개 조회 전부를 덤프해 전후 비교(가짜 DB 35항목·실DB 3,128항목 동일), `verify:fco-screen` 이
화면 경기를 넣은 뒤에도 덤프가 그대로인지 본다.

| 2. 내부 안전 | 시리즈 대진 비교(`context.ts`)·세트 승수 합산(`series.ts`)을 사람 기준 키로. 키 순서를 **스트리머 → 계정 → 화면 이름**으로 바꿨다(0054) — ouid 먼저면 같은 사람이 API·화면 경기에서 다른 사람이 된다 | **완료**(2026-10-01) |

## 4.1 FC 전체 순서표 (2026-10-01)

화면 경기 저장(위 단계 1~4)을 포함한 FC 과거 기록 작업 전체의 순서다. 앞 번호가 뒤 번호의 전제다.

| # | 일 | 문서·위치 | 상태 |
|---|---|---|---|
| 1 | 화면 경기 단계 2 — 사람 기준 대진 비교 | 위 §4 | **완료** |
| 2 | FC 완료 도장 `event_lead.raw.fco_scan` 분리. 확인: `raw` 쓰기는 전부 최상위 키 병합(`raw \|\| {...}`)이라 `ck:merge` 가 FC 도장을 안 지운다. `vodWork(raw, 길이, 'fco_scan')`·`markLeadScan(..., {key:'fco_scan'})` | §4 「도장 분리」 | **완료**(도구만 — 쓰는 곳은 3·6단계) |

## 5. 사용자가 정한 것 (2026-10-01)

1. **공개 통계에 섞을지** — 저장·표시는 하되 통계 반영은 보류. 쌓인 뒤 검수해 정한다.
2. **최근 30일 안의 경기** — 화면 관측은 저장하고(숨김), API 경기가 오면 연결한다. 등록 계정이 없는 대회 경기는 API 가 못 주므로 화면 경기가 정본이다.
3. **자동 연결** — 세 조건이 모두 맞고 후보가 하나일 때만. 나머지는 검수.

## 6. 위험

| 위험 | 대응 |
|---|---|
| 닉네임 오독·같은 닉네임을 다른 사람이 씀 | 등록 계정과 정확히 하나만 일치할 때만 붙인다. 공개 전 검수 필수(단계 3) |
| 화면 시각 오차로 미연결·오연결 | 애매하면 연결하지 않는다 — 오연결보다 미연결로 기운다 |
| 화면 경기가 공개 통계를 오염 | 단계 4 전에는 구조상 안 나온다. 4 에서도 뱃지·필터로 구분 |
| **0050 을 되돌리기** | **데이터가 들어간 뒤에는 단순히 되돌릴 수 없다.** ouid NULL 행이 생기면 `SET NOT NULL`·옛 PK 복원이 실패한다. 되돌리려면 화면 경기(`source='manual' AND game_code='fconline'`)를 먼저 지워야 하고, 그건 관측 손실이다 |

## 7. 하지 않는 것

- 행사(주최자 방송·유튜브·대진표) 단위 복원 — 스트리머 VOD 백필이 먼저다
- 화면에서 스쿼드·슈팅 등 세부 통계 판독
- FC 결과 화면 판별기 재학습 — 별도 과제(처음 보는 방송 재현율 26%)
