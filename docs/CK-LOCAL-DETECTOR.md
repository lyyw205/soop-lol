# ck-local 결과창 판별기 학습 계획

작성: 2026-10-01. 상위: [CK-LOCAL-FIX-PLAN.md §9](CK-LOCAL-FIX-PLAN.md). 실험 폴더(`scripts/ck-local/`)와 함께 지울 수 있게 만든다.

## 0. 한 줄

로컬 모델에게 결과창을 **말로 설명하던 것**(프롬프트)을 그만두고, Claude 가 지금까지 직접 확인한 **실제 CK 결과창 사진으로 학습**시킨 작은 판별기를 쓴다.
판별기가 썸네일 모든 칸(3초)에서 결과창을 찾고, Claude 는 골라 준 원본만 읽는다.

## 1. 대상 — 스트리머 CK 결과창만

- **포함**: 스트리머 본인(또는 화면에 띄운) **롤 클라이언트 결과창** — 승리/패배 제목 + 점수판·그래프·룬 탭.
- **제외**: 공식 대회 채널(`lolbjmatch`, `afbjmatch`)의 사진 전부. 멸망전은 결과 화면을 방송 그래픽으로 만들고
  시즌마다 컨셉이 바뀐다. 우리가 모으는 건 CK 라서 학습에서 뺀다(정답으로도, 오답 예시로도 쓰지 않는다).
- 실측(2026-10-01): DB 의 결과창 표시 1,846장 중 1,602장이 공식 채널 방송 그래픽이었다. 스트리머 쪽은 약 250장.
  DB 의 `kind: result` 는 "결과를 읽은 근거 화면"이라는 뜻이라 클라이언트 결과창과 같지 않다 — **그대로 정답으로 쓰지 않는다.**

## 2. 정답 종류 (판별기가 고르는 것)

| 라벨 | 뜻 | 예 |
|---|---|---|
| `result` | **클라이언트 결과창** (찾을 대상) | 승리/패배 + 점수판·그래프·룬 탭. 창이 일부만 보이거나 일부 가려도 포함 |
| `ingame` | 게임 중 | 맵이 보이는 화면. Tab 점수판·상점·리플레이·남의 방송 속 게임 포함 |
| `client` | 롤 클라이언트 기타 | 로비, 사용자 설정 게임 방, 챔피언 선택, 로딩 |
| `other` | 롤 아님 | FC, 토크, 웹페이지, 다른 게임 |

헷갈리던 화면(Tab 점수판 = `ingame`, 챔피언 선택 = `client`)을 **따로 가르쳐** 경계를 잡는다. 로직은 `result` 확률만 쓴다.

## 3. 재료 — 결과창 주변의 실제 썸네일

- 스트리머 채널의 결과창 사진(약 250판)마다, 그 시각을 담은 **썸네일 시트 한 장**(5분 = 100칸)을 받는다(시간축: `vod-timeline.mjs`).
  한 장에 게임 끝 → 넥서스 폭발 → 결과창 → 로비가 다 들어 있어 가장 헷갈리는 순간이 모인다.
- `other` 재료: 이미 받아 둔 FC·토크 VOD 썸네일(시험용 VOD, 308장 세트).
- 원본을 줄여 흉내 내지 않는다 — 판별기가 실제로 볼 썸네일로 학습한다.

## 4. 정답 달기 — 자동 초벌 + 헷갈리는 칸만 검수

1. **초벌**: 결과창 사진 시각의 칸 = `result`. 나머지 칸은 비워 둔다(모름).
2. **1차 학습**을 초벌로 한다(결과창 칸 vs 결과창에서 1분 이상 떨어진 칸).
3. 판별기가 **자신 없어 하는 칸**과 **초벌과 어긋나는 칸**만 몽타주로 뽑아 Claude 가 4종 라벨을 단다(대화 안에서).
4. 다시 학습 → 3 반복(2~3번). 수만 칸 중 검수는 수백~천 칸이 되게 한다.
5. 수정한 정답은 `out/ck-detector/labels.jsonl` 에 쌓는다 — 다음 학습에도 쓴다.

## 5. 판별기 구조

- **특징 추출기(고정)**: 공개 이미지 모델 — SigLIP·CLIP·DINOv2 중 2~3개를 비교해 고른다. 학습하지 않는다.
- **판별기(학습)**: 그 위의 작은 4종 분류기(로지스틱 회귀 → 부족하면 작은 MLP).
- 이유: 결과창 판 수가 수백이라 큰 모델을 통째로 학습하면 외운다. 고정 추출기 + 작은 분류기는 적은 데이터로도 일반화되고,
  썸네일 한 칸에 몇 ms 라 5시간 방송 6,000칸을 1분 안에 본다.
- 입력: 썸네일 192×108 을 비율 유지(위아래 여백)로 추출기 입력 크기에 맞춘다.

## 6. 시험 — 처음 보는 스트리머, 판 단위

- **스트리머 단위로 떼어 시험**한다(예: 김민교로 배우고 이상호로 시험). 같은 스트리머는 VOD 가 달라도 화면 배치가 비슷해 점수가 부푼다.
  새 스트리머가 와치리스트에 들어와도 통하는지가 중요하다.
- **판 단위 채점**: 시험 VOD 20개 정도의 썸네일 전체를 실제처럼 돌려,
  (1) 알려진 판마다 결과창 후보가 잡혔나(재현율) (2) 시간당 가짜 후보 수 (3) 후보 원본 재확인 뒤 남는 가짜.
- 놓치는 쪽이 비싸므로 **놓침이 거의 없는 기준**에서 가짜가 얼마나 나오는지 본다. 합격선은 숫자를 보고 사용자와 정한다.

## 7. 적용 뒤 흐름

로컬: 모든 칸 판별 → 연속으로 걸린 칸을 후보로 묶음 → 후보마다 원본 1~2장(가장 잘 보이는 것) →
Claude: 원본 판독·같은 판 묶기 · 몽타주에서 "롤은 했는데 후보가 없는 구간" 점검 · 기록(ck-research 규칙).
Claude 의 후보 판정(진짜/가짜)은 새 정답으로 쌓여 재학습에 쓰인다.

## 8. 순서

| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | 설치(uv 가상환경, PyTorch·추출기 약 3GB) + 결과창 주변 썸네일 수집 + 초벌 | 수집량·초벌 표본 |
| 2 | 학습 → 헷갈리는 칸 검수 → 재학습 (2~3번) | 검수 전후 점수 |
| 3 | 처음 보는 스트리머·VOD 로 판 단위 시험 | **숫자 보고 → 적용 여부 결정** |
| 4 | ck-local 에 붙이고 Claude 는 최종 검수만 | 새 VOD 로 기존 스킬과 비교 |

지우기: 코드 `scripts/ck-local/detector/`, 데이터 `out/ck-detector/`, 가상환경 `scripts/ck-local/detector/.venv`(gitignore).

## 12. 화면 종류 라벨과 토큰 절약 (2026-10-01)

### 라벨 (multi.py — 같은 SigLIP 특징 위의 8종 분류기, 확신 0.6 미만은 "모름")
검수 r7~r9 로 클라이언트를 밴픽·게임 방·그 밖으로 나누고, 그래프 탭·로딩을 유사도로 찾았다(로딩은 썸네일에 거의 없어 2칸 — 뺐다).
스트리머 하나씩 빼고 시험:

| 라벨 | 맞게 붙임 | 붙인 것 중 맞음 |
|---|---|---|
| 게임 중 | 98% | 100% |
| 밴픽 | 99% | 98% |
| 게임 방 | 100% | 94% |
| 결과창(점수판) | 91% | 97% |
| 롤 아님 | 94% | 95% |
| 종료 화면 | 95% | 76% |
| 결과창(그래프) | 100% | 66% |
| 클라이언트 그 밖 | 62% | 47% |

준비 단계가 이 라벨을 구간으로 묶어 `map.txt`(구간 지도)를 낸다 — 밴픽·게임 중(2분+)·종료·결과창·그래프·게임 방(1분+)만, 결과창 구간엔 후보 번호.
4판 VOD(2.6시간)가 31줄. 1칸짜리 종료 라벨은 로딩을 잘못 본 경우가 많아 뒤 90초 안에 결과창 라벨이 없으면 지도에서 뺀다.
