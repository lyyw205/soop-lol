## 2. 경기 결과·출전·맞라인

- 결과 판정은 core `matchOutcome`·`tallyGroups`가 맡는다. 랜드 묶음은 유지하되 묶음에 승/무/패를 부여하지 않고 `5승 5패`처럼 표시한다. 개인 기록·상대 기록·연도 요약·최근 경기 칩을 함께 변경했다.
- 보너스 경기의 명단 조회는 `match_with_bonus`를 사용한다. 본게임 통계에 보너스를 섞지 않는 기존 공개 경기 뷰는 유지했다.
- FC의 출전과 평점 분모는 `fcoPlayerAppearance`로 통일했다. 스쿼드 사용 기록·대회 선수 모델·상대전적 선수 표가 같은 함수를 사용한다. 양수 평점 또는 골/도움 기록이 있으면 출전이며, 평균 평점에는 유효한 양수 평점만 포함한다.
- 롤 개인 기록·대회 맞라인·챔피언 SQL 집계는 검증된 포지션을 사용한다. team/individual position 불일치는 제외한다. SQL `resolve_position`과 TS `resolvePosition`의 81개 입력 조합을 대조했다.

실데이터 사전 확인에서는 평점 0인 선수 행 59,746개 중 골/도움이 양수인 행은 0개였다. 향후 그런 자료가 들어와도 출전 자체가 사라지지 않도록 별도 경계 테스트를 추가했다.

## 3. 기간·요약·목록 상한

- `resolveRecordPeriod`·`filterSeriesPeriod`·공통 scope 계약을 사용한다. 다전제 첫 경기의 KST 날짜로 묶음 전체를 포함/제외하고, SQL의 별도 `year` 자르기를 제거했다.
- 목록에 표시할 줄 수를 제한하기 전에 기간·모드를 적용한다. 승패·합계는 해당 범위 전체에서 계산한다. FC 대회 성적도 개인 목록 1,000건 제한에서 분리했다. 통산 참가·수상 정보는 통산이라고 표시한다.
- 롤·FC 개인 경기 목록은 날짜+ID 커서로 이전 기록을 읽는다. 한 묶음의 세트를 페이지 경계에서 끊지 않는다.
- 상대전적은 한 쌍의 필터·집계용 최소 자료 전체를 받고, 클라이언트에서 필터 → 전체 요약 → 목록 상한 순으로 처리한다. LoL 500묶음·FC 200묶음을 넘으면 제한 안내가 나오며 요약은 전체 범위 값이다.
- 롤 프로필 상대전적 탭은 SQL 요약을 먼저 보내고 상대 행을 펼칠 때만 상세 목록을 요청한다. 펼친 목록의 200묶음 제한도 표시한다. 이전 전체 경기 전송 경로와 미사용 `listOpponents`는 제거했다.
- 모드·기간·관계·정렬은 주소에 남는다. 상대전적 필터 변경은 native history로 적용하며 서버 조회를 유발하지 않는다. 정렬 후 새로 보이는 경기 링크·범위별 탭·좌우 교체 링크의 자동 prefetch도 차단했다.
- 날짜 입력 초안도 주소의 기간이 바뀌면 복원한다. FC 지표·사용 선수 탭은 결정 D8대로 **전체 맞대결 기준**이며, 그 문구를 유지한다. 선택한 필터는 목록 탭으로 돌아올 때 복원한다.

연도를 넘긴 다전제, 1,005건 이상의 합성 자료, 필터 후 집계, 커서 경계, 묶음 보존을 단위/DB 검증에 포함했다.

## 4. 구단가치

- 계정별 `fco_club_attempt`에 조회 시작·완료·결과·실패 코드·스냅샷 연결을 기록한다. 미조회, 진행 중, 오류, 실제 missing을 구분한다. 닉네임 조회 실패·신원 불일치·가져오기 실패를 기록하며 존재하지 않는 계정 호출은 계정 이력으로 만들지 않는다.
- 성공 스냅샷·선수·성공 결과는 한 트랜잭션으로 저장한다. 오류는 마지막 성공 값을 지우지 않는다. 늦게 완료된 오래된 시도가 최신 조회 상태를 덮지 않도록 시작 시각을 기준으로 정렬한다.
- `resolveClubState`는 최근 조회 결과와 마지막 성공 값/시각을 분리한다. `pickRepresentative`는 순위에 포함할 수 있는 공개 계정 중 최대 구단가치를 선택한다. 후보가 없으면 과거 값은 참고로만 표시한다.
- 정기 수집 주기와 최신성 정책을 core에서 함께 관리한다. 현재 매일 조회 기준으로 마지막 성공 후 **48시간부터 순위에서 제외**한다. 단순 오류는 아직 유효한 성공 값을 유지하고, 실제 missing은 순위에서 제외한다.
- 대표 계정과 마지막 성공 조회는 40일/365일 차트 범위와 독립적으로 읽는다. 메인·순위표·상세가 같은 계정과 값을 사용한다.
- `change7d`는 최근 7일 범위 안의 첫/마지막 성공 기록을 비교한다. 날짜가 다른 두 값이 없으면 `—`. 급상승·급하락 순서는 BP 증감 총액이며 비율은 표시만 한다.
- 순위표에 실제 비교 기간을 표시한다. 행별 기간이 다르면 하나의 기간으로 표시하지 않고 각 행의 툴팁에 해당 기간을 제공한다. 단위는 BP로 통일했다.

과거 성공/missing 스냅샷만 `legacy` 이력으로 이관했다. 도입 전 실패를 추정해 만들지 않았으므로 **과거 조회 이력은 완전하지 않다**. 공개 계약은 이 사실과 필요한 상태·시각만 제공하며 내부 실패 원문/계정 ID는 내보내지 않는다.

## 5. 이동·커뮤니티·솔랭 도전

- 프로필 → 편성표 링크는 site를 필수 인자로 받는다. 해당 게임 메뉴를 유지하면서 그 사람의 롤·FC 일정을 함께 표시한다.
- 커뮤니티 프로필 링크는 글의 게임 → 들어온 site → 실제 공개 기록이 있는 게임 순으로 정한다. 공통 공지는 게임별 공지 탭과 공지 띠에 같은 조건으로 노출한다. 일반 글 목록의 게임 구분은 유지한다.
- 솔랭 도전에서 `시즌 N판 중 M판 수집` 문구와 전용 `riotGames` 계산을 제거했다.
- 듀오 전적·날짜별 흐름은 두 멤버가 같은 팀으로 함께한 판만 집계한다. 한 명만 뛴 판과 서로 상대인 판은 각자의 개인 전적에만 포함한다. 히어로는 보정 승률과 표본 수를 명시하고 실제 승패 수를 함께 유지한다.

## 6. 공통 UI·재발 검사

- 롤 스트리머 표·FC 선수표·구단가치 순위표는 공용 `SortHeader`를 사용한다. 링크 정렬과 버튼 정렬의 동작을 보존하고, 레이블과 SVG 화살표를 한 묶음으로 정렬하며 머리글에 `aria-sort`를 둔다.

- 검사 자체를 검증하는 self-test와 순수 계산 회귀 테스트를 추가했다.

## 8. 실제 DB 적용

`npm run db:migrate`로 아래 3개를 적용 완료했다. 총 88개 마이그레이션이 적용된 상태다.

2. `0086_public_lane_position.sql` — SQL 포지션 판정 함수, 공개 참가자 포지션 필드 추가.
3. `0087_fco_club_attempt.sql` — 조회 시도 장부, 기존 스냅샷 이관, 내부 장부 RLS.
