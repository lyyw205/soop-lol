# 운영 오피스

관리자 메뉴 **운영 오피스** (`/admin/office`). 기존 관리자 인증이 화면과 상태 API를 보호한다.
상주 감시 AI·LLM 호출은 없다. 기존 조사 작업이 사용하는 AI와 감시는 별개다.

## 연결 구조

`systemd + job_run + 조사 큐 + DB 점검 기록 → 1분 수집기 → 원자적 스냅샷/알림 이력 → 어드민`

- 작업 목록: 자동화 등록부 `ops/jobs/*.json` 의 `office` 칸(부서·주기 문구·관측 허용 주기·최대 실행 시간)에서 생성한다(`packages/core/lib/ops/jobs.generated.ts` → `model.ts` 의 `JOBS`, 2026-10-16). 손으로 적지 않는다 — 등록부를 고치고 `node scripts/ops/jobs.ts sync`. 부서는 `model.ts` 의 `ROOMS`.
- 실행 기록: 감싸는 실행기(`scripts/ops/run-job.ts`)가 실행 하나를 `job_run` 한 행(0088 — 생존 신호·진척·멈춘 이유)으로 남긴다. 카드의 "멈춘 이유·생존 신호·진척·할 일"이 여기서 온다. 같은 종료 코드라도 이유가 다르면 다르게 보인다(DB 관문 = 외부 차단, STOP = 사용자 정지).
- 조사 작업(롤 자동 조사)은 최근 실행만으로 정상이 아니다 — 대기가 있는데 진척(세션 저장)이 30분(실행 중이면 3시간) 없으면 "조사 정지". 목록 확인이 매시간 성공해도 가리지 않는다.
- 수집기: `scripts/ops-office.ts`. 읽기만 수행하고 `out/ops/office/snapshot.json`에 상태와 발생·해소 이력을 저장한다. 기존 작업을 재실행하거나 DB를 변경하지 않는다.
- 화면: 30초마다 스냅샷을 읽으며 숨겨진 탭에서는 폴링을 쉰다. 여러 브라우저가 같은 수집 결과를 공유한다.
- 스냅샷이 없으면 요청 시 수집하고 **화면 관측 중**을 표시한다. 스냅샷이 3분 이상 오래되면 감시 중단 알림을 띄우며, 새 웹 조회로 중단 사실을 가리지 않는다.
- 경고는 새 발생 시 로컬 `notify-send`로 전달을 시도한다. 데스크톱 알림 서비스가 없는 환경에서도 알림함에 보존된다. 외부 메신저·메일은 연결하지 않는다.

## 설치

현재 작업 호스트의 기존 타이머를 건드리지 않고 오피스만 설치:

```bash
bash scripts/systemd/install.sh --office-only
systemctl --user start soop-office.service
systemctl --user status soop-office.timer
```

서비스는 다른 기존 유닛처럼 `%h/repos/soop-lol`을 사용한다. 다른 체크아웃에서는 유닛의 경로를 맞춘다.
단독 점검: `node --env-file-if-exists=apps/web/.env.local scripts/ops-office.ts`.

웹 서버와 수집기 양쪽의 `OPS_OUT_ROOT`에 같은 `out` 디렉터리를 지정한다. 기존 `CK_OUT_ROOT`도 지원한다.
CLI는 변수가 없으면 체크아웃의 `out`을 사용하지만, 웹은 경로를 추측하지 않는다(Next standalone에 대용량 산출물이 포함되는 것을 방지).
호스트가 다르면 수집기 스냅샷을 웹의 읽기 전용 마운트/동기화 경로로 연결한다. 파일에는 관리자용 운영 정보가 있으므로 공개 정적 파일로 배포하지 않는다.

## 상태의 의미와 범위

- `정상`: 관측된 최근 실행이 성공했거나 등록된 트리거가 첫 실행을 기다린다. 아직 실행하지 않은 작업에 성공 시각을 만들지 않는다.
- `작업 중`: 최근 실행/서비스가 실행 중. 설정된 최대 시간을 넘으면 지연으로 표시한다. 오래된 `running` DB 기록도 지연으로 드러난다.
- `일시 중지`: 조사 STOP 파일 또는 비활성 트리거. 진행 중 조사 세션은 저장 후 종료될 수 있다.
- `미등록`: 자동 실행 트리거가 설치되지 않았다. 장애와 구별한다.
- `확인 필요`: 관측 근거가 없거나, 상주 루프의 실행 이력만 오래 남았다. 정상으로 추정하지 않는다.
- 처리 0건은 그 자체로 실패가 아니다. 부분 실패는 DB에 저장된 실패 상태를 따른다.
- 총 완료·처리량은 등록된 작업의 최근 24시간 `job_run` 기준이다. 기존 `(job, started_at)` 인덱스를 사용해 과거 전체 실행 이력을 매분 훑지 않는다. systemd 전용 조사 작업을 이 수치에 합산하지 않는다.
- 조사 큐의 소유권은 실제 프로세스 생존을 보장하지 않는다. 큐가 30분 이상 변경되지 않았고 실행 작업도 관측되지 않으면 알린다. STOP 상태에서는 의도적 중지를 존중한다.
- 백필은 저장된 채널·게임 요청 수와 요청 기간을 보여준다. 요청을 진행률로 환산하지 않는다. 수동 VOD 백필은 감싸서 띄우면(`node scripts/ops/run-job.ts --job ck-backfill -- scripts/ck-backfill.sh …`) 백필 카드에 생존 신호·세션 진척·멈춘 이유가 보인다. 감싸지 않고 띄운 백필은 여전히 화면에 안 보인다(정식 작업화는 재설계 3단계).
- DB 용량은 기존 `ops:usage` 기록이다. 100분 이상 오래되면 점검 지연을 알린다. 수집기가 별도 관리 API나 비용 발생 AI를 호출하지 않는다.
- 알림 확인 표시는 브라우저 로컬에 저장된다. 확인은 문제 해결이 아니다. 정기 수집이 해소를 관측하면 해결 이력으로 이동한다. 관측 소실을 해소로 처리하지 않는다.
- 화면과 수집기가 같은 호스트에 있으면 호스트 전체 중단을 그 호스트에서 통지할 수는 없다. 외부 가용성 감시는 별도 연결이 필요하다.

## 인게임 화면

- 실제 등록 작업마다 책상과 캐릭터를 배치한다. 캐릭터는 AI 에이전트가 아니라 기존 작업의 상태 표현이다.
- 타이핑은 관측된 실행, 손들기는 실패·지연, Z 모션은 의도적 중지, 물음표는 미확인·미등록이다. 수집 중단·연결 실패 때는 실행 모션을 보류한다.
- 각 작업의 말풍선은 “47분 전에 FC 경기 동기화를 마쳤어요. 13분 후에 다시 동기화할 예정이에요.”처럼 자신의 실행 기록과 실제 다음 일정으로 말한다. 다른 작업의 완료 이력을 섞거나 다음 실행 시각을 추정하지 않는다. 부서 제목과 생략 부호 없이 문장을 줄바꿈한다.
- 기본 화면의 말풍선은 최대 2개다. 실패·지연 → 최근 2분 내 완료 → 실행 순으로, 부서당 한 명만 짧게 말한다. 정상 대기·중지·미등록은 자동으로 긴 대화를 띄우지 않는다. 관측이 끊기면 자동 대화를 보류한다.
- 캐릭터에 마우스를 올리거나 키보드 포커스를 주면 해당 캐릭터 한 명의 전체 대화만 표시한다. 부서 확대에서도 자동 대화는 최대 2개이며, 장비창을 열면 말풍선은 거둔다. 상태 모션·바닥 경고·알림함은 그대로 유지한다.
- 넓어진 각 부서에 작업 구역과 커피·휴식 좌석을 구분했다. 정상 대기·중지 캐릭터는 휴식공간에, 실행·문제 확인 캐릭터는 책상에 있다. 관측 상태가 바뀌면 2초 동안 걸어서 이동하고 도착 후 타이핑·휴식 모션으로 전환한다. 이동 중에는 말풍선을 잠깐 거둬 잘못된 자리를 가리키지 않는다.
- 캐릭터를 선택하면 장비창에서 현재 업무·최근 행동·문제 기록을 확인한다. 처리량·시각은 실제 관측만 사용하며 진행률이나 경험치를 만들지 않는다.
- 바닥 드래그로 이동하고 휠·+/−로 확대·축소한다. 하단 부서 슬롯 또는 숫자 1~6으로 이동한다. 같은 부서를 다시 선택하거나 큰 전체 보기 버튼, 0/Home, 빈 바닥 더블클릭으로 전체 보기로 돌아간다. Escape는 장비창 닫기 → 전체 보기 → 집중 모드 종료 순서다. 작은 화면에서는 한 부서를 확대해서 시작한다.
- 모션 정지와 OS의 모션 줄이기 설정을 지원한다. 기존 아이소메트릭 벡터 렌더러를 사용하며 별도 3D 엔진이나 GPU 라이브러리를 추가하지 않는다.

## 스케줄러 일정표

상단 **일정표**에서 오늘 남은 일정·내일·향후 24시간을 KST 시간대별로 확인한다. 부서별 필터와 반복 예상 표시 전환을 지원하며, 항목을 선택하면 해당 작업의 장비창을 연다.

- **다음 실행**: 스냅샷의 실제 `nextAt` 관측 시각.
- **예상**: 그 시각을 기준으로 등록된 매일·매시간·N분/시간 반복 주기를 적용한 후속 실행. 정확한 systemd 달력 재계산이나 실행 보장이 아니며 지연·설정 변경에 따라 달라질 수 있다.
- 중지·미등록·상태 미확인·이벤트 트리거·지난 예정 시각은 반복 계산에서 제외한다. 정해진 시각이 없는 작업은 별도 영역에 표시한다.
- 현재 실행 중 작업도 함께 보여주며, 관측이 끊기면 마지막 기록임을 명시한다. 소요 시간이나 종료 시각은 추정하지 않는다.

## 검증

```bash
node --test packages/core/lib/ops/*.test.ts scripts/office-dialogue.test.ts
node scripts/verify-office-browser.ts
```

브라우저 검증은 로컬 전용 Next 서버와 임시 스냅샷을 쓰며 실제 DB·스케줄러를 변경하지 않는다.
인증, 작업별 캐릭터·말풍선, 말풍선 비중첩, 실제 팔 애니메이션과 책상↔휴식공간 이동, 장비창 이력, 카메라 복귀·휠, 키보드, 알림 확인, 집중 모드, 모바일, 수집 중단 시 동작 보류, 연결 실패를 검증한다.
