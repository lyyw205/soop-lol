# 경기 상세 공용화 · 2026-09-22

개인 매치 히스토리는 코어 로스터 정보를 받고도 합쳐진 이름 목록만 표시했고, 상대전적 상세의 `ExpandPanel`은 첫 세트 로스터만 표시했다. 검색·레이아웃을 공유하던 것과 달리 경기 상세는 중복 구현되어 있었다.

두 화면을 `packages/ui/match-details.tsx`로 교체했다. 같은 세트의 블루/레드 팀, 팀 이름, 승패, 참가자, 챔피언 이미지·이름, 포지션, KDA를 같은 구조로 표시한다. 세트 선택은 해당 세트의 전체 로스터를 바꾼다. 참가자 전적 링크도 현재 세트의 팀 관계를 기준으로 만든다. NULL KDA는 `—`, 실제 0은 `0`으로 표시한다.

같이 정리한 부분:

- `RosterEntry` 중복 선언을 없애고 `PublicRosterEntry` 계약을 사용한다.
- 프로필 `Avatar`와 상대전적 `Portrait`의 이미지 렌더링을 공용 `packages/ui/avatar.tsx`로 통합한다. 기존 호출 경로는 얇은 어댑터로 유지한다.
- 사용처가 없는 이전 `OpponentCard`, `OpponentFilters`, `OpponentFixture`, `OpponentRowCompact`, `GameList`, `SeriesLog`, 이전 요약 보조 UI와 대응 CSS를 제거한다.
- 개인/상대전적의 조회·집계 및 접힌 행의 관점은 각 화면에 유지한다. 공용/개별 책임은 `packages/ui/README.md`에 기록한다.

검증:

- 공용 모델 테스트 3개: 팀 이동에 따른 링크, 조회 조건 유지, 자기 자신·미확인 관계, 포지션 순서, 빈 로스터, NULL·0·일부 확인 KDA.
- 웹/모듈 TypeScript 및 모듈 경계 검사 통과.
- 첫 프로덕션 빌드는 통과했다. 모바일 보완 후 최종 빌드는 UI 컴파일에 성공했으나, 동시 작업 중인 `apps/web/app/admin/ck/actions.ts`의 CK 입력 타입 불일치(`result_evidence`, `event_id`, `upsert` 등)로 타입 검사에 실패했다. 이 관리자 코드는 변경하지 않았다. 기존 CK 프레임 파일 추적 경고도 별도 작업이다.
- 실제 공개 기록의 동일 경기 2세트·참가 정보 18건을 개인 기록과 상대전적 양쪽에서 확인. 세트를 전환할 때마다 팀·포지션·챔피언·KDA를 DB 공개 로스터와 대조했고, 두 화면의 팀 영역 내용이 일치했다.
- 360px 모바일 가로 넘침 없음. 세트 버튼, 프로필/전적 링크 및 클라이언트 런타임 오류 확인.
- 실제 DB 검증은 읽기만 수행했다. 이미지 파일은 양쪽 화면의 데스크톱/모바일 캡처다.
