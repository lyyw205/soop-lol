## 1. 검색 수요 가설 (원문 표현 기반 — 검색량 검증 필요)

`customer-research.md` 의 원문 표현에서 뽑은 검색어 패턴. **검색량은 아직 모른다** — 네이버 검색광고 키워드 도구(무료, 계정 필요 — 사용자 작업)로 확인 후 우선순위 확정.

| 패턴 | 예 | 받을 페이지 |
|---|---|---|
| {이름} CK 전적 / {이름} 롤 전적 / {이름} 내전 | "김민교 CK 전적" | 스트리머 |
| {A} {B} 상대전적 / {A} vs {B} / {A} {B} CK | "김민교 깐숙 상대전적" | **A vs B** |
| {주최}CK / {주최}CK 결과 | "천상계CK", "호우CK 결과" | 날짜별 CK(시리즈 제목 포함) |

## 2. 주소 구조 (site-architecture)

```
/                                   게임 선택(현행)
├── /lol                            롤 허브 — 오늘의 CK·최근 대회·인기 맞대결로 연결
│   ├── /lol/streamers              스트리머 목록(현행) — 모든 스트리머 페이지로 가는 길
│   ├── /lol/s/{slug}               스트리머(현행) — 탭은 같은 주소(쿼리) + canonical 은 본 주소
│   ├── /lol/versus/{slugA}/{slugB} ★ 신규: 맞대결 — 쌍 순서는 정규화(slug 사전순), 반대 순서는 301
│   ├── /lol/ck                     ★ 신규: CK 허브 — 최근 날짜 목록·연승/연패
│   │   └── /lol/ck/{YYYY-MM-DD}    ★ 신규: 그날 CK 시리즈·판 결과
│   └── /lol/tournaments/{slug}     대회(현행)
└── /fc/...                         같은 틀(2순위)
```

- **slug 는 지금처럼 SOOP 방송국 아이디를 쓴다** — 닉네임이 바뀌어도 주소가 안 깨진다(숲로그는 한글 닉네임 주소라 개명 시 끊긴다). 검색어인 한글 이름은 제목·H1·본문에 둔다.
- **옛 주소 보존:** `/lol/versus?a=&b=` 는 새 경로로 301. 탭 쿼리(`?tab=`)는 canonical 로 본 주소에 모은다.
- **허브-바퀴살 연결:** 스트리머 페이지 → 상위 맞대결 상대 목록(각 A vs B 링크) → 맞대결 페이지 → 그 판이 있던 날짜 페이지 → 대회. 고아 페이지 0개.
- **빵부스러기(breadcrumb):** `롤 > 스트리머 > 김민교`, `롤 > 맞대결 > 김민교 vs 깐숙`, `롤 > CK > 2026-10-13`.

## 3. 자동 생성 페이지 (programmatic-seo) — 무엇을 색인하나

데이터는 **우리가 만든 것(VOD 판독·검수)** — 스킬 기준 가장 방어력 높은 '독자 데이터'.

| 페이지 | 색인 조건 | 수(2026-10-15 DB) | 색인 안 하는 것 |
|---|---|---|---|
| 스트리머 | 경기 기록 1판 이상 | 약 411 | 기록 0명(목록에선 보이되 noindex) |
| **A vs B (롤, CK·대회·번외 포함 상대 관계)** | **서로 다른 경기 5판 이상** | **2,199** (3판↑ 3,994 · 10판↑ 751 · 30판↑ 158) | 3~4판은 noindex,follow / 2판 이하는 페이지 없음 |
| A vs B (롤 공개큐만) | 같은 페이지 안 섹션으로 | 쌍 612 (5판↑ 55) | 별도 페이지 안 만든다(얇다) |
| 날짜별 CK | 그날 CK 1시리즈 이상 | 76일 (매일 증가) | – |
| 대회 | 공개 대회 | 롤 193 · FC 18 | – |

**얇은 페이지 방지(쌍 페이지가 변수만 바꾼 복사본이 되지 않게):**
- 맨 위 한 문장 요약은 **데이터로 갈라지는 문장** — 예: "김민교는 깐숙에게 맞라인 27전 12승 15패. 최근 5판은 3승 2패로 흐름이 바뀌었다." (연승·역전·첫 맞대결 등 조건별 문장)
- 판별 기록 표(날짜·주최CK·챔피언·KDA·승패·**그 판 다시보기**), 같은 팀일 때 승률(케미), 챔피언 상성, 최근 흐름
- 표본이 작으면 "참고용" 표시(원칙 3) — 3승 0패를 100%로 쓰지 않는다

## 4. 페이지별 제목·설명 규칙

| 페이지 | `<title>` | meta description |
|---|---|---|
| 스트리머 | `{이름} CK 전적 · {N}전 {W}승 {L}패 · {월/일} 갱신 \| SOOP SEEK` | `{이름}의 롤 CK·대회 전적. 맞라인 상대 {top상대} 외 {k}명, 최근 {날짜} {주최}CK {승/패}. 매일 자동 갱신.` |
| A vs B | `{A} vs {B} CK 상대전적 {Wa}:{Wb} \| SOOP SEEK` | `{A}와 {B}의 롤 CK·대회 맞대결 {N}판. 맞라인 {x}판, 같은 팀 {y}판. 최근 {날짜}. 판마다 다시보기.` |
| 날짜별 CK | `{M월 D일} 롤 CK 결과 · {주최CK들} \| SOOP SEEK` | `{날짜} SOOP 롤 CK {n}개 시리즈 결과: {주최CK} {스코어} … 판별 챔피언·KDA.` |
| 대회 | `{대회명} 결과·대진 \| SOOP SEEK` | 우승팀·준우승·기간 |

- 제목에 **Riot ID(계정 이름)는 넣지 않는다** — 부계정 노출 위험(CLAUDE.md 원칙 2·RESEARCH §6).
- 이름이 바뀐 스트리머는 본문에 "이전 이름: …"(streamer.aliases) — 옛 이름 검색도 받는다.

## 5. 기술 SEO (seo-audit) — 출시 전 필수

- **`sitemap.xml`** — 종류별로 나눈 사이트맵 묶음(스트리머·맞대결·날짜·대회). `lastmod` 는 **실제 데이터가 바뀐 시각**(파생 갱신 시각) — 거짓 lastmod 는 신뢰를 잃는다.
- **`robots.txt`** — /admin·/me·/login·쿼리 변형 차단, 사이트맵 위치. AI 봇 정책은 아래 §8. 구현: `apps/web/app/robots.txt/route.ts`(봇 차단과 같은 목록).
- **canonical** 전 페이지, 쌍 순서 정규화, 쿼리 탭은 본 주소로.
- **서버 렌더링 확인** — JS 없이 받은 HTML 에 제목·요약·표가 들어 있어야 한다(네이버). 숲로그 수준 이상 확인을 검증 항목으로.
- **크롤러 부하** — 2,900+ 페이지를 검색봇이 훑으면 DB 질의가 몰린다(PLAN M4-1 의 동시 접속 문제와 같은 곳). 쌍 요약은 **파생 표로 미리 계산**(원칙 5, 재계산 가능)하고 페이지는 캐시(정해진 주기 재생성). 크롤러 때문에 사이트가 멈추면 안 된다.
- **숨김 처리 존중** — 스트리머가 숨김 요청(visibility)하면 그 페이지·관련 쌍 페이지를 사이트맵에서 빼고 noindex/404. 검색에 남지 않게.
- **공유 이미지(OG)** — 맞대결·스트리머마다 자동 생성 카드(이름·스코어·고유 색/로고). 갤러리에 링크를 붙이면 카드가 뜨게 — Sharp 의 '찾는 순간 바로 닿기'.
- 404/소프트 404, 한 주소 한 페이지, 대소문자·끝 슬래시 규칙 하나로.

## 7. 네이버·다음 (스킬에 없는 국내 보완)

- **네이버 서치어드바이저** 소유 확인 + 사이트맵 제출 + **RSS 제출**(새 CK 결과를 RSS 로 — 네이버 수집 신호로 쓰인다).
- **IndexNow** — 새 페이지·갱신을 즉시 알림(빙 등). 네이버 지원 여부는 서치어드바이저에서 확인 필요.
- **다음 웹마스터도구** 등록.
- 검색량: **네이버 검색광고 키워드 도구**(무료, 광고 집행 없이 계정만) — §1 패턴 확정.

## 8. AI 검색 (ai-seo)

- 페이지 맨 위 **한두 문장 사실 요약**(누가·몇 판·몇 승·최근 언제) — AI 답변이 인용하기 좋은 형태. 숲로그의 분석 글처럼 '숫자 + 출처'.
- **결정(2026-10-15): AI 검색·답변 봇은 허용, 학습용 수집은 금지.** OAI-SearchBot·ChatGPT-User·PerplexityBot·Claude-SearchBot 등은 열어 두고(OpenAI·Perplexity 는 공개 IP 목록으로 진짜를 확인해 검색봇 한도), GPTBot·ClaudeBot·CCBot·Google-Extended 등은 robots.txt 금지 + 무시하면 403. robots.txt 에 `Content-Signal: search=yes, ai-input=yes, ai-train=no`. Google-Extended 를 막아도 구글 검색·AI 개요(Googlebot)에는 영향 없다.

## 9. 측정

- 구글 서치 콘솔·네이버 서치어드바이저: 색인된 페이지 수, 노출·클릭, 검색어(어떤 "○○ 전적"이 들어오나).
- 목표 지표(DAU·MAU·재방문율)와 연결: 검색 유입 → 두 번째 방문 비율.
- 월 1회 경쟁 비교: 같은 검색어에서 숲로그·sooplol 대비 노출(사람이 확인).

## 11. 일정에 대한 제안 — 도메인과 색인은 일찍

검색 노출은 색인·신뢰가 쌓이는 데 **몇 주~몇 달**이 걸린다. 숲로그는 이미 그 시계를 돌리고 있다. 도메인 구입과 서치 콘솔·서치어드바이저 등록은 **출시 기능이 다 되기 전에** 해 두는 편이 유리하다(운영자 결정 사항 — 미완성 화면을 먼저 열지 여부와 함께).

## 열린 결정 (사용자)

4. AI 학습용 크롤러 차단 여부(§8).
