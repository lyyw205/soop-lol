# FC 온라인 사이트와 대회 기록

## 화면

게임 선택 드롭다운에서 `/fc`로 이동한다. 상단의 **전적 검색** 한 화면에서
LoL과 같은 개인 기록·상대전적 검색 탭을 고른다. 결과는 각각
`/fc/s/[slug]`, `/fc/versus?a=...&b=...`에 표시되며 검색창을 유지한다.
검색 첫 화면에는 실제 맞대결이 가장 많은 공개 스트리머 쌍의 상대전적 카드를 보여 준다.
개인 결과는 프로필·승무패·승률 카드 아래에 매치 히스토리/상대 전적/대회/스쿼드 탭,
카드 위의 경기 모드·기간 필터는 네 탭과 카드 지표에 공통 적용되며 탭을 옮겨도 유지된다.
필터 조건은 최근 경기 제한보다 먼저 DB 질의에 적용한다.
상대 전적 탭은 LoL처럼 정렬 가능한 펼침 카드와 경기별 기록을 보여 준다.
대회 탭은 확인해 연결한 경기의 승·무·패를 카드에 집계하고, 스쿼드 탭은
LoL 챔피언 탭과 같은 기록 표 배치로 출전 선수·사용률·골/도움·평점을 보여 준다.
맞대결 결과는 LoL 상대전적처럼 검색·경기 모드/기간 필터·전적 카드·날짜별 경기 기록
순서로 표시하고 우측에 스트리머 정보 패널을 둔다. 경기 기록 아래에서 경기 지표와
사용 선수 탭을 열 수 있다.
카드 지표·스쿼드 분석은 수집 경기 전체를 쓰지만, 개인 매치 히스토리와 상대 전적
목록에는 양쪽 OUID가 각각 **공개 스트리머 계정에 연결된 경기만** 표시한다.
일반 이용자와의 경기는 목록에서 제외한다. OUID 문자열끼리 같은지 비교하는 것이
아니라 `streamer_fco_account`에서 상대 OUID를 다른 `streamer_id`로 확인한다.
기존 `/fc/s/[slug]/squad` 주소는 같은 프로필의 스쿼드 탭으로 이동한다.
대회(`/fc/tournaments`)와 리더보드(`/fc/leaderboard`)는 별도 메뉴다.
경기 상세(`/fc/m/[matchId]`)에는 양쪽 경기 지표, 슛 위치와 경기 당시
선수별 기록이 있다. 개인기록의 스쿼드 분석은 최근 수집 경기에서 실제 사용한 선수의
출전·골·도움을 집계한다. 현재 보유 스쿼드를 뜻하지 않는다.

화면 틀은 LoL 기록실과 같은 헤더·본문 폭·2단 개인기록 레이아웃을 쓰며,
요약 카드·탭·날짜별 경기 타임라인·대회 목록 컴포넌트를 공유한다.
FC의 포인트 녹색 `#04e45f`는
[FC 온라인 공식 사이트 CSS](https://js.nexon.com/s3/fc/online/obt/fo4_ssl.css)의
헤더 내비게이션 강조색을 기준으로 잡았다. FC 전용 장식 요소(예: 슛 위치 경기장)를
제외하고는 게임 전환 시 화면 문법이 달라지지 않게 한다.

대회 상세는 **확인해 연결한 경기만** 집계한다. 팀 단위 승무패·골·슛·패스·점유율과
선수별 출전·골·도움·평점을 보여 준다. API에서 정확한 볼터치 수를 확인하지 못했으므로
다른 지표를 볼터치로 이름 붙이지 않았다.
몰수 경기의 화면 스코어(`goalTotalDisplay`)와 실제 득점(`goalTotal`)은 따로 저장한다.

## 데이터 입력 순서

1. `npm run db:migrate`로 `0029_fconline_records`와 `0030_fconline_display_score`를 적용한다.
2. 스트리머와 FC 감독명이 실제로 같은 사람임을 확인한 뒤
   `npm run fco:sync -- --streamer 스트리머slug --nickname 감독명 --source-url 확인근거URL`로
   계정을 연결하고 최근 공식경기·친선 기록을 수집한다. 기본값은 매치 타입마다 최근 20개다.
   `--limit 100`까지 늘릴 수 있다. 1:1 외 모드는 현재 저장하지 않는다.
   지난 기록은 `--matchtypes 60 --offset 20 --limit 80`처럼 모드와 구간을 골라 더 수집한다.
3. 대회 날짜에 수집된 경기를
   `npm run fco:find-event-matches -- --from YYYY-MM-DD --to YYYY-MM-DD --streamer 스트리머slug`로
   찾는다. 이 출력은 후보이며 대회 경기라는 뜻은 아니다.
4. 방송 VOD나 대회 공지로 확인한 넥슨 matchId만
   `npm run fco:link-event -- --match-id 넥슨matchId --slug 대회slug --name '대회명' --source-url 확인근거URL`로
   연결한다. 첫 연결에서 대회가 생성된다. 같은 대회에 속한 다른 경기도 반복해서 연결한다.
5. `npm run verify:fco`로 수집·대회 연결·공개 질의를 임시 DB에서 검증한다.

넥슨 매치 상세 원본은 `fco_match_detail.payload`에 남는다. 스탯표는 이 원본의
`matchInfo`에서 계산한다. 새 감독명을 닉네임만으로 기존 스트리머에 자동 연결하지 않는다.
대회 연결 역시 시간대만으로 자동 확정하지 않는다.

현재 `fco:sync`는 수동 실행 명령이다. 운영 자동 수집을 시작하려면 별도 워커 잡과
재조회 정책을 붙여야 한다. 대회 데이터가 없는 상태에서는 각 화면에 빈 상태가 표시된다.

## 첫 운영 데이터 (2026-09-23)

사용자가 확인한 감독명으로 김민교→교로텔리, 이상호→메시연,
스맵(`smebim`)→바르셀리아, 두치와뿌꾸(`doochiwa-ppukku`)→호날두를 연결했다.
두치와뿌꾸는 기존 스트리머 행이 없어 새로 등록했다. 네 감독의 최근 1:1 경기
상세를 수집했으며, 과거 전체 전적을 의미하지 않는다.

[SOOP의 대회 소개](https://pick.sooplive.com/daily/view/182785)와
[두치와뿌꾸의 당일 VOD](https://vod.sooplive.com/player/205320949)를 근거로
`2026-mini-ppuchamps` 대회를 등록했다. 공식 소개의 최종 3·4위(스맵·이상호)와
일치하는 스맵 1:0 이상호 경기(`6a8d9a0b73e031dce3609ee8`), 이어진 스맵
2:3 상대 경기(`6a8da1b6b50f4b19579a2d5a`) 두 건만 우선 연결했다.
같은 방송 시간대에 수집된 나머지 경기들은 연습 경기 가능성이 있어 미연결 상태다.
따라서 대회 스탯표는 **전체 대회 성적이 아닌 확인된 2경기의 부분 집계**다.
