# 백필 안정성·사용량 개선 최종 계획

작성: 2026-10-04. 구현·검증 결과는 아래 실행 기록에 갱신한다.

## 검토 결론

기존 계획의 방향은 타당하지만, 새 작업 상태 체계나 완료 게이트를 만들면 현재 구조와 충돌한다.
`event_lead.raw.scan`, 후보, `match_pov`가 정본이고 `ck:merge`가 유일한 저장 창구인 구조를 유지한다.
자동·수동 백필의 완료 판정(`vodWork`), 경기별 트랜잭션, 재전송 멱등성, 검수값 보호,
다른 시점의 독립 판독을 유지한다. 진행 요약은 정본에서 다시 만들 수 있는 읽기 자료다.

| 검토 관점 | 확인한 사실·위험 | 최종 결정 |
|---|---|---|
| 완료 의미 | `done`은 필수 탐색 종료이며 미해결 사실이 남아도 가능하다 | 의미를 바꾸지 않는다. 완료와 미해결 수를 함께 보고한다. 후보가 남았다는 이유로 전체 VOD를 다시 돌리지 않는다 |
| 재시작 | 기존 셸은 DB를 재조회하고 같은 VOD를 새 세션으로 이어간다 | 새 커서 테이블을 만들지 않는다. DB에 저장된 경기·열람 진척도 측정하고 짧은 재개 요약을 전달한다 |
| 진척 판정 | 전체 requested가 이미 채워지면 새 경기를 저장해도 기존 지표가 변하지 않을 수 있다 | 시점 저장·후보 결론·남은 범위 감소와 원본 열람만 있는 활동을 구분한다. 결과 없는 연속 세션은 3회 후 보류하고 재실행에도 제한을 유지한다 |

| 공용 이미지 | 1280×720 시트를 1920×1080 고정 좌표로 자른 실제 실패 확인 | JS 공용 추출과 Python 판별·학습 모두 실제 10×10 격자를 자르고 표준 칸으로 정규화한다. 시간축은 유지한다 |
| 라벨 품질 | 여러 라벨 중 뒤쪽 입력이 틀려도 앞부분이 이미 저장되는 경로가 있다 | 전체 입력 검증 뒤 한 번에 기록한다. 열람 근거를 요구하고 무검증 일괄 기본값은 없앤다 |
| 학습 | 수집·학습 명령은 이미 있다. fit은 현재 모델을 직접 교체한다 | 자동 학습으로 오해하지 않도록 문서화한다. 후보 모델을 별도 출력하고 평가 후 명시적으로 적용하는 경로를 만든다 |
| 평가 | 같은 채널 일부를 학습에 넣은 기존 test 분할은 엄격한 신규 채널 시험이 아니다 | 이 한계를 표시한다. 운영 성능 개선은 별도 검증 없이 주장하지 않는다 |
| 실행 모델 | --model 생략 시 전역 설정 변화에 영향받는다 | 백필 자식 모델을 명시한다. 전역 설정은 변경하지 않는다 |
| 병렬 실행 | 서로 다른 별칭이 같은 채널을 가리키거나 일부 worker가 막힐 수 있다 | 채널별 잠금·실패 보고를 보완한다. SOOP 호출은 기존 속도·직렬 규칙 유지 |
| 접근 실패 | 빈 files, 네트워크 실패만으로 영구 접근 불가를 확정할 수 없다 | 근거를 남기고 temporary/unavailable을 구분한다. 무제한 재시도는 하지 않는다 |
| 데이터 정리 | 불일치 25항목과 중복 후보는 모두 오답으로 확정된 것이 아니다 | 원본 근거 없이 자동 덮어쓰기·합치기를 하지 않는다. 기존 검토 목록을 유지한다 |
| 칼바람 | 기존 VOD 저장 경로는 모두 CUSTOM으로 넣어 게임 규칙을 잃었다 | 경기의 game_mode와 대회 성격(event.kind)을 분리한다. 새 경기에는 모드를 요구하고 칼바람은 공개 전적·조우·챔피언 집계에서 분리한다 |
| 배포 호환 | 새 분류 함수는 0071이 있어야 한다. 구형 3인자 함수도 사용처가 있다 | 새 4인자 함수를 추가하고 구형 함수를 유지한다. 스키마를 먼저 적용하고 수집 코드를 전환한다 |

## 무엇이 근본 수정이고 무엇이 조정인가

- **저장했는데 진척 없다고 멈춤:** 진척 판정에 새 경기/시점 저장이 빠져 있던 결함이다. DB의 실제 저장 수를 함께 비교하도록 고쳤다.
- **720p 준비 실패/잘못된 칸:** 화면 크기를 고정한 공용 추출기의 결함이다. JS와 Python 모두 실제 격자를 사용하게 고쳤다. 판별기를 재학습하는 것으로 해결할 문제가 아니었다.
- **긴 세션의 토큰 누적:** 앞 경기 이미지·도구 출력이 매 호출의 문맥에 남는다. 새 세션에 짧은 DB 요약만 넘기는 구조로 줄인다. 캐시는 이 문맥을 싸게 재사용하는 장치이며 캐시 자체를 없애는 것이 해법은 아니다.
- **갑작스러운 모델 변화:** 전역 모델 설정을 상속하던 실행 문제다. 조사 모델을 명시하고 실제 사용 모델도 기록한다.
- **칼바람이 일반 전적에 섞임:** 원본에 모드를 저장하지 않고 대회 종류만으로 집계한 분류 문제다. UI에서 이름만 바꾸는 것으로는 해결되지 않아 저장·계산·공개 조회를 함께 수정했다.
- **학습하면 좋아진다는 보장 없음:** 판정 수집과 실제 학습/적용은 별개다. 운영 파일 덮어쓰기를 막고 후보 생성과 평가를 분리했다. 정답 품질과 독립 평가 자료의 부족은 코드만으로 해결되지 않는다.
- **챔피언 오독이 전부 이미지 인식 문제는 아님:** 207056363의 5,836초 선택창에서는 붕어에몽이 신드라지만, 5,959초 실제 경기에서는 아트록스다. 교환 전 선택값을 최종값으로 삼은 판정 단계 오류다. 실제 경기·결과창으로 최종 챔피언을 확인하도록 판독 지침을 보완했다.
- **시점이 바뀌면 팀 방향도 바뀜:** 화면의 위 팀을 무조건 기존 경기의 100팀으로 취급하면 승패가 뒤집힌다. 206716943의 추가 시점이 이 사례였다. 각 시점의 참가자 구성을 기준으로 방향을 대조하고, 그 시점의 원본 판독값을 정정했다.
- **같은 판의 다른 경기 ID:** 같은 ID 재전송에 대한 멱등성만으로는 다른 방송에서 새 ID로 만든 중복을 막지 못한다. 기존 경기 조회와 원본 비교가 필요하다. 이번에는 확인한 중복을 기존 숨김 경로로 제외했다. 자동 판정·물리적 병합·별칭 리다이렉트까지 구현한 것은 아니다.

5경기라는 숫자, sonnet의 정확도/비용 균형, 최종 절감률은 조정·측정 대상이다. 결함 수정과 효과 추정을 구분한다.

## 구현 순서

1. 공용 이미지 추출 오류, 진척 누락·대체 후보 집계 오류를 회귀 테스트와 함께 수정한다.
2. 기존 DB에서 재개 정보를 생성하고, 짧은 다음 행동·맥락을 scan에 저장한다. 경기·근거는 기존 테이블에 남긴다.
3. 셸의 모델, 세션 분량, 준비물 재사용, 채널 잠금·실패 보고를 보완한다. 실제 백필을 임의 재시작하지 않는다.
4. 판정 기록의 사전 검증과 학습 모델의 후보 출력을 구현한다. 평가 후 운영 적용은 별도 명시 작업으로 둔다.
5. 칼바람 모드 저장과 일반 집계 분리를 추가한다. 확인한 기존 경기만 근거·수정 이력과 함께 정정할 도구를 제공한다.
6. 실제 셸·임시 DB 통합 검증과 공용 경계 검증을 실행한다. 운영 모델·DB의 불확실한 경기값은 이 코드 변경으로 대량 교체하지 않는다.

## 수집 정책

사용자 결정: **스트리머끼리의 칼바람 내전도 보상 유무와 관계없이 수집하며 일반 CK·대회·협곡 전적과 분리한다.**
새 VOD 경기에는 CLASSIC/ARAM을 필수로 받는다. 못 확인하면 unresolved 후보로 남긴다.
보상 여부는 event.kind의 근거이며 모드와 별개다. 보상 미확인 친목 내전은 other, 확인된 보상 내전은 ck로 기록해도
ARAM 모드가 우선해 `aram_custom`으로 집계된다. 공개 큐 칼바람은 `aram`이며 사설 내전과도 구별된다.
기존 CUSTOM은 모드 미분류라는 뜻이다. 기존 시점의 부분 제출은 호환하되 옛 경기를 제목만 보고 일괄 재분류하지 않는다.
별도 상단 메뉴는 후속 ARAM 모듈로 만든다. 이번 수정은 수집과 경기 기반 집계 분리 및 그 공개 조회 경계까지다.
재방송·시청 장면은 화면 속 경기의 대상 여부와 중복 여부를 확인한다. 단순히 시청이라는 이유로 일괄 제외하지 않는다.
기존 공식 LCK Watch Party 태그의 비용상 제외 정책은 유지한다. 이 정책도 영상 안 내전이 없다는 증명은 아니다.

## 검증과 확대 기준

- 회귀: 720p/1080p 시트의 마지막 칸·시간축, 잘못된 시트 거부, 라벨 부분 저장 방지.
- DB: 새 경기 저장은 진척, 같은 제출·메모만 변경은 무진척, supersedes 후보 제외, 미해결이 있어도 탐색 done 유지.
- 셸: 잠금·중단·재개·Claude 실패·준비 실패·모델 고정·FC 경로 호환.
- 기존 `npm test`, `verify:db`, `verify:ingest`, `verify:modules`, CK backfill/POV 검증을 수행한다.
- 실제 품질/절감률은 같은 VOD 구간과 동일 모델의 대조 시험으로만 확인한다. 입력·캐시쓰기·캐시읽기·출력을 따로 기록하고
  경기/시점당 토큰, 호출 수, 시간, 누락·오독·재처리 횟수를 비교한다. 캐시 읽기를 전부 낭비로 간주하지 않는다.
- 학습 후보는 학습에 쓰지 않은 자료에서 누락과 오탐을 비교한 후 적용한다. 비교 전에는 기존 운영 모델을 유지한다.

## 실행 기록

### 후속 리뷰 반영

- 열람만 늘어나는 경우와 실제 결과 진척을 구분하고, 전자는 연속 3회 후 미완료로 보류한다. 수동 백필 실행 횟수는 로컬 guard 파일로 보존한다. DB 진척 정본과 별개이며 새 진행 테이블은 없다.
- 분할 목표 기본값을 5에서 0으로 내렸다. 분할의 실제 절감률은 계속 측정 대상이다.
- 세션 JSON의 응답 요약과 원본 경로를 run.log에도 기록한다. 추가 LLM 호출은 없다.
- 병렬 워커의 채널 잠금 75는 건너뛰고, 공통 잠금 75와 실제 실행 실패는 기존대로 중단한다.
- Python 캐시를 무시하고 이미 추적된 6개 pyc는 Git 추적에서 제거한다. 런타임의 로컬 캐시는 보존한다.
- 백필·칼바람·공용 이미지 수정만 분리한 스냅샷으로 검증 후 커밋한다. 관리자·FC 구단·대회 변경과 0072는 이 커밋에 섞지 않는다.
- 분리 스냅샷 검증: 전체 단위 테스트 313개, core/web/worker/modules/scripts 타입 검사, 모듈 경계 자체검사 55개, Python 이미지·학습 3개 통과.
  다른 작업의 미커밋 테스트를 제외한 수치다. 백필 임시 DB 시험에서 열람만 이어진 세 번째 세션 중단, 재실행 보류, 중복 after 호출, 명시적 초기화도 통과했다.
  실제 병렬 셸에서는 중복 별칭을 건너뛰고 세 번째 독립 채널까지 처리함을 검증했다. 운영 모델이나 운영 경기값은 이 후속 수정에서 바꾸지 않았다.
  같은 분리 스냅샷에서 `verify:db`(SQL/TS 분류 1,232조합 포함), `verify:ingest`, `verify:ck:pov`, ARAM 기존 DB 업그레이드도 모두 통과했다.

5. 검증된 새 라벨로 후보 모델을 학습한다. 고정된 별도 평가 자료에서 놓친 경기·오탐을 비교하고 개선이 확인된 파일만 백업 후 적용한다.

### 되돌리기

- 분할 효과가 나쁘면 `--session-games 0`으로 분량 목표를 끄고 모델은 명시적으로 지정한다. 저장한 근거/시점/후보는 그대로 이어 쓴다.
- 새 모델은 아직 운영에 적용하지 않았다. 향후 적용 실패 시 백업한 모델 파일로 복구한다. 준비물 지문이 달라지므로 다음 준비가 다시 돈다.
- DB 스키마를 적용한 뒤 구형 수집 코드로 되돌리면 구형 3인자 집계가 ARAM을 다시 섞을 수 있다.
  따라서 단순 코드 롤백으로 운영 쓰기를 재개하지 않는다. 분류/집계 경로는 유지하거나 해당 수집을 중지한 채 호환 수정한다.
  원본 경기·근거는 삭제하지 않고 파생 통계만 다시 계산한다.
