## 1. 목적

한 CK를 여러 스트리머가 방송하면 VOD가 여러 개 들어온다. 각 VOD는 **같은 방식으로** 경기를 읽고,
이미 저장된 경기와 같으면 **경기 데이터는 하나로 두고 시점(VOD·스트리머·사진)만 여러 벌 붙인다.**
검수 화면에서는 경기 하나를 열면 모든 시점이 한 화면에 보인다.

```
경기 1개 (match)                  ← 값은 한 벌: 승패·10명·챔피언·KDA
 ├─ 시점: 저라뎃 VOD  사진 N장 · 이 화면에서 읽은 값
 ├─ 시점: 스맵임 VOD  사진 N장 · 이 화면에서 읽은 값
 └─ 시점: 임아니 VOD  사진 N장 · 이 화면에서 읽은 값
       일치·불일치는 저장하지 않고 볼 때마다 현재 경기 값과 비교해 계산한다
```

단계는 둘이다.

- **1단계 (이번 구현):** 들어온 VOD는 전부 경기를 처음부터 읽고 비교한다.
- **2단계 (나중):** 경기마다 독립 확인 3개가 모이면, 그 다음 VOD부터는 30분 간격 사진에서 보이는 만큼만
  읽는다. 이번에는 구현하지 않고 집계 원칙(5절)만 정해 둔다.

**시점 하나여도 조사 완료와 검수가 가능하다.** 다른 시점이 붙으면 반드시 비교한다(백필처럼 한 사람의
VOD만 도는 경우도 같은 구조로 저장된다).

**역할 구분:** 모델은 화면 해석·탐색·연결할 경기 후보를 판단한다. 코드는 값 비교·검수 보호·불일치 표시·사진 연결을 보장한다.

## 2. 지금 구조가 꼬인 이유 (2026-09-27 재현 실행에서 확인)

| 현상 | 원인 |
|---|---|
| 임아니 VOD 사진 41장이 검수 화면에 0장 | 사진을 기존 경기에 붙이는 방법이 `resultType: "match"` 재제출뿐인데, 재제출하면 참가자 10명을 **지우고 다시 쓴다**(`upsertMatchFromScanInTx`). 덮어쓰기를 피하려고 에이전트가 붙이기를 포기했다 |
| VOD마다 사진이 붙기도 하고 안 붙기도 함 | 같은 지시를 받은 에이전트가 "위험하니 안 붙임"과 "통째로 재제출해서 붙임"으로 갈렸다 |
| 확인하지 않은 값이 "일치"처럼 보임 | 재제출한 에이전트는 자기가 못 본 참가자 값까지 기존 기록에서 옮겨 적었다 |
| `linked`(같은 판이다)만 적고 끝남 | 9/22 재작성 때 다른 시점 처리용으로 메모 기능만 넣었다. 사진 연결·값 비교 기능은 없다 |
| 빠른 연결이 비교를 건너뜀 | 9/27에 넣은 "참가 확인 사진 한 장으로 닫는다" 규칙이 비교 없는 연결을 부추겼다 |
| 검수 목록에 같은 경기가 9줄 | `ck` 분류는 VOD 단위(`listEventLeads`)로 목록을 만든다. 대회 단위(`listReviewEvents`)는 tournament·showmatch만 쓴다 |

DB의 사진 테이블(`match_evidence_frame`)은 이미 `lead_id`(어느 VOD)와 `match_id`(어느 경기)를 따로
가진다. **경기 하나에 여러 VOD의 사진이 붙는 구조는 이미 가능하다.** 없는 것은 "비교 후 붙이기"
저장 경로와 경기 중심 검수 화면이다.

## 3. 1단계 동작 — 모든 VOD가 같은 방식으로

1. VOD가 큐에 들어온다(자동 큐·수동 백필 모두 같다).
2. 조사자는 스킬대로 VOD를 훑고, 경기를 찾으면 **경기 추적 3단계(맥락 → 경계 → 판마다 결과창)를 끝까지** 한다.
3. 읽은 경기를 `ck:merge`에 `resultType: "match"`로 낸다. 제출 명령과 형식은 하나다.
   기존 경기라고 판단하면(`--find-match` 조회와 추가 조사) 그 `match_id`를 적는다.
4. **저장 도구가 처리한다.**
   - 그 `match_id`가 없으면 → **새 경기 생성.** 지금의 필수 정보 검증(승자·결과 근거·시각 정밀도 등)을 그대로 요구한다.
   - 있으면 → **시점 추가.** 이 화면에서 직접 읽은 칸만 받는다(4.2). 경기 값은 빈 칸만 채우고, 다른 값은 덮어쓰지 않는다.
5. 연결이 확인된 시점의 제출 사진은 빠짐없이 그 경기에 연결한다. 사람이 교정한 사진 연결은 자동으로 되돌리지 않는다(4.6).
6. 경기 구간 밖(판 사이·시리즈 전후·보너스 단판·다른 게임)은 지금처럼 훑고 추적한다.

조사자는 "같은 경기인가"의 후보를 제안하고 근거를 남긴다. **"값이 같은가"는 코드가 계산한다.**
조사자는 일치 여부를 선언하지 않는다.

## 4. 저장 계약

### 4.1 시점 기록 — 신규 표 `match_pov`

경기 × VOD마다 한 행. "이 VOD가 이 경기에서 무엇을 직접 봤나"를 남긴다.

| 칸 | 뜻 |
|---|---|
| `match_id`, `lead_id` | 어느 경기 · 어느 VOD. `(match_id, lead_id)` 유일 |
| `streamer_id` | 이 VOD 방송 주인 |
| `role` | `created`(이 시점이 경기를 만듦) · `added`(기존 경기에 시점 추가) |
| `mode` | `full`(경기를 처음부터 읽음). 2단계에서 `light`가 추가된다 |
| `source` | `own`(본인 클라이언트 화면) · `rebroadcast`(남의 방송을 띄운 화면) |
| `observed` | 이 화면에서 **직접 읽은 값만**(JSON). 칸마다 값과 제출 시각을 함께 둔다. 못 읽은 칸은 키 자체가 없다 |
| `link_basis` | 같은 경기라고 본 근거(시간·로스터·챔피언 등 조사자 관찰) |
| `filled` | 이 제출로 실제로 채운 경기 칸 목록. 실제로 채우지 않았으면 비어 있다 |
| `submitted_at` | 마지막 제출 시각 |

**일치·불일치는 저장하지 않는다.** 검수 화면과 조회 도구가 볼 때마다 `observed`를 현재 경기 값과 비교해 계산한다.
사람이 검수에서 값을 고치면 모든 시점의 비교가 그 즉시 새 값 기준으로 바뀐다.

**불일치와 검수 완료는 다르다.** A가 5킬, B가 6킬을 읽고 사람이 6킬을 고르면 A의 5킬은 계속 다르다.
이 불일치가 사람이 이미 본 것인지는 기존 검수 완료 시각(`match.review_completed_at`)으로 구분한다.
**검수 완료 시각이 그 칸의 관측 제출 시각보다 나중이면 "검수 완료된 불일치", 아니면 "미해결 불일치"다.**
검수 완료는 경기 값이 바뀌면 자동으로 풀리므로(0043), 값이 바뀐 뒤의 불일치는 다시 미해결로 보인다.
새 판정 표나 이력 시스템은 만들지 않는다.

사진은 기존 `match_evidence_frame`에 `lead_id`·`match_id`를 채워 붙인다. 사진 칸은 새로 만들지 않는다.

### 4.2 제출 규칙 — 직접 읽은 값만

- **새 경기 생성**은 지금의 필수 정보를 그대로 요구한다.
- **시점 추가**는 그 화면에서 직접 읽은 칸만 낸다. 못 읽은 값을 기존 기록에서 복사해 내지 않는다.
  복사한 값은 항상 "일치"가 되어 확인하지 않은 값을 확인한 것처럼 보이게 한다.
- **생략과 0은 다르다.** 칸이 없으면 "안 읽음"이다. `kills: 0`은 읽은 값이다.
- **참가자는 줄 순서가 아니라 사람으로 맞춘다.** 롤 결과창은 보는 사람의 팀이 위에 오므로 시점마다
  팀 순서가 뒤집힌다. 코드는 참가자를 사람(스트리머·계정·관찰명)과 팀으로 대응시켜 비교한다.
  대응이 불확실한 칸(이름을 못 읽은 자리 등)은 비교만 보류하고 경기 값을 자동으로 채우지 않는다.

### 4.3 비교 규칙 (코드가 계산)

| 경기 값 | 이 시점이 읽은 값 | 결과 |
|---|---|---|
| 있음 | 같음 | 일치 |
| 없음(빈 칸) | 있음 | 제출 시 **빈 칸만 채움**(`filled`에 기록) |
| 있음 | 다름 | **덮어쓰지 않음.** 불일치로 표시, 사람이 검수에서 확인한다 |
| 무엇이든 | 안 읽음(칸 없음) | 비교하지 않음 |

- 비교 대상: 승자, 경기 길이(허용 오차 ±10초), 세트 번호, 참가자별 사람·팀·포지션·챔피언·K/D/A.
- 챔피언은 표기(한글·영문)가 달라도 같은 챔피언 id면 같다.

### 4.4 덮어쓰기가 허용되는 경우

**경기를 만든(`role: created`) VOD** 외에 **다른 시점 기록이 아직 없을 때만** 그 VOD가 자기 값을 고칠 수 있다.
예전 경기(시점 기록 없음)에 처음 붙은 추가 시점은 혼자여도 만든 시점이 아니므로 덮어쓸 수 없다
(같은 조사 중 세트 순서를 바로잡는 경우 등, 지금 동작 유지). 다른 VOD가 한 번이라도 기록하면
그 뒤로는 자동 덮어쓰기 없이 빈 칸 채우기와 비교만 한다.

### 4.5 경기 연결 확인과 사진 범위

**어느 경기인지 확인하는 근거**와 **붙일 수 있는 사진의 범위**는 따로 본다.

- **연결 근거:** 시간·로스터·챔피언 등 조사자가 `link_basis`에 남긴 관찰. 새 자동 경기 식별기는 만들지 않는다.
  후보 탐색은 기존 `--find-match`, 판단은 조사자의 추가 조사로 한다.
- **사진 범위:** 그 경기의 밴픽(시작 전)·로딩·인게임·결과창(종료 후)을 모두 붙일 수 있다.
  "사진 시각이 경기 시작~끝 안" 같은 조건을 두지 않는다. 밴픽·결과창이 거부되기 때문이다.
- **코드가 거부하는 경우(명백한 모순만):**
  - 이 시점의 사진 시각이 경기 시각과 명백히 떨어져 있다(기준: 경기 시작 30분 전보다 이르거나 종료 30분 뒤보다 늦음).
    **이 검사는 실제 경기 시각과 방송 시각을 직접 대응할 수 있을 때만 적용한다.** 즉 `source: own`이고,
    경기 시각이 `datetime`으로 확인됐고, VOD 시간축이 연속이라 사진의 절대시각을 믿을 수 있을 때다.
    VOD가 중간에 끊겨 시각 대응이 불확실하면 이 검사로 거부하지 않고 조사자 근거로 판단한다.
  - `source: own`인데 방송 주인이 그 경기 참가자에 없다.
- **±30분 안이라는 사실은 같은 경기의 증명이 아니다.** 모순이 없다는 뜻일 뿐이다. 연속 판·보너스 단판은
  30분 안에 여럿 있을 수 있으므로 연결 근거(챔피언·로스터·세트 표기 등)는 따로 필요하다.
- **확정하지 않는 경우:** 경기 시각이 날짜 단위(`date`)라 연속된 판을 시간으로 가를 수 없고, 로스터도 같으면
  연결을 확정하지 않는다. 조사자가 챔피언·세트 표기·스코어 등으로 추가 조사해 근거를 남긴 뒤에만 연결한다.
- **재송출(`rebroadcast`)도** 어느 경기인지 확인하는 근거가 필요하다. 방송 주인 참가 조건과 ±30분 검사는 적용하지 않는다.
  몇 시간 전 경기를 다시 보는 방송은 촬영 시각과 경기 시각이 다르기 때문이다. 대신 원본 경기와 이어지는
  별도 근거(화면 속 방송·경기 시각, 세트 표기, 결과창 내용, 참가자·챔피언 일치 등)를 `link_basis`에 남긴다.

### 4.6 경기 값 보호와 사진 연결은 별개

- **검수 완료 뒤 새 미해결 불일치가 생기면 검수 완료(`review_completed_at`)를 푼다.** 경기 값을 덮지 않으므로
  값 변경으로 풀리는 0043 트리거가 걸리지 않는다. 풀지 않으면 상세에는 미해결인데 목록은 검수 완료로 남아
  사람이 새 오류를 못 본다. 다시 완료하면 그 불일치는 "검수 완료"가 된다.
- **검수된 경기**(`reviewed_at`)의 값은 자동으로 바꾸지 않는다. 빈 칸 채우기도 하지 않으며, 이때 `filled`는 비어 있다.
- 검수된 경기에도 **새 시점 기록과 사진은 추가할 수 있다.**
- 사람이 연결을 해제하거나 다른 경기로 옮긴 사진은 기존 사진 검수 보호 규칙(사진의 `reviewed_at`)을 그대로 따른다.
  자동 수집이 그 연결을 되돌리지 않는다.

### 4.7 재제출과 관측 이력

- **재제출은 제출한 칸만 갱신한다. 생략한 칸의 이전 관측값은 유지한다.** 챔피언·KDA를 낸 뒤 KDA만 고쳐
  다시 내도 챔피언 관측은 남는다.
- **잘못 읽은 값을 철회할 때는 그 칸을 `null`로 명시해 낸다.** 생략(그대로 둠) · `0`(읽은 값) · `null`(철회)은 서로 다르다.
- 관측값이 바뀌거나 철회되면 **이전 값을 그 시점 행의 `history`에 남긴다.** 재제출만으로 불일치가
  조용히 사라지지 않고, 무엇이 왜 바뀌었는지 추적할 수 있다.
  (계획은 `review_record` 였으나, 그 표는 후보·프레임 단위 제약과 후보별 유일 인덱스(0024) 때문에 한 시점의
  반복 이력을 담을 수 없었다. 별도 이력 표 대신 같은 행의 칸으로 두었다.)
- 바뀐 칸은 제출 시각도 새로 찍히므로, 이전에 검수 완료된 불일치라도 새 관측은 다시 미해결로 보인다.
- 사람이 검수에서 고른 값은 지금처럼 `review_change`에 남는다.

### 4.8 `linked` 후보의 새 뜻

후보 결론 `linked`는 유지하되, **같은 파일에 그 경기의 시점 제출(`match`)이 있어야 한다.**
없으면 `ck:merge`가 거부한다. 메모만 남기고 사진·비교가 빠지는 일(임아니 사례)을 코드로 막는다.

## 5. 2단계 — 토큰 절약 (이번에 구현하지 않음)

이번에는 가벼운 모드와 확인 수 집계를 구현하지 않는다. 나중에 구현할 때 따를 원칙만 정한다.

**구체화한 계획: [CK-POV-LIGHT-PLAN.md](CK-POV-LIGHT-PLAN.md)** (힌트 목록·통과 조건·확인 못 함(B) 처리).

### 5.1 "독립 확인 3개"를 세는 원칙

`match_pov` 행 세 개가 곧 확인 세 개는 아니다.

- **경기마다 센다.** 보너스 단판처럼 방송한 사람이 적은 판은 따로 센다.
- **스트리머 기준으로 센다.** 한 방송이 VOD 여러 개로 쪼개져 올라온 경우(예: 클리드1의 208032325/208032415,
  208191839/208192427)는 시점 하나다.
- **재송출은 세지 않는다.** 남의 방송을 띄운 화면은 같은 원본이다.
- **조사를 끝낸 것과 교차 확인한 것은 다르다.** 행이 있다는 것만으로 세지 않고, 그 시점이 실제로 읽어
  비교한 칸을 본다. 승자와 참가자 10명의 챔피언·KDA를 직접 읽어 경기 값과 일치한 시점만 "전체 확인"이다.
  챔피언 하나만 맞춰 본 시점은 전체 확인이 아니다.
- **미해결 불일치가 있으면** 그 경기는 가벼운 모드 대상이 아니다. 검수 완료된 불일치는 막지 않는다.
- 이 숫자는 정답 판정이 아니라 **비용 스위치**다. 스킬의 "합격선 금지"와 충돌하지 않는다.
- 세는 것은 코드다. 모델이 세지 않는다.

### 5.2 가벼운 모드의 동작 (예정)

- 30분 간격 대표 사진에서 그 경기 시간대 화면을 열어 방송 주인·팀·챔피언을 읽고 시점을 추가한다.
- 그 경기의 결과창을 찾는 5분할은 하지 않는다.
- 사진에 그 경기가 안 걸리거나 챔피언이 안 보이면 그 경기만 전체 읽기로 돌아간다.
- 새 미해결 불일치가 나오면 그 경기는 가벼운 모드가 풀린다.
- 경기 구간 밖은 모드와 무관하게 평소대로 훑는다.

## 6. 검수 화면

- **`ck` 분류도 대회 단위 목록**을 쓴다(`listReviewEvents`). 추석 CK는 한 줄로, 그 아래 경기 4개.
- **경기 화면**(`/admin/ck/match/[matchId]`)이 VOD 화면으로 넘기지 않고, 그 경기에 붙은 **모든 시점을 스트리머별로** 보여준다.
  시점마다 사진·읽은 값을 나란히 두고, 현재 경기 값과 다른 칸을 **미해결 / 검수 완료**로 구분해 표시한다.
- 사람이 불일치 칸의 기준값을 고르면 경기 값이 바뀌고(`review_change`에 기록), 모든 시점의 비교가 새 값
  기준으로 다시 계산된다. 기준값과 다른 관측은 불일치로 계속 보이며, 사람이 검수 완료를 누르면 그 불일치들은
  "검수 완료"로 표시된다. 기준값이 이미 맞아 값을 바꾸지 않는 경우도 검수 완료만 누르면 된다.
- VOD 화면(`/admin/ck/[leadId]`)은 그대로 두되, 이 VOD 사진이 붙은 경기로 가는 링크를 보여준다.
- 조사 기록(후보·기각 구간·안 붙은 사진)은 지금처럼 `ck:record`로 본다.

## 7. 함께 고칠 것

- **`lead_match` 뷰의 URL 연결:** 같은 VOD 주소라는 이유만으로 FC 단서(`fc:208178709:13100`)가 롤 경기와
  이어져 CK 목록에 섞였다. URL 연결은 `vod:` 단서에만 적용한다.
- **스킬 문구:** "빠른 연결 · 참가 확인 사진 한 장으로 닫는다"를 지우고 "모든 시점은 이 화면에서 직접 읽은 값으로
  경기를 제출하고 도구가 비교한다"로 바꾼다. 2단계 구현 전까지 가벼운 모드 문구는 넣지 않는다.
- **자동 실행 지시문(`ck-auto.sh`):** 빠른 연결 문장을 같은 뜻으로 바꾼다.

## 8. 기존 데이터

추석 CK(`ck-2026-09-26-jeoradet-clid1`, 4경기·9 VOD)는 시점 기록이 없다. 구현 후 두 방법 중 하나로 채운다.

- **재조사(권장):** VOD를 새 방식으로 다시 돌린다. 1단계 검증을 겸한다(10절 순서대로 작게 먼저).
  이전 상태는 `out/ck/_repro-backup-20260927/`에 백업돼 있다.
- **이관:** 기존 사진·후보에서 시점 기록을 만든다. 직접 읽은 값을 가려낼 수 없는 VOD는 `observed` 없이 사진만 이어 붙인다.

다른 기존 경기(멸망전 시드 등 VOD 없는 경기)는 시점 기록 없이 그대로 둔다.

## 10. 구현·검증 순서

1. `match_pov` 표와 제출·비교·보호 규칙(4.2~4.8)을 코어에 구현하고 DB 검증 사례를 먼저 통과시킨다.
2. `ck:merge`를 새 경로에 연결하고 `linked` 제약을 건다.
3. 스킬·자동 지시문을 바꾼다.
4. 검수 화면을 경기·대회 단위로 바꾼다.
5. **작게 먼저 검증한다.** 추석 CK의 한 경기를 2~3개 시점으로 제출해 부분 제출·사진 연결·불일치 표시·
   기준값 선택과 검수 완료 후 재계산·부분 재제출과 철회 이력을 확인한다.
6. 통과하면 추석 CK 9개 VOD 전체 재조사로 넓힌다.
7. 1단계 결과를 확인한 뒤 2단계(5절)를 구현한다.

## 11. 검증 사례

| 사례 | 기대 결과 |
|---|---|

| 사람이 불일치 칸의 기준값을 고르고 검수 완료 | 비교가 새 값 기준으로 다시 계산, 남은 불일치는 "검수 완료" |

| 같은 VOD가 칸을 `null`로 재제출 | 그 관측 철회, 이력 남음 |
| 밴픽·결과창 사진 제출 | 경기 시작 전·종료 후여도 연결됨 |
| `own`·시각 확인된 경기·연속 VOD에서 두 시간 떨어진 사진 | 파일 전체 되돌림 |

| 몇 시간 뒤 재송출로 본 경기 | ±30분 검사 없이 원본 경기 근거로 연결 |
| ±30분 안의 연속 판 | 시간만으로 연결되지 않음, 챔피언 등 근거 필요 |
| 날짜 단위 경기 + 같은 로스터의 연속 판 | 추가 근거 없이는 연결 확정 안 됨 |
| `own`인데 방송 주인이 참가자에 없음 | 거부 |

| 검수된 경기에 제출 | 값 불변, `filled` 없음, 시점·사진은 추가 |
| 사람이 떼어 낸 사진을 다시 제출 | 연결 되돌아가지 않음 |
| 경기를 만든 VOD가 혼자일 때 재제출 | 덮어쓰기 허용 |
| 예전 경기에 처음 붙은 추가 시점이 필수 정보를 다 채워 재제출 | 덮어쓰지 않음(만든 시점이 아님) |
| 검수 완료 뒤 다른 값을 가진 새 시점 | 검수 완료가 풀려 미검수 목록에 다시 뜸 |
| 기존 경기에 `winning_team: null`·`team_id: null` | 철회로 받아들임(새 경기 생성에서는 거부) |

| `linked` 후보만 있고 시점 제출 없음 | 거부 |
| FC 단서와 롤 경기가 같은 VOD | CK 목록에 FC 단서가 안 나옴 |

## 12. 완료 기준

같은 경기를 여러 VOD가 제출해도 경기는 하나이고, 각 시점이 직접 읽은 값과 사진이 그 경기 아래에 남는다.
값이 다르면 덮어쓰지 않고 불일치로 보이며, 사람이 확인한 불일치는 검수 완료로 구분된다.
부분 재제출은 이전 관측을 지우지 않는다.
조사자는 VOD마다 같은 방식으로 제출하고, 같음·다름은 코드가 계산한다. 검수 목록에 같은 경기가
VOD 수만큼 반복되지 않는다.
