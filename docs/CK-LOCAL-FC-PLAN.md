# 로컬 준비 단계 공유 — 롤·FC 온라인 (C안)

작성: 2026-10-01. 상태: **계획**. 관련: [CK-LOCAL-DETECTOR.md](CK-LOCAL-DETECTOR.md)(롤 판별기) ·
[fco-match-context 스킬](../.claude/skills/fco-match-context/SKILL.md) · [MULTI-GAME-FCONLINE-PLAN.md](MULTI-GAME-FCONLINE-PLAN.md).

## 0. 한 줄

**화면을 보는 일(로컬 준비)은 하나로, 판단하는 일(스킬)은 게임별로 둘.**
한 VOD 의 썸네일은 한 번만 받고 한 번만 판별해 **롤·FC 가 함께 표시된 구간 지도**를 만든다.
롤 스킬(ck-local)과 FC 스킬(fco-match-context)은 그 지도를 각자 읽고, 각자의 규칙으로 판단한다.

## 1. 왜 C안인가

| | 롤 CK | FC 온라인 |
|---|---|---|
| 결과의 출처 | 화면뿐 — 사용자 설정 게임은 라이엇 API 에 없다 | **넥슨 API** — 승패·스코어를 이미 안다 |
| 경기가 언제였나 | 모른다 — 찾아야 한다 | **안다** — API 종료 시각 → VOD 초 |
| Claude 의 일 | 결과창을 찾아 **판독**(승패·이름·KDA·챔피언) | 그 경기와 같은 경기인지 대조하고 **맥락 판단**(친선·CK·대회) |
| 일의 단위 | VOD 하나(백필·자동 조사) | API 경기 하나(행사면 행사 묶음) |
| 남은 양 | 와치리스트 VOD 백필 | 스트리머 간 FC 경기 642개 중 620개 맥락 미조사(2026-10-01) |

- **한 스킬로 합치지 않는다(A안 기각)**: 목적·종료 조건·기록 창구(`ck:merge` vs `fco:context apply`)가 다르다.
  한 문서에 넣으면 두 규칙을 오가며 판단이 흐려진다 — ck-local 을 단순하게 만든 이유와 같다.
- **완전히 따로 두지도 않는다(B안 기각)**: 와치리스트 VOD 에 롤과 FC 가 섞여 있다(클리드1 9월 대부분).
  지금은 롤 조사가 썸네일을 다 받고 판별까지 하고도 FC 구간을 "롤 아님"으로 버리고, FC 조사가 같은 VOD 를 다시 연다.
  롤 조사 중 본 FC 는 `fco:context clue` 로 손으로 한 줄씩 남긴다.

## 2. 합치는 곳과 갈라지는 곳

```
                ┌───────────────── 공유 (로컬, DB 에 안 씀) ─────────────────┐
 VOD 번호 ──▶ │ ① 썸네일 시트 받기 (vod-timeline.mjs, 3초 칸)                   │
               │ ② 판별: 결과창 후보(롤) + 화면 종류 라벨(롤 + FC)              │
               │ ③ 산출물: out/ck/<vod>/local/  scan.json · map.txt · 몽타주    │
               └───────────────────────────────┬──────────────────────────────┘
                                                │  ← 여기서 갈라진다 (같은 파일을 읽는 두 소비자)
                     ┌──────────────────────────┴──────────────────────────┐
           롤 스킬 (ck-local)                                    FC 스킬 (fco-match-context)
   일의 시작: 백필·자동 조사가 VOD 를 고른다          일의 시작: fco:context list 가 API 경기를 고른다
   지도의 롤 구간 → 후보 → 원본 판독                  API 종료 시각 → 지도의 FC 구간·FC 결과 화면 → 원본 대조
   기록: ck:merge (경기·후보·scan)                    기록: fco:context apply (맥락·근거)
```

- **합치는 곳**: ①~③. 같은 VOD 면 어느 스킬이 먼저 부르든 한 번만 만든다(이미 있으면 재사용 — `scan.json` 의 run_id).
- **갈라지는 곳**: ③의 산출물을 **읽는 순간**. 두 스킬은 서로를 부르지 않는다. 같은 파일을 각자 읽을 뿐이다.
- **판단은 공유하지 않는다**: 로컬은 라벨만 단다. 롤 판독도 FC 맥락도 각 스킬의 Claude 가 원본을 보고 한다.

## 3. 바뀌는 것

### 공유 준비 (scripts/ck-local/)
- 화면 종류 라벨에 FC 3종 추가: `fc_match`(경기 중 — 잔디·스코어·시간) · `fc_result`(경기 종료 결과 화면) · `fc_menu`(스쿼드·이적시장·상점 등).
  롤 쪽 `other` 에 섞여 있던 것을 나눈다.
- 구간 지도에 FC 구간을 같이 싣는다. FC 결과 화면은 칸 단위로(경기마다 한 번, 짧다).
  ```
  0:17:50~1:12:05 FC 경기 중 (결과 화면 0:29:10 · 0:41:55 · 0:55:02 …)
  1:12:53~1:47:41 게임 중
  3:14:26~3:14:35 결과창(그래프) (후보 #1)
  ```
- 준비 명령은 그대로 하나: `npm run ck:local -- --vod N` (이름은 실험이 끝나면 정리).

### 롤 스킬 (ck-local) — 거의 그대로
- FC 구간은 지금처럼 롤 조사 대상이 아니다.
- **`fco:context clue` 손 기록을 없앤다** — 지도가 FC 구간을 이미 남긴다. (LoL 조사 중 FC 단서의 목적이 "FC 조사 후보 알림"이었는데 지도가 그 역할을 한다.)

### FC 스킬 (fco-match-context) — 찾는 부분만 바뀐다
- `locate` 가 API 종료 시각으로 VOD 초를 계산하는 것은 그대로.
- 그 VOD 에 준비 산출물이 없으면 만든다(`ck:local -- --vod N`), 있으면 재사용.
- 지금: 종료 −20초~+60초를 원본 5분할로 좁혀 결과 화면을 찾는다.
  바뀐 뒤: **지도의 `fc_result` 칸 중 API 종료 시각에 가장 가까운 것**의 원본을 바로 연다. 없으면 지금 방식(5분할).
- 지도에서 **FC 경기가 이어진 묶음**(같은 두 사람·한 저녁)이 보인다 → 맥락(친선·CK·대회)은 묶음의 시작(대기실·대진·공지)과 끝을 보고 판단하고,
  묶음 안 경기마다 결과 화면으로 matchId 대조. 기록은 지금처럼 경기마다(`apply`).
- 판단 규칙·기록 형식·검수 화면은 그대로다.

## 4. 순서

| 단계 | 내용 | 확인 |
|---|---|---|
| 1 | FC 라벨 데이터: 받아 둔 썸네일(클리드1 9월 VOD 대부분이 FC)에서 검수 + FC 근거 사진(DB 약 360장, role=result/end/start)으로 초벌 | 칸 수 |
| 2 | 종류 판별기에 FC 3종 추가 학습 | 스트리머 하나씩 빼고 — 전체 재현율·부여율·정확도. **롤 라벨 성능이 떨어지지 않는지** |
| 3 | 지도에 FC 구간 표시 | 클리드1 VOD 몇 개 지도를 눈으로 대조 |
| 4 | 롤 스킬에서 FC 손 기록 제거 | 롤 백필 1~2개로 회귀 확인 |
| 5 | FC 스킬에 지도 연결 | 이미 결론 난 FC 행사 경기 20개를 다시 조사(dry-run) → 같은 결론·같은 결과 화면인지, 원본 몇 장·토큰 얼마나 |
| 6 | FC 미조사 경기 일부로 실제 운영 | 경기당 비용, 묶음 판단이 실제로 쓰였는지 |

## 5. 위험

- FC 라벨을 넣다 롤 라벨이 나빠질 수 있다 → 2단계에서 롤 지표를 같이 보고, 나빠지면 FC 를 별도 판별기로 분리한다.
- FC 결과 화면은 짧다(수 초) → 3초 칸에 1~2번만 찍힐 수 있다. 못 찾으면 지금 방식(5분할)으로 — 판별기가 못 찾은 것은 "없음"의 근거가 아니다.
- 묶음 판단이 "같은 저녁이면 같은 행사"로 굳으면 안 된다(행사 중간 연습 경기 등) → 묶음은 **어디를 볼지**일 뿐, 경기마다 결론은 근거로.
- 남의 방송 시청(FC 중계)도 `fc_match` 로 보인다 → 화면 종류일 뿐, 본인 경기인지는 FC 스킬이 판단(지금 규칙 그대로).
