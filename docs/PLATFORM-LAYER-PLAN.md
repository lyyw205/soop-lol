# 플랫폼 층(로비) — 구현 계획

작성: 2026-10-02 · 상태: **1단계 완료**(2026-10-02), 2단계부터 남음 · 결정: 롤을 `/lol` 로 옮기고 `/` 를 SOOP 전체 로비로 쓴다

## 왜

지금 사이트는 **게임별 사이트 두 개**다. `/` 가 롤, `/fc` 가 FC 이고, 모듈은 `module.json` 의 `game`
한 칸으로 **정확히 한 사이트**에만 붙는다. 게임과 무관한 공용 공간이 없다.

곧 들어올 두 기능이 둘 다 공용 공간을 필요로 한다.
- **편성표**([SCHEDULE-PLAN.md](SCHEDULE-PLAN.md)): 여러 게임 일정을 한 장에 보여준다
- **커뮤니티**: 게임과 무관하게 글을 쓴다

목표는 "숲 플랫폼의 여러 카테고리를 아우르는 화면"과 "상대전적처럼 게임 하나를 깊게 보는 화면"을 함께 두는 것이다.
배포(M4) 전이라 지금 주소를 옮기는 비용이 가장 싸다. 배포 후에 옮기면 리다이렉트와 검색 색인 문제가 따라온다.

## 층 나누기

| 층 | 기준 | 기능 |
|---|---|---|
| **플랫폼** | 사람·시간. 게임은 필터일 뿐 | 로비 홈, 편성표, 커뮤니티, (나중) 통합 프로필 |
| **게임** | 게임 규칙. 게임마다 계산이 다름 | 전적 검색, 프로필, 스트리머 목록, 상대전적, 대회, 리더보드 |

판단 기준: **게임마다 계산 규칙이 달라지면 게임 층, 게임이 속성이면 플랫폼 층.**
스트리머 목록(`/streamers`)은 티어·우승 수 같은 롤 기록을 보여주므로 지금은 게임 층이다.

## 주소

| 지금 | 바뀐 뒤 |
|---|---|
| `/` (롤 홈 = 상대전적 검색) | `/` **로비** · 롤 홈은 `/lol` |
| `/s/[slug]` | `/lol/s/[slug]` |
| `/streamers` | `/lol/streamers` |
| `/m/versus` | `/lol/versus` (`/m/` 접두사는 옛 흔적이라 이번에 정리) |
| `/tournaments`, `/tournaments/[slug]` | `/lol/tournaments`, `/lol/tournaments/[slug]` |
| `/fc/...` | 그대로 |
| — | `/schedule` (편성표), `/community` (커뮤니티) |
| `/admin/...` | 그대로 |

리다이렉트는 두지 않는다. 배포 전이라 바깥에서 들어오는 옛 주소가 없다.

## 화면 틀(머리말)

틀은 세 개이고, 모두 같은 머리말 부품을 쓴다.

```
[S SOOP ▾전체 ]  편성표 · 커뮤니티                    ← 로비 (/, /schedule, /community)
[S SOOP ▾LOL  ]  전적 검색 · 상대전적 · 대회 · 스트리머 │ 편성표 · 커뮤니티   ← /lol
[S SOOP ▾FC   ]  전적 검색 · 대회 · 리더보드          │ 편성표 · 커뮤니티   ← /fc
```

- **게임 전환 메뉴는 전체 / LOL / FC 세 칸**이 된다
- 게임 사이트 머리말 끝에도 **플랫폼 메뉴(편성표·커뮤니티)**를 둔다. 롤 안에서 편성표를 누르면
  `/schedule?game=lol` 로 간다. 롤 필터가 걸린 채로 로비 층으로 나가는 것이다
- 로비 홈(`/`) 처음 내용: 게임 입구 카드(LOL·FC)와 집계 숫자. 편성표가 생기면 "오늘·이번 주 편성",
  커뮤니티가 생기면 "새 글"이 여기에 붙는다

## 모듈 규칙 변경

1. **`module.json` 의 `game` 에 `"platform"` 을 추가한다.** 플랫폼 모듈은 로비 틀 안에서 뜬다.
   기본값은 지금처럼 `lol` 이라 기존 모듈 manifest 는 `routes` 경로만 고친다.
2. **마운트 지점이 셋이 된다.**
   - `app/[...path]` → 플랫폼 모듈
   - `app/lol/[...path]` (새로 만듦) → 롤 모듈
   - `app/fc/[...path]` → FC 모듈 (그대로)
   - 롤 틀은 `app/lol/layout.tsx` 가 씌운다. FC 의 `app/fc/layout.tsx` 와 같은 모양이다
3. **게임 사이트 메뉴에 플랫폼 모듈의 메뉴가 같이 뜬다.** 등록부의 `moduleNavRoutes(game)` 가
   그 게임 모듈과 플랫폼 모듈을 함께 돌려준다. 순서는 게임 메뉴 뒤에 구분선을 두고 플랫폼 메뉴를 붙인다
4. **플랫폼 모듈 화면은 `searchParams.game` 으로 게임 문맥을 받는다.** 주소 자체는 하나다

## 근본 수정: 주소를 한 곳에서만 만든다

롤 경로가 문자열로 박힌 곳이 **약 40곳**이다(빌드 산출물 제외). 그중 상당수가 **모듈 안**에 있다.
- `tournaments/ui/tournament-detail.tsx` 에서 `/s/${slug}` 를 7번 쓴다
- `versus/ui` 에서 `/m/versus`, `/s/` 를 쓴다
- 공용 UI(`packages/ui/record-sidebar.tsx`, `match-details.tsx`)에서 `/s/` 를 쓴다

이대로 주소만 옮기면 40곳을 고치게 되고, 다음에 주소를 바꿀 때 같은 일이 또 생긴다.
모듈이 core 주소(`/s/`)를 알고 있는 것은 "모듈은 주소를 모른다"는 원칙과도 어긋난다.

**고치는 방법**
- core 화면 주소를 만드는 함수를 한 파일에 모은다: `profileHref(game, slug, query?)`,
  `streamersHref(game)`, `gameHomeHref(game)`. 계약(`core/lib/contract`)으로 내보내서
  웹·모듈·공용 UI 가 모두 이 함수만 쓴다
- 자기 모듈 안의 주소(대회 목록 ↔ 대회 상세 등)는 **`module.json` 에 적은 경로에서** 만든다.
  모듈 코드에 자기 주소를 또 박지 않는다
- `verify:modules` 에 검사를 추가한다: **모듈과 공용 UI 안에 core 주소 문자열(`"/s/"`, `"/lol/"`,
  `"/fc/s/"` 등)이 있으면 실패**. 문서로만 적어 두면 다시 박힌다

이렇게 하면 이번 이동이 "함수 정의 몇 줄 + 라우트 폴더 이동"으로 줄고, 다음 이동도 같다.

## 순서

각 단계가 끝날 때마다 `npm test`, `verify:modules`, 화면 확인을 통과시키고 커밋한다.

| 단계 | 내용 | 주소 변화 |
|---|---|---|
| 1. 주소 모으기 ✅ | 주소 함수 도입, 40곳 교체, `verify:modules` 금지 검사 추가. 수정 전후 서버로 19개 화면의 링크 약 2,800개·메뉴 표시가 같음을 확인 | **없음** (동작 그대로) |
| 2. 롤 이동 | `app/lol/` 로 라우트 이동, `app/lol/layout.tsx`, 롤 모듈 manifest 경로를 `/lol/...` 로, `/m/versus` → `/lol/versus` | 롤 주소 전부 |
| 3. 로비 | `game: "platform"`, 플랫폼 마운트, 로비 틀·홈, 게임 전환 3칸, 게임 머리말에 플랫폼 메뉴 | `/` 가 로비 |
| 4. 편성표 | [SCHEDULE-PLAN.md](SCHEDULE-PLAN.md) 1단계를 플랫폼 모듈로 | `/schedule` |
| 5. 커뮤니티 | 별도 계획서 | `/community` |

1단계는 주소를 바꾸지 않는다. 고친 게 맞는지를 "화면이 그대로인가"로 확인할 수 있게 나눈 것이다.
2단계는 1단계 덕분에 거의 기계적인 작업이 된다.
