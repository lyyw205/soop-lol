## 왜

지금 사이트는 **게임별 사이트 두 개**다. `/` 가 롤, `/fc` 가 FC 이고, 모듈은 `module.json` 의 `game`
한 칸으로 **정확히 한 사이트**에만 붙는다. 게임과 무관한 공용 공간이 없다.

곧 들어올 두 기능이 둘 다 공용 공간을 필요로 한다.
- **편성표**([SCHEDULE-PLAN.md](SCHEDULE-PLAN.md)): 여러 게임 일정을 한 장에 보여준다
- **커뮤니티**: 게임과 무관하게 글을 쓴다

배포(M4) 전이라 지금 주소를 옮기는 비용이 가장 싸다.

## 결정된 것

### 층 나누기

| 층 | 기준 | 기능 |
|---|---|---|
| **플랫폼** | 사람·시간. 게임은 필터일 뿐 | 로비 홈, 편성표, 커뮤니티, (나중) 통합 프로필 |
| **게임** | 게임 규칙. 게임마다 계산이 다름 | 전적 검색, 프로필, 스트리머 목록, 상대전적, 대회, 리더보드 |

판단 기준: **게임마다 계산 규칙이 달라지면 게임 층, 게임이 속성이면 플랫폼 층.**
스트리머 목록은 티어·우승 수 같은 롤 기록을 보여주므로 게임 층이다.

**공간과 게임 종류는 다른 축이다.** 편성표 모듈은 플랫폼 공간에 속하지만, 그 안의 일정 하나하나는
`game_code`(`lol`·`fconline`)를 가진다. `platform` 은 공간 이름일 뿐이고 **경기·일정 데이터의 게임 값이 되지 않는다.**

### 주소

| 지금 | 바뀐 뒤 |
|---|---|
| `/` (롤 홈 = 상대전적 검색) | `/` **로비** · 롤 홈은 `/lol` |
| `/s/[slug]` | `/lol/s/[slug]` |
| `/streamers` | `/lol/streamers` |
| `/m/versus` | `/lol/versus` (`/m/` 접두사는 옛 흔적이라 이번에 정리) |
| `/tournaments`, `/tournaments/[slug]` | `/lol/tournaments`, `/lol/tournaments/[slug]` |
| `/fc/...` | 그대로 |
| — | `/schedule` (편성표), `/community` (커뮤니티) |
| `/admin/...` | 그대로 |

**옛 주소는 404 가 된다. 리다이렉트를 두지 않는다.** 배포 전이라 바깥에서 들어오는 옛 주소가 없다.
배포 후 주소를 다시 옮기게 되면 그때는 리다이렉트가 필수다.

### 화면 틀(머리말)

틀은 세 개이고, 모두 같은 머리말 부품을 쓴다.

```
[S SOOP ▾전체 ]  편성표 · 커뮤니티                                  ← 로비 (/, /schedule, /community)
[S SOOP ▾LOL  ]  전적 검색 · 대회 · 스트리머 │ 편성표 · 커뮤니티      ← /lol
[S SOOP ▾FC   ]  전적 검색 · 대회 · 리더보드 │ 편성표 · 커뮤니티      ← /fc
```

- 게임 전환 메뉴는 **전체 / LOL / FC** 세 칸이다
- 게임 사이트 머리말 끝에 플랫폼 메뉴를 둔다. 롤 안에서 편성표를 누르면 `/schedule?game=lol` 로 간다
- 관리자 화면은 자기 틀(`AdminShell`)만 쓴다. 공개 머리말이 겹치지 않아야 한다

### 로비 내용 (2단계에서 만드는 최소 로비)

- 게임 입구 카드 두 장(LOL·FC). 카드마다 **그 게임의** 숫자만 쓴다
  - LOL: 공개 경기 수·조우 수(지금 `countPublic` 의 경기·조우 — 롤 전용 뷰에서 센다)
  - FC: 공개 FC 경기 수·FC 기록이 있는 스트리머 수
- 카드 밖 숫자는 **등록 스트리머 수 하나**: `core_public.streamer` 의 행 수 = 숨기지 않은 **사람 수**(게임별 인원의 합이 아니다)
- 게임 합계 경기 수는 쓰지 않는다. 게임마다 "경기"의 단위가 달라(롤 세트 ↔ FC 한 판) 더하면 뜻이 없다
- 편성표가 생기면 "이번 주 편성", 커뮤니티가 생기면 "새 글"이 붙는다

### 모듈 규칙

1. **`module.json` 에 `site` 칸을 둔다**: `"platform" | "lol" | "fconline"`. 모듈이 **어느 공간의 틀 안에서 뜨는가**다.
   지금의 `game` 칸을 이름만 바꾼 것이다(값 `lol`·`fconline` 은 그대로). 기존 manifest 3개(FC 모듈)를 고친다
2. **마운트 지점이 셋이 된다.**
   - `app/[...path]` → 플랫폼 모듈 (로비 틀)
   - `app/lol/[...path]` (새로 만듦) → 롤 모듈. 롤 틀은 `app/lol/layout.tsx` 가 씌운다(FC 와 같은 모양)
   - `app/fc/[...path]` → FC 모듈 (그대로)
3. **게임 사이트 메뉴 끝에 플랫폼 모듈 메뉴가 붙는다.** 등록부의 메뉴 함수가 그 사이트 모듈 + 플랫폼 모듈을 함께 돌려준다
4. **플랫폼 모듈 화면은 `searchParams.game` 으로 게임 문맥을 받는다.** 주소는 하나다
5. **주소는 함수로만 만든다**(1단계에서 완료): core 화면은 `profileHref` 등, 모듈 자기 화면은 `module.json` 의 routes 로.
   모듈·공용 UI 에 주소 글자가 있으면 `verify:modules` 실패

## 1단계 — 주소 모으기 (검증 완료)

- `core/lib/site-paths.ts` 에 주소 함수. 웹·공용 UI·모듈의 박힌 주소 약 40곳을 교체
- 모듈 자기 주소는 `ui/paths.ts` 가 `module.json` 에서 만든다. host `roleHref` 도 같은 `routeHref`
- `verify:modules`
  - 모듈·공용 UI 의 `/` 로 시작하는 문자열 금지. **`"/"` 하나도 주소로 본다**
  - 예외는 `apps/web/public` 의 **실제 맨 위 폴더·파일**(`/images/…` 등)뿐이다. 손으로 적은 목록이 아니다
  - 한 모듈 안에서 **파라미터 조합이 같은 경로가 둘이면 실패**(`routeHref` 가 첫 번째를 조용히 고르는 모호성)
  - 자체 검사(selftest)에 위반 사례(템플릿 주소·자기 주소·`"/"`·public 에 없는 `/icons/…`·경로 모호성)와 정상 사례(`/images/…`)
- 함께 고친 core 버그: `fromKstInputValue` 가 없는 날짜(`2026-02-30`·`25:00`)를 다음 달·다음 날로 넘겨 저장하던 것 → `null`
- **검증**: 수정 전/후 코드로 서버 두 개를 띄워 19개 화면의 상태 코드·링크 약 2,800개(쿼리 포함)·활성 메뉴가 같음을 확인.
  `npm test`, `typecheck`, `verify:modules`(selftest 포함) 통과
- **검증하지 못한 것**: 검색창 제출(클라이언트에서 주소를 만들어 이동)은 HTML 링크 비교에 안 잡힌다. 코드상 같은 주소를 만들지만
  브라우저로는 확인하지 않았다 → 2단계 브라우저 검증에 넣는다

## 2단계 — 롤 이동 + 최소 로비 (검증 완료)

한 커밋으로 끝낸다. 중간에 `/` 가 비는 상태를 두지 않는다.

1. `GAME_BASE.lol` 을 `"/lol"` 로. 롤 라우트(`page.tsx`·`s/[slug]`·`streamers`)를 `app/lol/` 아래로, `app/lol/layout.tsx`·`app/lol/[...path]`
2. 롤 모듈 manifest 경로: `/lol/tournaments…`, `/lol/versus`
3. `site` 칸 도입(등록부 생성기·FC manifest 3개·마운트 두 곳)
4. 로비: `app/page.tsx`(로비 홈), 로비 틀, 게임 전환 3칸, 게임 머리말의 플랫폼 메뉴 자리(플랫폼 모듈이 없으면 안 그린다)
5. 루트 `layout.tsx` 제목·설명을 플랫폼 이름으로. 롤·FC 레이아웃은 각자 제목 템플릿을 갖는다

**완료 전에 확인할 것**

| 항목 | 방법 |
|---|---|
| 새 주소 직접 접속·새로고침 | 롤·FC·로비 주요 화면 상태 코드 200 |
| 옛 주소 | `/s/…`·`/streamers`·`/m/versus`·`/tournaments` 가 404 (결정대로) |
| 내부 링크 | 1단계와 같은 방식으로 링크 전수 수집 → 모든 내부 링크가 200 |
| 머리말 | 로비·롤·FC 각 1개, 관리자 화면에는 공개 머리말 없음 |
| 제목·메타데이터 | 화면별 `<title>` 이 해당 공간 이름을 쓴다 |
| 활성 메뉴 | 화면별 `aria-current` 가 기대값과 같다 |
| 검색창 제출 | 브라우저(Playwright)로 개인 기록·상대전적 검색 → 새 주소로 이동 |
| 모듈 제거 | `verify:modules` selftest(모듈 하나씩·전부 제거 후 통과·컴파일) |
| 기존 검증 | `npm test`, `typecheck`, `verify:modules`, `scripts/lib/verify-unknown-browser.ts` |

### 2단계 검증 결과 (2026-10-02)

- 13개 화면: 상태 200 · 공개 머리말 정확히 1개 · 제목 · 머리말의 켜진 메뉴가 기대값과 같음
  - 로비 "SOOP — 스트리머 기록실" · 롤 "… · SOOP LOL" · FC "… · SOOP FC 온라인"
  - 롤 상대전적 화면 제목은 "SOOP LOL — 스트리머 롤 전적" 이다. 상대전적 모듈이 제목을 정하지 않아서이고, 이동 전(`/m/versus`)과 같다
- 옛 주소 5개(`/s/…`·`/streamers`·`/m/versus`·`/tournaments`·`/tournaments/…`) → 404 (결정대로)
- 관리자 화면(`/admin`)에 공개 머리말 없음
- 위 화면들의 내부 링크 1,069개 중 261개(프로필 링크 848개 중 40개 + 나머지 전부)를 하나씩 요청 → 모두 200
- 검색창 제출(브라우저): 롤 개인 기록 → `/lol/s/…`, 롤 상대전적 → `/lol/versus?a=&b=`, FC 개인 기록 → `/fc/s/…`
- `npm test` 246 · `typecheck` · `verify:modules`(selftest 53, 모듈 하나씩·전부 제거 후 컴파일 포함) 통과
- 레이아웃 기본 제목에도 부모 템플릿이 씌워진다 — 게임 공간 기본 제목은 `absolute` 로 둔다(안 그러면 "… · SOOP" 이 한 번 더 붙는다)

**검증하지 못한 것 / 관측한 것**
- `scripts/lib/verify-unknown-browser.ts` 는 돌리지 않았다(주소 한 줄만 함수로 바꿨다)
- 모듈 제거 후의 **실행 중 메뉴**는 화면으로 보지 않았다. 컴파일·경계 검사만 selftest 가 본다
- 링크 검사를 **동시 3개씩** 보냈을 때 프로필 화면이 2분 넘게 응답하지 않았고, `/lol/s/leesangho?opponent=kimmingyo` 가
  한 번 500(`malformed array literal`)이었다. 하나씩 보내면 모두 200 이다. 이번 변경과 무관한 기존 동시성 문제로 보이며
  (프로필 화면의 질의 팬아웃 — docs/PLAN.md §M4-1), **원인은 확인하지 않았다.** M4-1 에 관측 기록을 남겼다
