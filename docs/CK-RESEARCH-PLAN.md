# CK 조사 스킬 재설계 계획 — 프레임 우선, 판단은 조사자에게

작성: 2026-09-22, 갱신: 2026-09-27. 구현된 조사 계약과 후속 설계 판단을 함께 기록한다.

## 1. 목적과 채택 방향

화이트리스트 방송 VOD에서 스트리머 간 롤 경기를 찾아, 근거와 함께 DB에 기록한다.
저장한 경기는 기본 공개하며 운영자는 어드민에서 사후 수정·제외한다. 초안 승인이나
조사 종료 도장은 만들지 않는다. 나무위키 대회 시드 수집은 별도 워크플로우로 유지한다.

**필수로 정할 것은 수행과 기록이다. 그 자료의 의미, 결론, 추가 조사 방법은 LLM이 판단한다.**

- 기본 경로: 이전 기록 조회 → 미확인 범위 탐색 → 판별 추적·즉시 기록 → 시리즈 교차검증·통합 → 확인된 구간 재사용.
- SenseVoiceSmall은 선택 구간 전사의 기본 도구다. 전체 음성 전사는 시각 탐색을 보완하는 선택지다.
- Qwen3-ASR 0.6B는 필요한 구간을 다시 읽는 선택지다. 모든 구간을 두 모델로 돌리지 않는다.
- 30분 간격은 초기 탐색의 기본값이다. 짧은 경기·잔여 구간은 격자 사이에 있을 수 있다. 걸린 자리부터 좁혀 간다. 경기 유무나 조사 완료를 결정하는 판정 규칙이 아니다.

채택 근거: VOD `207602969`의 동일한 약 30분 표본에서 SenseVoice 순수 전사는 7.5초,
로딩 포함 52.7초였다. Qwen은 각각 332.5초, 364.2초였다(RTX 2070 8GB).
이 VOD에는 오디오 전용 렌디션이 없어 표본 확보에 HLS 약 298MB를 받았다.
음성 전사의 계산보다 음성 확보 비용을 줄이는 것이 기본 경로 선택의 이유다.
두 탐색 방식의 누락률과 전사 정확도를 검증한 결과는 아니며, 다른 VOD에도 같은 비용을 가정하지 않는다.

## 2. 반드시 수행하는 일과 자율 판단의 경계

**판단의 자율과 수행의 생략은 다르다.** 요청 범위와 발견한 후보를 방치하지 않고 실제 수행과
근거를 기록하는 것은 필수다. 방법·순서·자료 해석은 조사자가 정한다. 확인에 실패할 수는 있어도
미수행을 완료로 기록해서는 안 된다. 기존 근거 재사용은 범위와 출처를 남기는 정당한 수행이다.

| 자리 | 반드시 수행·기록할 행동 | LLM이 결정할 것 |
|---|---|---|
| 대상·범위 | VOD·이전 기록 조회, 요청 범위를 조사·재사용·미확인으로 빠짐없이 처리 | 순서·간격·추가 탐색 위치 |
| 발견한 경기 | 대상 여부와 근거 기록, 대상 판의 경계·결과 추적 | 맥락·경계·판 구성 해석 |
| 중복 | 깊은 조사·신규 경기 생성 전 조회, 재사용 구간·경기·근거 연결 | 같은 판인지, 근거가 충분한지 |
| 교차검증 | 시리즈별 다른 시점 대조, 공백·충돌 처리와 확보 불가 사유 기록 | 시점·자료·조사 깊이·우선순위 |
| 통합 | 출처·상충 관찰 보존, 같은 판은 같은 경기 ID에 연결 | 사람·팀·시리즈 매핑, 값 채택 또는 미해결 |
| 종료 | 종료 사유·남은 범위·재개 지점·저장 응답 기록 | 근거에 해당하는 종료 상태와 다음 조사 순서 |

30분·5분할·2~3초 마무리는 기본 전략이다. 횟수로 경기 유무·정확성·완료를 판정하지 않는다.
사용자에게 의미 판단을 매번 묻지 않고 근거와 함께 처리한다. DB 제약을 통과하려고 없는
사람 ID·승패·KDA를 만들어 넣지 않는다. 현재 계약으로 표현할 수 없으면 후보·근거에 남긴다.

## 3. 실행 파이프라인과 전환 기준

| 단계 | 수행 | 다음 단계로 넘어가는 판단 |
|---|---|---|
| 1. 대상·이전 기록 | VOD·방송 시간축·이전 실행·기존 경기 조회 | 중단이면 재개, 알려진 경기면 재사용 가능 범위와 공백 확인 |
| 2. 미확인 범위 | 재사용하지 못한 범위에 대표 화면을 두고 실제로 열람 | 롤 화면이면 맥락 확인, 아니면 관찰 범위 기록 |
| 3. 맥락 | 모드·화면·채팅 등 필요한 자료 확인 | 대상이면 판 추적, 대상 밖이면 해당 구간만 제외, 불명확하면 추가 조사·미해결 |
| 4. 판·시리즈 | 판별 경계·순서·시리즈 관계 조사 또는 기존 경계 재사용 | 확인된 판은 결과 탐색, 잘린 경계는 확인 불가 기록, 잔여 수행은 재개 대상 |
| 5. 결과 | 결과창 탐색, 읽힌 값과 근거 즉시 반영 | 결과창 열람·다른 시점 확보·미발견·확인 불가 중 종료 사유 기록 |
| 6. 다른 시점 | 기존 경기도 처음부터 읽고 직접 읽은 칸만 `match` 로 제출, 저장 도구가 비교·빈 칸 채우기·불일치 표시([다시점 계획](CK-MULTI-POV-PLAN.md)) | 근거 부족·충돌이면 다른 시점(와치리스트 밖 포함), 신원은 어드민 미확인 참가자 |
| 7. 구간 재사용 | 이후 시점에서 같은 판임과 시간축을 확인하고 검증된 판별 구간 재사용 | 공백 및 경기 사이·시리즈 전후 미확인 범위는 다시 탐색 |
| 8. 마무리 | 저장 결과·근거 연결 확인, 현재 결론·잔여 범위·재개 지점 기록 | 필수 수행 종료면 done, 수행이 남으면 running, 실행 실패는 원인·범위 기록 |

새 단서가 나오면 이전 단계로 돌아간다. 첫 경기부터 즉시 반영해 같은 실행의 다음 VOD가
최신 기록을 조회할 수 있게 한다. 교차검증이나 시리즈 전체 완료를 저장·공개의 선행 조건으로 삼지 않는다.

### A. 대상·시간축·범위

- watchlist 또는 직접 받은 VOD를 조사한다. 제목·카테고리로 혼합 방송을 제외하지 않는다.
- 채널의 `vod_availability`는 우선순위 힌트다. 목록 조회를 끄거나 VOD 부재를 불참으로 판단하지 않는다.
- 정규화한 VOD 키와 `ck:record`로 이전 기록을 조회한다. lead 행 존재를 조사 완료로 간주하지 않는다.
- 훑기 전에 `ck:merge --find-match --vod <번호>`로 방송 주인이 참가자로 기록된 경기의 VOD 어림 구간·
  이 사람의 팀·챔피언·화면 빈칸을 본다. date 정밀도 경기는 구간을 내지 않는다. 새 후보는 근사 시각
  `--find-match <시각>`으로 조회한다.
- 분할 파일은 VOD 전체 초로 대응시킨다. 다른 VOD의 오프셋끼리 직접 비교하지 않는다.
  API/HLS 길이 불일치·누락으로 연속성이 불확실하면 절대시각 투영을 생략 근거로 사용하지 않는다.
- 경기 시작 절대시각은 확인된 방송 시작과 검증된 시간축의 경기 시작 오프셋으로 계산할 수 있다.
  이때 `played_at_precision: datetime`을 쓴다. 결과창 시각을 경기 시작으로 저장하지 않는다.
  날짜만 확실하면 `date`로 남긴다. 구간 생략에는 종료 경계 또는 확인된 길이도 필요하다.
- 기본 30분 샘플 외에 시작·끝·짧은 꼬리·재사용 구간 사이의 잔여 범위도 처리한다.
  픽셀 거름망은 추가 단서이며 기본 탐색을 대체하지 않는다. 대표 샘플을 전 프레임 열람으로 표현하지 않는다.

### B. 판별 추적과 탐색 종료

- 롤 화면을 보면 맥락을 확인한다. 시청·중계라는 이유만으로 기각하지 않는다. 방송 주인의
  참가 여부와 화면 속 경기의 수집 대상 여부는 별개다. 유효한 결과창은 시청 화면에서도 채택할 수 있다.
- 대상 판의 경계·순서를 조사한다. `--divide 5`는 기본 방법이며 정확한 단서로 바로 이동할 수 있다.
  확인된 경계는 같은 판임과 시간축을 확인한 후 재사용한다. VOD 시작·끝에 잘린 경계는 한계를 기록한다.
- 결과창 탐색은 실제 열람, 다른 시점 근거 확보, 5분할 반복 후 마지막 조각을 기본 2~3초 간격으로
  소진한 미발견, VOD 누락·가림 등의 확인 불가 중 하나로 닫는다. 미발견은 그 간격에서의 관찰이며 간격을 기록한다.
- 탐색·좁히기·결과창 찾기로 뽑은 프레임은 전부 연다(2026-09-23 "뽑고 왜 안 읽냐"). 미열람을 읽음으로
  표시하거나 애매한 화면으로 미발견을 선언하지 않는다.
- 결과창 탐색 종료는 정보 확보 완료와 다르다. 부분 결과·미발견·확인 불가이면 교차검증에서 공백을 처리한다.
- 현재 결론은 경기 반영·기존 경기 연결·대상 아님·미해결로 남긴다. 넓은 후보를 나누면
  `supersedes`로 부모를 참조해 원본 이력을 보존한다. 한 linked 후보에는 한 판의 좁은 구간을 연결한다.

### C. 시리즈 교차검증·통합·재사용

- 추가로 들어온 시점도 정해진 조사 절차를 수행하고, 직접 읽은 값과 사진을 제출한다. 도구가 기존 값과 비교하고 빈칸을 채운다.
  추가 시점을 일률적으로 몇 개 찾지 않는다. 결과 근거가 부족하거나 자료가 충돌하면 도움이 될 다른 시점
  (와치리스트 밖 포함)을 찾고, 못 찾으면 시도와 한계를 기록한다(2026-09-27 에 같은 판을 여섯 번 팠다).
- 이후 시점도 경기를 처음부터 읽어 직접 읽은 칸만 제출하고, 같다·다르다는 저장 도구가 계산한다.
  "빠른 연결(참가 확인 한 장으로 닫기)"은 폐지했다 — 메모만 남고 사진·비교가 빠졌다([다시점 계획](CK-MULTI-POV-PLAN.md) §2).
- 같은 원본의 재송출을 독립적인 교차검증으로 세지 않는다.
- 공백·충돌별로 추가 조사·다른 시점 이관·확인 불가·후속 조사 중 방침과 이유를 남긴다.
  미수행 필수 작업을 후속 조사라는 말로 바꿔 done으로 내지 않는다. 다수결로 상충 값을 덮지 않는다.
- 같은 판은 같은 `match_id`, 같은 시리즈의 판은 같은 `series_id`로 통합한다. 출처 VOD·채널·오프셋,
  상충한 관찰과 채택 이유를 보존한다. 앞 판 로스터 자동 복사나 보너스 단판의 세트 편입은 하지 않는다.
- 미등록 인게임명(신원)은 다른 시점에서 채울 빈칸이 아니다 — `/admin/ck/unknown` 몫이다.
- 시점 하나여도 조사 완료와 검수가 가능하다. 다른 시점이 붙으면 저장 도구가 반드시 비교한다.
- 시리즈의 처음부터 끝까지 하나로 덮지 않는다. 경기 사이·시리즈 전후 미확인 범위와 보너스 단판을 조사한다.
- 연결·경계·근거가 교정되거나 새 충돌이 나오면 그 근거에 의존한 구간의 재사용 가능 여부를 재평가한다.

### D. 저장과 실행 마무리

- `ck:merge --result`가 단일 쓰기 창구다. 프레임 추출·전사는 로컬 산출물만 만든다.
- 첫 경기부터 누적 반영하고 곧바로 공개한다. 경기 ID·근거 연결·변경 응답을 확인한다.
  검수 보호·충돌로 반영되지 않은 것을 성공으로 세지 않는다.
- 필수 탐색·교차검증 처리는 끝났지만 승패·신원 등이 미해결이면 done일 수 있다.
  미수행 조사가 남으면 running으로 저장하고 남은 구간·질문·다음 행동을 기록한다.
- 자동 큐(`ck:queue`)는 와치리스트 채널의 `running`을 기간과 무관하게 합친다. done + failed 구간은
  기간 안에서만 재시도한다 — 영구 실패의 무한 재시도를 막는다. 영상 길이 밖처럼 원래 없는 구간은
  `scan.resolved_failed`로 닫는다.

## 4. 판단을 규칙으로 바꾸지 않는 방법

스킬은 아래 질문을 조사자에게 남기되 정답을 정하지 않는다.

- 이 화면은 플레이·재방송·중계 중 무엇이며, 어떤 경기의 근거로 쓸 수 있는가?
- 앞뒤 구간이 같은 경기인가, 추가 세트인가, 다른 팀 구성인가?
- 이 이름을 어느 사람에게 연결할 근거가 있는가? 더 확인하거나 미해결로 남길 부분은 무엇인가?
- 결과 화면, 오버레이, 음성의 차이는 시각 차이인가, 다른 판인가, 오독인가?
- 새로운 자료를 더 보면 이번 결론이 달라질 가능성이 있는가?

`CK-COLLECTION.md`의 실측 사례는 판단을 돕는 참고자료로 유지한다.
‘후보가 둘이면 제외’, ‘한 명과 정황 두 개면 확정’, ‘조회 0건이면 오독’, ‘중계면 기각’,
‘두 결과창의 로스터가 같으면 중간 판도 동일’ 같은 자동 결론은 새 스킬에 옮기지 않는다.
결과창 탭·줄 순서·진영·이름 잘림 등은 관찰상의 함정으로 설명하고 필요할 때 읽게 한다.

숫자 간격은 도구 기본값, 실패 이력은 참고, FK·타입·멱등성은 코드 계약이다.
이 셋을 경기 의미를 판정하는 규칙으로 섞지 않는다. 구현에서도 키워드나 픽셀 점수로
경기 확정·제외를 자동 실행하지 않는다.

## 5. 기록 계약 — 실행 사실과 조사 판단을 분리한다

새 조사 테이블을 늘리기보다 `event_lead.raw`와 `review_record`를 역할에 맞게 사용한다.
다음은 현재 기록 계약이다. `state`는 기존 단서 상태로 남기고 공개 승인에 쓰지 않는다.

| 기록 | 최소 내용 | 의미 |
|---|---|---|
| `raw.scan` | 버전, `running/done/failed`, 요청 범위, 예정/추가 탐색 지점, 확보·열람·실패 기록, 사용 신호 | 무엇을 수행했는지 |
| `raw.scan`의 범위 정보 | 대표 화면 샘플링 범위, 실제 연 프레임 시각, 실제 읽은 전사 구간을 구분 | 대표 샘플을 전체 영상 정밀 확인으로 오인하지 않게 함 |
| `raw.candidates` | 안정적인 후보 ID, 시각 범위, 관찰, 결론, 근거 참조, 연결 경기 ID 또는 미해결 내용 | 자료를 어떻게 해석했는지 |
| `match_evidence_frame` | lead ID, 해당 경기 ID(없을 수 있음), 경로, VOD 전체 초, 종류, 읽은 내용 | 어드민에서 다시 열 실제 화면 |
| `review_record(type='final_evidence')` | 결과 판단의 근거, 추정·상충·미확인 사항과 원본 시각 | 경기 단위 교정 근거의 정본 |

기본 탐색 전체의 열람 이력은 간결한 manifest로 보관하고 `raw.scan`에서 참조할 수 있다.
후보 결론에 사용한 프레임은 경기 생성 여부와 무관하게 근거 테이블에 남긴다.
후보가 아닌 구간도 탐색 manifest를 통해 재검수할 수 있어야 한다.
`lead_id`는 필수다. `match_id`가 없는 프레임은 누락 데이터가 아니라 미연결 근거다.

`done`은 필수 탐색·교차검증 처리를 수행하고 후보들의 현재 결론을 기록했다는 실행 상태다.
정보가 미해결이어도 실행은 마칠 수 있지만 미수행 작업은 `running`과 재개 지점에 남긴다.
실행 실패는 `failed`와 원인·범위를 기록한다. 영구적인 확인 불가를 미수행과 구분한다.
어드민은 ‘탐색 완료’, ‘발견 경기 수’, ‘미해결 후보 수’, ‘미확인 범위’를 분리해 표시한다.
**경기 행이 0개라는 이유만으로 ‘경기 없음’을 표시하지 않는다.** 그 결론은 조사자가 남긴다.

| `resultType` | 단일 입력 창구의 역할 |
|---|---|
| `scan` | 시작·중간·종료 실행 기록, 후보 결론, 미연결 근거 프레임을 병합한다. 실행 종료 전용이 아니다 |
| `match` | 경기·참가자·이벤트/팀 연결과 명시한 근거를 생성·보강한다 |
| `identify` | 기존 참가자의 사람 매핑과 그 근거를 보강한다 |

입력 파일은 운반·재시도용 산출물이며 승인 대기 초안이 아니다. 근거 메모는 자유 서술로 받는다.
정형 ‘확인 완료’ 문구, 점수, 특정 단어를 요구하지 않는다. 타입·키·참조·파일 존재·처리 응답은
기계적으로 검증하되, 메모 내용이 어떤 결론을 내려야 하는지는 검증기가 정하지 않는다.
열람 표시는 실제 열람 뒤에 기록하며 추출 도구가 자동으로 ‘읽음’을 붙이지 않는다.

## 6. 현재 구조에 맞춘 구현 범위

2026-09-22 작업 트리 기준이며, 파일의 존재와 실제 DB 적용·화면 검증 완료는 구분한다.

| 구성 | 현재와 필요한 작업 |
|---|---|
| DB | `0019`~`0025`와 `core/lib/db/ck.ts`에 근거 프레임·검수 기록·채널별 VOD 성향이 구현돼 있다. 결과 근거 정본은 `review_record.final_evidence`다 |
| 시각 탐색 | `soop-vod.mjs`의 목록·시트·HLS·추출 기능을 재사용한다. 전체 범위 대표 화면과 열람 manifest를 잇는 실행 도구가 필요하다 |
| 기존 거름망 | `scan-vod-frames.mjs`의 픽셀 신호는 유지한다. 롤 카테고리 필터, 15분 구간 필터, 후보 상한을 새 탐색의 누락 없는 범위 조건으로 사용하지 않는다 |
| ASR | `scripts/asr/`에 로컬 모델·표본 추출·전사·재개 도구가 있다. 후보 구간 입력과 분할 파일 경계 처리를 연결한다 |
| 입력 창구 | `ck-merge.mjs --result`가 쓰기의 유일한 창구다. `--find-match`는 로스터·판독 공백·결과 근거·남은 질문을 조회한다 |
| 어드민 | `/admin/ck` 목록·타임라인·수정 화면을 구현한다. 현재 `apps/web/proxy.ts`의 `/admin` 인증 보호를 유지한다 |
| 기존 오케스트레이션 | 새 경로가 검증된 뒤 `ck:collect`·`ck:prep`의 VOD 조사 역할을 대체한다(2026-10-01 `ck:prep`·`ck:seen` 삭제). 다른 출처의 단서 수집 기능까지 일괄 삭제하지 않는다 |

DB·저장 경로에는 다음 데이터 계약을 둔다. 이는 LLM의 경기 판독 규칙이 아니다.

- 동일 결과 재전송은 경기·참가자·프레임을 중복 생성하지 않는다. 후보·경기 ID를 재실행에 재사용한다.
- 다른 VOD에서 같은 경기를 발견하면 LLM이 기존 경기를 조회·선택할 수 있어야 한다.
  VOD 번호만으로 경기 ID를 새로 만드는 방식은 피한다. 한 VOD와 한 이벤트를 일대일로 강제하지 않는다.
- 검수 수정과 `hidden` 처리는 자동 재수집이 덮지 않는다. 동시 저장도 이 보호를 우회하지 못하게 한다.
- 변경 전후 영향 범위의 `streamer_encounter`와 `champion_stat`을 원본 변경과 함께 갱신한다.
  인물 교체 시 이전 인물의 집계도 갱신한다. 조회가 동적이라는 것만으로 파생 집계가 갱신되지는 않는다.
- 모르는 값은 지원되는 빈 값으로 기록한다. 현재 입력이 요구하는 승자 등 필수 정보가
  미해결이면 후보로 보존한다. 이름만 읽힌 참가자는 `observed_name`으로 남길 수 있으며,
  이름도 읽지 못한 자리는 후보 기록에 남긴다. FK나 식별자를 만들어 넣지 않는다.
- 사람이 교정한 값·숨김·서로 다른 데이터 출처의 소유권을 보존한다. 나무위키 시드의
  원래 수집 절차는 바꾸지 않고, 공유 이벤트에서 VOD 근거가 삭제되지 않는지만 검증한다.

프레임과 근거 산출물은 `out/ck/<vodId>/`, ASR 환경·캐시는 `.local/asr/`를 기본으로 한다.
현재 ASR 실험 경로의 파일을 근거로 채택하면 어드민이 읽는 근거 경로로 복사·등록한다.
설치·모델·임시 파일은 계속 프로젝트 내부에 둔다.
프레임 라우트는 허용 루트 안의 실제 파일만 읽도록 경로 탈출·심볼릭 링크 탈출을 차단한다.
로컬 파일 기반 운영이라는 점을 화면에 표시하고, 배포 시 저장소 이전은 별도 작업으로 둔다.

### 6.1 시리즈 교차검증과 구간 재사용 — 후속 구현

아래는 2026-09-27 합의한 설계다. **1·3은 구현했다**(2026-09-27): `ck:merge --find-match --vod`,
`ck:queue`의 기간 밖 running 합치기. 2·4는 후속 작업이다.

1. **VOD 선조회 (구현):** `ck:merge --find-match --vod <번호>` 확장으로 방송 시간 범위와 채널 참가 경기를
   조회한다. 확인된 경계만 VOD 구간으로 투영하고 로스터·KDA·세트 순서·근거·질문의 공백을 반환한다.
   date 정밀도·종료 경계 미상·불확실한 시간축은 자동 생략 구간이 아닌 조회 후보로 반환한다.
   같은 실행 중 새 경기 반영 후에도 최신 DB를 조회한다.
2. **기록과 강제 검사:** 판별 탐색 종료 사유, 근거 참조, 남은 범위, 재사용 출처를 구조화한다.
   done 검사는 이번 입력만이 아니라 병합 후 활성 후보 전체에 적용한다. 대체된 부모 후보는
   현재 작업에서 제외하되 이력은 보존한다. 참조·상태·범위 계약을 검사하며 의미 판독의 정확성까지
   보장한다고 하지 않는다. 탐색 종료와 다른 시점 생략 가능 상태는 구분한다.
3. **재개 큐 (running 만 구현 — 영구 실패 구분은 기간 제한으로 대신한다):** 최근 조회 기간 밖의 미완료 기록도 합친다. 재시도 가능 실패와 영구 확인 불가를
   구분해 누락과 무한 재시도를 막는다. 교정·새 충돌로 재사용 전제가 깨지면 관련 판을 재평가 대상으로 돌린다.
4. **통합 검수:** 시리즈 한 항목 아래 각 세트의 통합 값과 대표·비교 프레임을 보여준다.
   프레임마다 VOD·채널·오프셋을 유지하고 상충 값과 채택 근거를 비교할 수 있게 한다.
   보너스 단판은 같은 행사 아래 별도 경기로 표시한다. 첫 경기부터 누적 표시하며 공개 승인 게이트를 만들지 않는다.

회귀 검증은 ① 연결 조건 세 가지가 맞는 판만 재사용 ② 부분 결과창의 공백만 추가 조사
③ 시리즈 사이·뒤 보너스 단판 보존 ④ 재송출을 독립 근거로 세지 않음 ⑤ date/경계 미상/시간축 누락의
생략 방지 ⑥ 과거 running 재개와 영구 실패 반복 방지 ⑦ 병합 후 미종료 후보의 done 거부
⑧ 교정 후 재사용 전제 재평가 ⑨ 같은 실행 내 반영 직후 조회 ⑩ 시리즈 UI의 출처 보존을 다룬다.

## 7. 사후 교정 어드민의 최소 기능

기존 VOD 중심 화면의 기능이다. 시리즈별 통합 비교는 §6.1의 확장으로 구현한다.

- 목록: 날짜·채널·실행 상태·경기 유무·미해결 후보로 찾는다. 일부 실패와 전량 완료가 구분되어야 한다.
- 세션: VOD 시간축에서 기본 탐색 범위, 후보, 근거 프레임, 음성 단서, 미확인 범위를 확인한다.
- 판독: 프레임을 선택하면 이미지·원본 시각·관찰·판단 이유와 연결된 경기·참가자를 함께 본다.
- 교정: 참가자·챔피언·KDA·포지션·승자·이벤트/시리즈·근거를 수정하고 즉시 반영한다.
- 누락 복구: 미연결 프레임에서 경기 생성·기존 경기 연결이 가능해야 한다. 잘못 연결한 근거도 옮긴다.
- 제외·복구: 경기 숨김과 복구를 제공한다. 숨긴 경기가 재수집으로 되살아나지 않는다.

Server Component + Server Action + `useActionState` + Tailwind 패턴을 따른다.
별도 승인·닫기·전원 검수 완료 버튼은 필요 없다. 교정 자체가 데이터 변경이다.

## 8. 스킬 문서 구성과 이행 순서

최종 `SKILL.md`에는 목적, 필수 수행/자율 판단의 구분, 최소 흐름, 실제 명령과 출력 위치,
입력 창구, 필요한 참고문서 링크만 둔다. 이 계획안의 구현 명세 전체를 스킬 본문에 복제하지 않는다.

`CK-COLLECTION.md`에는 실측 함정과 읽기 요령을 남기되, 옛 단계 번호와 강제 판단표를
새 절차로 다시 끌어오지 않도록 정리한다. ‘자주 틀리는 자리’도 증상·관찰·참고 수단으로 바꾼다.
ASR 실행 세부는 [scripts/asr/README.md](../scripts/asr/README.md)를 단일 출처로 쓴다.
스킬에서 참고자료를 열라고 안내할 때도 필요한 주제만 가리킨다.

1. **기록 계약과 DB/어드민을 연결한다.** 이미 있는 코드에서 출발해 미해결 후보·미연결 근거·교정 보존까지 확인한다.
2. **프레임 탐색과 단일 입력 창구를 연결한다.** 전체 범위 대표 샘플·열람 기록·후보별 반영을 구현한다.
3. **선택 구간 ASR을 연결한다.** 기존 SenseVoice를 재사용하고 필요할 때 전체 전사·Qwen을 호출할 수 있게 한다.
4. **실제 VOD로 실행하고 스킬을 갱신한다.** 명령과 어드민 교정 경로를 검증한 동작만 스킬의 필수 행동으로 올린다.

현재 단일 입력 창구·기존 경기 요약 조회·검수 어드민·채널별 VOD 성향까지 구현되어 있다.
후속 변경도 구현과 회귀 검증을 먼저 끝낸 뒤 스킬 문구를 갱신한다.

## 9. 검증 기준

구현 검증은 사람이 ‘승인’하는 조사 단계가 아니라, 새 경로가 계약대로 동작하는지 확인하는 개발 작업이다.

| 사례 | 확인할 수행·데이터 계약 |
|---|---|
| FC온라인과 롤이 섞인 긴 VOD | 처음 본 게임으로 전체를 제외하지 않고 끝까지 대표 화면을 확인한다 |
| 픽셀 거름망이 놓친 시점 | 기본 대표 화면 탐색은 거름망과 독립적으로 남는다 |
| 프레임 추출 성공·열람 안 함 | 근거 판독 완료로 기록되지 않는다 |
| 분할 파일 경계·다운로드 실패 | VOD 전체 시각을 유지하고 미확인 범위를 남기며 재개한다 |
| 결과창·사람 매핑이 불명확 | 강제 결론이나 사용자 승인 요청 대신 근거와 현재 판단/미해결을 남긴다 |
| 경기 없음과 후보 미해결 | 경기 행이 0개여도 서로 다른 조사 결과로 표시한다 |
| 동일 결과 재전송·다른 시점 보강 | 중복을 만들지 않고 해당 경기의 근거만 연결한다 |
| 근사 시각으로 기존 경기 조회 | 정확한 시각을 기다리지 않고 기본 90분 창에서 후보를 찾되 같은 판을 자동 확정하지 않는다 |
| 여러 경기가 든 VOD 구간 | 경기별 좁은 `linked` 후보를 남겨 경기 막대와 프레임 문맥이 팽창하지 않는다 |
| 풀 점수판이 있는 경기의 다른 시점 | 참여 확인만 할 수 있으나 같은 VOD의 나머지 미확인 범위까지 생략하지 않는다 |
| VOD 미저장 경향 채널 | 조회 우선순위 힌트로 쓰되 목록 조회를 끄거나 불참으로 판정하지 않는다 |
| 어드민 교정·숨김 후 재수집 | 교정·숨김이 보존되고 공개 조회·관련 집계가 일치한다 |

DB 변경은 `npm run verify:db`, 모듈 경계는 `npm run verify:modules`, 관련 로직은 `npm test`로 검증한다.
브라우저에서는 목록 → 타임라인 → 프레임 → 수정/숨김 → 공개 페이지 반영을 확인한다.

탐색 방식은 동일 VOD 표본에서 프레임 우선과 전체 음성 우선을 비교한다.
혼합 방송·CK 방송·CK가 없다고 판단한 방송을 포함하고, 기존 방식의 후보만 정답으로 쓰지 않는다.
원본을 별도로 확인해 만든 기준 경기 목록에 대해 누락·오탐·결과 화면 확보·전송량·총 소요 시간을 기록한다.
일부 범위만 검증했다면 그 범위의 결과로 표시한다. 이 평가는 도구 기본값을 개선하는 데 쓰며,
개별 조사마다 통과시킬 점수나 고정 판독 횟수로 옮기지 않는다.
