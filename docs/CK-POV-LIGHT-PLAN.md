## 1. 목적과 원칙

1단계는 모든 VOD 가 모든 경기를 처음부터 읽는다. 추석 CK 9개 VOD 재조사에서 경기마다 독립 시점 7~8개가
결과창을 각자 읽었고 전부 일치했다. 같은 판을 7번 결과창까지 파는 비용을 줄인다.

**목표는 "기존 경기 값은 유지하고, 추가 연결의 정확성과 누락 여부를 검증한다" 이다.** 가벼운 모드는 경기 값을
바꾸지 않는다. 틀릴 수 있는 것은 **사진을 엉뚱한 판에 붙이는 것**과 **새 경기를 놓치는 것**이고, 이 둘을 막는 것이 설계의 중심이다.

- 가벼운 모드의 일은 "이 스트리머가 이 판에 있었다" 확인과 사진 연결뿐이다. 경기 값을 다시 검증하지 않는다.
- **경기 구간 밖은 절대 줄이지 않는다.** 판 사이·시리즈 전후·보너스 단판·다른 게임은 평소대로 훑고 추적한다.
- **판정은 코드가 한다.** 자격·통과·해제는 저장 도구가 계산하고, 모델은 화면에서 읽은 것을 낸다.
- **애매하면 절약하지 않는다.** 자격이 없거나, 판을 특정하지 못하거나, 시간축을 믿을 수 없으면 일반 조사로 돌아간다.

## 2. 가벼운 모드 자격 (경기마다, 코드가 계산)

아래를 모두 만족한 경기만 자격이 있다. 자격은 저장하지 않고 조회 때마다 계산한다.

1. **독립 주요 확인 3개 이상.** 다음을 모두 만족한 시점을 **스트리머 기준으로** 센다.
   - `mode: full`, `source: own` — 재송출은 세지 않는다.
   - 그 시점이 직접 읽어 비교한 칸이 **승자 + 챔피언 10/10 + K/D/A 30칸 중 27칸 이상**이고 불일치가 없다.
   - 한 방송이 VOD 둘로 나뉜 경우(같은 `streamer_id`)는 하나로 센다.
   - ⚠ 27칸 기준은 비용 절약 기준이다. 세 시점이 같은 3칸을 못 읽어도 자격이 된다 — "3개 시점이 **주요 항목**을
     확인했다" 는 뜻이지 "다 채워졌다" 가 아니다. 남은 빈칸은 검수 화면에 그대로 빈칸으로 보이고, 가벼운 모드는 채우지 않는다.
2. **미해결 불일치 0.** 검수 완료된 불일치는 막지 않는다.
3. **경기 구간을 계산할 수 있다** — 경기 시각이 `datetime` 이고 경기 길이(`game_duration`)가 있다. 시작만 알고 끝을 모르면 자격이 없다.

새 불일치가 생기면 그 즉시 자격이 풀린다.

## 3. 판정의 기본 — 맞음·다름·모름

화면에서 읽은 값과 저장값을 비교할 때 결과는 셋이다.

| 결과 | 뜻 |
|---|---|
| **맞음** | 둘 다 있고 같다 |
| **다름** | 둘 다 있고 다르다 |
| **모름** | 화면에서 못 읽었거나, 저장값이 비어 있다 |

**모름은 다름이 아니다.** 모름으로 후보를 지우지도, 통과시키지도 않는다.

## 4. 힌트

### 4.1 필수 — 본인 챔피언
방송 주인의 챔피언을 읽어 저장값과 **맞음**이어야 한다(인게임 하단 초상화·밴픽·탭 점수판·결과창).

### 4.2 판을 특정하는 힌트 — 하나 이상 "맞음" 이어야 한다
같은 멤버의 다른 판에서는 달라지는 값이다. "**이 판이다**" 를 직접 가리킨다.

| 힌트 | 어디서 보이나 | 제출 | 코드가 확인하는 것 |
|---|---|---|---|
| 게임 시계 | 인게임 상단 | `hints.game_clock: [{frame, clock:"12:34"}]` | (사진 절대시각 − 경기 시작)과 게임 시계 차이 ±2분 |
| 세트 스코어 | 오버레이 "[5/3] 라뎃팀 0 vs 1" | `hints.series_score: {frame, score:"0:1", phase:"in_game"\|"after"}` | 진행 중이면 점수 합 = 세트 번호 − 1, 끝난 뒤면 = 세트 번호. 세트 순서가 확인된 시리즈만 |
| 결과창 | 우연히 걸리면 | 1단계와 같은 전체 값 | 결과창 값 전체가 맞음. 경기 길이 ±10초 |

### 4.3 후보를 줄이는 힌트 — 통과 근거로는 못 쓰고, 다른 후보를 지우는 데만 쓴다
같은 멤버가 연달아 하면 다음 판에서도 똑같이 맞을 수 있다(추석 CK 는 클리드팀이 3연승 — 승리 배너가 세 판 모두 같다).

| 힌트 | 제출 | 쓰임 |
|---|---|---|
| 로비·밴픽 이름 3명 이상 | 참가자 `observed_name`·slug | 명단이 다른 판을 지운다 |
| 다른 사람 챔피언 2명 이상 | 참가자 `champion_name` | 챔피언이 다른 판을 지운다 |
| 승리/패배 배너 | `winning_team`(이 화면 기준) | 승패가 다른 판을 지운다 |
| 채팅 경기 종료 | `hints.chat_end_at`(`noticesFrom`) | 종료 시각 ±3분 밖의 판을 지운다 |

넣지 않은 것: **팀 킬 스코어** — 경기 중간 값이라 "최종보다 작다" 외에는 확인할 수 없고 연속 판을 가르지 못한다.

## 5. 통과 판정 (코드)

1. **후보를 모은다** — 방송 주인이 참가자인 기록된 경기 중, 제출 사진 시각이 그 경기 구간(밴픽 10분 전 ~ 결과창 5분 뒤) 근처인 것.
2. **후보를 지운다** — 제출한 값 중 하나라도 "다름" 인 후보를 지운다. "모름" 으로는 지우지 않는다.
3. **통과** — 아래를 모두 만족해야 한다.
   - 남은 후보가 **대상 경기 하나**다.
   - 대상 경기에 대해 본인 챔피언이 **맞음**이다.
   - 대상 경기에 대해 **판을 특정하는 힌트(4.2)가 하나 이상 맞음**이다.
   - 대상 경기에 대해 **다름이 없다**.

**왜 판을 특정하는 힌트가 꼭 필요한가:** 기록된 후보 중 하나만 남았다는 것은 "알려진 경기 중에서는" 이라는 뜻이다.
DB 에 아직 없는 판(예: 아무도 못 찾은 보너스 단판)일 수 있다. 게임 시계·세트 스코어처럼 대상 판을 직접 가리키는
근거가 있어야 새 경기 가능성을 배제한다. ±30분·구간 안이라는 사실은 증명이 아니다.

## 6. 결과 처리 (코드)

| 상황 | 기존 경기 | 이 VOD 의 조사 기록 | 조사자가 할 일 |
|---|---|---|---|
| 자격 없는 경기에 `light` 제출 | 변경 없음 | — | 거부됨. 전체 읽기로 낸다 |
| **통과** | 시점 기록(`mode: light`)·사진 연결. 빈칸 채우지 않음 | — | 끝 |
| **판 불확실** — 후보가 둘 이상 남음 / 판 특정 힌트 없음 / 게임 시계·세트 스코어가 대상과 다름 | **아무것도 붙이지 않는다**(사진·불일치·검수 해제 없음) | 후보를 `unresolved` 로 남기고 **연결 보류 사유**를 적는다 | 판을 특정할 사진을 더 보거나, 이 경기를 전체 읽기로 본다 |
| **판 확실 · 값 다름** — 판 특정 힌트는 맞고 저장값(챔피언 등)이 다름 | 불일치 기록 → 자격 해제·검수 완료 해제 | — | 이 VOD 에서 그 경기를 전체 읽기로 다시 본다 |
| **B: 확인 못 함** | 7절 | 7절 | 7절 |

- 게임 시계와 세트 스코어는 **판을 가르는 힌트이지 저장값이 아니다.** 어긋나면 "판 불확실" 이다(불일치로 기록하지 않는다).
- 가벼운 시점은 **확인 수(2절)에 들어가지 않는다.** 전체 읽기 시점만 센다.
- 같은 위험(잘못 고른 경기에 불일치가 기록되는 것)은 1단계 전체 읽기에도 이론상 있다. 결과창을 직접 보고 고르므로 가능성은 낮다.
  1단계에 같은 판정을 넣는 것은 후속 과제로 둔다.

## 7. B — 이 VOD 에서 확인하지 못했을 때

**시간축과 대상 경기 구간이 확실한데 화면이 가려진 경우에만** 쓴다. 스트리머가 다른 창을 띄웠거나, 그 구간 사진에 게임
화면이 없을 때다.

- **시간축·경기 경계가 불확실하면 B 를 쓰지 않는다** — VOD 가 끊겼거나(`time_reliable: false`) 구간을 계산할 수 없으면
  어디가 이미 확인된 경기 구간인지부터 모른다. 이때 B 로 닫으면 다른 경기까지 생략할 수 있다. 일반 조사로 돌아간다.
- 경기 값은 이미 독립 3개가 확인했으므로 기존 경기 값은 유지된다. 잃는 것은 이 VOD 사진 연결 하나다.
- `pov: { mode: "light", unseen: "사유" }` 로 낸다. 값·사진 연결은 없다.
- 코드는 이 VOD 의 **기존 열람 기록**(`match_evidence_frame.read_at` 이 있는 프레임) 중 그 경기 구간 안의 것이 2장 이상인지
  확인한다. 이것은 **열람 기록이지 열람 증명이 아니다** — 기록도 조사자가 남긴다. 적어도 "구간 안 사진을 하나도 열지 않고
  B 로 닫는" 것은 막는다.
- 시점 기록에 "확인 못 함" 으로 남고, 검수 화면 칩에 회색 표시가 붙는다.
- 그 구간에서 **다른 게임이 있었는지는** 평소 훑기로 본다(구간 밖 원칙과 같다).

## 8. 조사자 절차 요약

1. `ck:merge --find-match --vod <번호>` — 경기마다 `독립 확인 N/3 · 가벼운 모드 가능|전체 읽기`, 가능하면 **확인할 VOD 초
   후보**(구간 시작+5분 · 중간 · 끝−2분).
2. 가능한 경기: 이미 뽑힌 30분 간격 사진 중 그 구간에 걸린 것 → 부족하면 후보 초 2~3곳만 `--at` 으로.
3. 본인 챔피언 + **판을 특정하는 힌트**(게임 시계·세트 스코어·결과창)를 읽어 `mode: light` 로 제출. 후보를 줄이는 힌트도 보이면 같이 낸다.
4. 도구 판정: 통과 / 판 불확실(연결 보류 사유 남음 → 더 보거나 전체 읽기) / 값 다름(전체 읽기) / 거부(자격 없음).
5. 끝내 못 보면 B(시간축이 확실할 때만).
6. **경기 구간 밖은 평소대로.**

## 10. 검증

### 10.1 합성 사례 (verify:ck:pov)

| 사례 | 기대 결과 |
|---|---|
| 확인 2개 경기에 light 제출 | 거부 |
| 같은 스트리머 쪼개진 VOD 2개 + 다른 1명 | 확인 2 → 거부 |
| 재송출 시점 포함 3개 | 재송출 제외 → 거부 |
| K/D/A 26칸만 읽은 전체 시점 | 주요 확인으로 세지 않음 |
| 경기 길이 없음 / 날짜 단위 경기 | 자격 없음 |
| 챔피언 + 게임 시계 맞음, 후보 하나 | 통과, 사진 연결, 빈칸 안 채움 |
| 챔피언만 맞음(판 특정 힌트 없음) | 판 불확실 — 기존 경기 무변경 |
| 챔피언 + 로비 이름·승리 배너만 | 판 불확실(후보 줄이는 힌트만으론 통과 못 함) |
| 게임 시계가 대상과 5분 어긋남 | 판 불확실 — 불일치 기록 없음, 검수 완료 유지 |
| 연속 판·같은 챔피언·구간 경계 사진 | 시계·세트 스코어로 갈림. 옆 판엔 연결 안 됨 |
| 옆 판 챔피언이 비어 있음(모름) | 모름으로 지우지 않음 → 판 특정 힌트로만 통과 |
| 판 특정 힌트 맞음 + 본인 챔피언 다름 | 판 확실·값 다름 → 불일치 기록, 자격 해제 |
| B: 시간축 확실, 구간 안 열람 기록 2장 | 기록, 사진 연결 없음, 확인 수 불변 |
| B: `time_reliable: false` | 거부(일반 조사로) |
| B: 구간 안 열람 기록 1장 | 거부 |
| 가벼운 시점 3개 쌓임 | 확인 수 그대로 |
| 1단계 사례 34개 | 그대로 통과 |

### 10.2 실측 — 1단계를 **비교 기준**으로

가벼운 모드는 경기 값을 바꾸지 않으므로 "값이 같다" 는 검증이 안 된다. 사진 연결과 누락을 본다.

1. 돌리기 전에 지금 DB 의 **사진 → 경기 연결표**(1단계 결과)를 떠 둔다. 이것은 정답지가 아니라 비교 기준이다 — 1단계에도 오연결이 있을 수 있다.
2. 추석 CK 9개 VOD 를 가벼운 모드 포함으로 다시 돌린다.
3. 확인한다.
   - 가벼운 모드가 붙인 사진이 1단계와 **다르게 연결된 경우**와 **판 경계 사진**(앞 판 결과창·다음 판 밴픽)은 사람이 직접 열어 어느 판인지 본다.
   - **B·판 불확실 때문에 따로 있던 새 경기나 보너스 단판을 놓치지 않았는지** — 1단계가 찾은 경기가 2단계에서 전부 다시 잡히는지.
     (B 구간 안에 이미 알려진 경기가 있는 것은 정상이다. B 는 원래 그 경기의 추가 시점을 못 본 경우다.)
   - 위 조건을 지키면서 시간·연 사진 수가 줄었는지.
