# ck:listen 음성 맥락 도입 계획

작성일: 2026-10-12. 상태: 독립 음성 맥락 기능 구현 및 30분 실전 준비·열람 시험 완료. 사용자 최종 결정에 따라 첫 준비 창은 **30분**이다. 2026-10-12 사용자 요청으로 전체 LoL ck-local 적용을 on으로 전환했다. 2–3일 실사용 시험을 계획했으나, 현재 DB 용량 보호 장치로 조사 시작은 대기 중이다. 전체 VOD 전사·Claude 비용·분류 정확도 평가는 아직 하지 않았다. DB 직접 쓰기·분류 자동화는 없다.

기존 ck-local의 결과 화면 판독에 **경기 준비 대화 원문을 필수 참고자료로 추가**한다. 참가자·챔피언·KDA·승패 판독을 유지하면서, 화면만으로 놓치기 쉬운 CK·랜드·대회 성격, 시리즈 규칙, 보상 조건과 변경 시점을 더 잘 판단하게 만드는 것이 목적이다.

권장 시작점은 **첫 조사 묶음의 경기 시작 전 기본 30분 원문과, 이후 경기 사이 준비 대화 원문을 전달**하는 방식이다. 범용 로컬 LLM이나 리랭커로 문장을 탈락시키지 않는다. 키워드는 전체 전사에서 다른 단서를 찾는 검색 보조로 사용한다. 도구는 시간을 맞추고 원문을 묶으며, Claude가 발언의 의미와 적용 범위를 판단한다.

## 1 원칙과 수정 범위

기준은 [기존 조사 설계](CK-RESEARCH-PLAN.md)의 “필수로 정할 것은 수행과 기록”, [결과 화면 탐색 계획](CK-RESULT-SEARCH-QUEUE-PLAN.md)의 “탐색을 강제 판정으로 바꾸지 않는다”, [FC 맥락 계획](FCO-MATCH-CONTEXT-SKILL-PLAN.md)의 수행과 해석 구분이다. 현재 사용자 결정에 따라, 기능을 켠 조사에서는 준비된 음성 자료의 열람을 선택 사항으로 두지 않는다.

| 구분 | 이번에 적용할 기준 |
|---|---|
| 코드로 보장 | VOD·HLS 시간축 일치, 범위·참조·캐시 버전 검증, 원문 보존, 중복 구간 제거, 누락·실패 표시, 임시 파일 수명, 재실행·중단 복구 |
| 스킬에서 필수 수행 | 음성 준비 상태 확인, 해당 조사에 배정된 원문 열람 또는 실제 열람 기록 재사용, 확인 불가 사유와 읽은 범위 기록, 관련 분류를 제출하기 전 자료 검토 |
| Claude의 판단 | 어떤 경기의 말인지, 제안인지 합의인지, 현재인지 과거·미래인지, CK·랜드·대회 여부, 시리즈 연결, 보상 조건, 추가 확인 수단·범위, 근거가 부족할 때 미해결 처리 |
| 강제하지 않음 | 특정 분류 선택, 모든 칸 채우기, 특정 단어 포함, 단서 개수·점수 합격선, Qwen 재전사 횟수, 다른 POV 개수, 정확히 30분 또는 60분을 읽어야만 확정 가능하다는 규칙 |
| 완료와 성공의 구분 | 필요한 자료를 확인하고 한계를 처리하는 것은 필수다. 분류 확정 성공은 필수가 아니다. 아직 읽을 필수 자료가 남았으면 재개할 작업으로 남긴다 |

“랜드” 검색 결과는 관련 발언이 있다는 뜻이다. 랜드 경기의 존재·시작·참가·종료를 확정하는 값이 아니다. “300개”는 보상, 후원 감사, FC 카드 이야기 등일 수 있다. 코드는 이런 의미를 `event.kind`나 경기값으로 변환하지 않는다.

첫 적용 범위는 **기능을 켠 LoL ck-local 조사**다. 혼합 방송의 FC 대화도 원문에 남기고 Claude가 구별한다. FC 전용 조사에 전체 전사 의무를 일괄 추가하거나 FC API 소유 필드를 수정하지 않는다. FC 스킬이 이미 쓰는 선택 구간 `ck:listen`은 유지한다.

포지션·참가자 이름·팀 명단을 음성만으로 자동 채우는 기능은 이번 범위에 넣지 않는다. 다만 준비 대화에 나온 역할·팀 변경을 숨기지는 않는다. Claude가 화면을 다시 볼 단서로 활용할 수 있다. 기존 조사에서 허용하는 불명확한 결과의 보완 수단까지 이번 계획으로 금지하지 않는다.

## 2 현재 코드에서 확인한 연결 지점

| 현재 구성 | 확인한 동작 | 계획에 미치는 영향 |
|---|---|---|
| [ck-listen.mjs](../scripts/ck-listen.mjs) | `--vod --at`으로 선택 구간 추출·전사. `ck:probe`의 HLS 전체 초 사용. DB 직접 쓰기 없음 | 기존 호출은 호환 유지하고 새 준비·읽기 기능을 추가한다 |
| [ck-audio.ts](../scripts/lib/ck-audio.ts) | 요청을 분할 파일 경계로 나누고 범위 밖 요청을 기록 | 같은 시간축·범위 계약 재사용. 전체 VOD 요청에는 더 작은 처리 단위가 필요하다 |
| [transcribe.py](../scripts/asr/transcribe.py) | 모델·오디오 해시·설정으로 재개 확인. 완료 여부 확인 전에도 WAV 해시를 읽음. 다운로드 manifest가 불완전하면 거부 | 완료 캐시를 읽을 때 WAV가 없어도 동작하도록 새 준비 경로에서 먼저 확인해야 한다. 현재 스크립트에 파일 삭제만 붙이면 재개가 깨진다 |
| [ck-local 스킬](../.claude/skills/ck-local/SKILL.md) | 결과창을 먼저 읽음. 대상 분류는 현재 화면 근거로 하라는 지침. `--finish`로 기록 조립 | 화면 판독 뒤, 분류 제출 전 음성 열람을 연결한다. “화면만” 지침을 함께 갱신한다 |
| [ck-research 스킬](../.claude/skills/ck-research/SKILL.md) | 선택 구간 음성은 보조 수단. 판별로 즉시 저장. 열람과 생성 구별 | 기능을 켠 조사에 대한 필수 열람 계약을 명확히 하고 기존 선택 구간 기능은 보존한다 |
| [ck.ts](../packages/core/lib/db/ck.ts) | `scan.transcript_read`는 실제 읽은 시간 범위. 범위 병합. `done`은 탐색 상태 | 전체 전사 완료를 전체 열람으로 기록하지 않는다. 새 원문 버전 확인은 로컬 기록으로 보완한다 |
| [ck-merge.mjs](../scripts/ck-merge.mjs) | 기존 이벤트 종류 변경을 거부. 검수값 보호. `best_of`는 근거와 지원 형식 요구 | 음성으로 다른 분류를 찾았어도 저장 보호를 우회하지 않는다. 기존 행사 종류의 자동 교정은 이번 범위 밖이다 |
| [ck-auto.sh](../scripts/ck-auto.sh), [ck-backfill.sh](../scripts/ck-backfill.sh) | VOD 재개·세션 사용량 기록. SOOP 도구 병렬 실행 금지 | 준비 작업은 기존 직렬 흐름에 연결. 재개마다 전체 음성과 원문을 다시 만들지 않는다 |

현재 자동·백필 실행기는 기본 모델 별칭으로 `sonnet`을 사용하지만, 실제 모델 버전과 과금 경로를 별칭만으로 확정하지 않는다.

추가 지침 충돌도 정리 대상이다. 수동 백필 프롬프트에는 방송 주인이 참가하지 않은 재송출도 허용하는 문구가 있고, ck-local에는 2026-10-09 결정에 따른 참가 범위 제한이 있다. 음성 속 남의 경기 이야기를 자기 경기로 잘못 연결하지 않도록, 구현 때 해당 문구만 현재 사용자 결정과 맞춘다. 다른 조사 정책까지 일괄 개편하지 않는다.

## 3 기존 시험이 말해 주는 것

2026-10-12 리랭커 시험은 5개 VOD의 **부분 전사 총 89.5분**으로 수행했다. 성훈 VOD `209492205`의 기존 55분 전사에서 미리 표시한 근거 사례 15개를 비교했다.

| 원문 선택 방법 | 전달 원문 문자 비중 | 표시 사례 보존 |
|---|---:|---:|
| 키워드와 앞뒤 대화 | 58.0% | 13/15 |
| Qwen3-Reranker 0.6B 짧은 질의와 약 58% 분량 예산 | 56.9% | 10/15 |
| 같은 리랭커와 약 80% 분량 예산 | 79.4% | 12/15 |

근거: [시험 요약](../out/analysis/reranker-20261012/summary.json), [원문과 점수](../out/analysis/reranker-20261012/index.html). 원본 음성을 모두 다시 듣고 만든 정답 세트가 아니므로 전체 정확도로 부르지 않는다. 키워드 방식도 누락이 있었다. 더 큰 리랭커는 시험하지 않았다.

이 결과는 “어느 문장을 버릴지”를 더 복잡하게 결정하는 것보다 **준비 대화의 연속성을 유지하는 방법을 먼저 시험할 이유**다. 경기 전 원문 묶음 방식의 품질 향상이나 Claude 비용 절감이 이미 검증됐다는 뜻은 아니다.

범용 Qwen3.5·Ollama·시험용 리랭커는 정리했다. 이번 구현에 다시 설치하지 않는다. SenseVoice와 기존 선택 구간 Qwen ASR만 재사용한다. 이전 ck-context 실험 코드에 운영 의존성을 만들지 않는다.

## 4 경기 전 30분 또는 1시간을 통째로 주는 방안

### 한 번의 분량

성훈 표본 55분의 원문은 14,070자, 분당 약 256자다. 이 밀도를 단순 환산하면 다음과 같다.

| 원문 범위 | 예상 문자 수 |
|---|---:|
| 30분 | 약 7,700자 |
| 60분 | 약 15,300자 |

이는 **부분 표본의 평균 밀도에서 계산한 문자 수**다. 연속된 30분·60분을 새로 전사해 센 수치도, Claude 토큰 실측도 아니다. 동시 대화와 ASR 상태에 따라 달라진다. 한 번 전달할 수 없을 정도라고 단정할 근거는 없다.

### 매 경기마다 적용했을 때

같은 VOD의 지도에 있는 `ingame` 시작 후보 24개에 기계적으로 창을 붙이면 다음과 같다. 시작 후보는 확인된 경기 수·정확한 경기 시작 시각이 아니다. 오탐·분할 구간이 섞일 수 있는 **현재 지도 기반 범위 계산**이다.

| 모든 시작 후보에 붙인 범위 | 중복 포함 총분량 | 겹치는 범위를 합친 분량 | VOD 길이 대비 |
|---|---:|---:|---:|
| 앞 30분 | 약 696분 | 약 631분 | 약 77% |
| 앞 60분 | 약 1,370분 | 약 795분 | 약 96% |

근거: [계산 결과](../out/analysis/reranker-20261012/prestart-window-estimate.json). 실제 전체 텍스트 전송량·토큰·비용 측정은 아니다. 이 VOD에서는 매 판 앞 1시간을 붙이면 거의 전체 방송을 읽게 되는 구조이므로, **중복 제거만으로 충분히 작아진다고 약속하지 않는다.**

### 권장 원문 구성

1. **처음 살펴보는 경기 흐름 또는 새로운 행사·구성으로 의심되는 지점:** 확인한 시작 시각 앞 30분을 기본으로 원문을 전달한다. VOD 시작을 넘지 않으며, 이미 읽은 원문은 재사용한다. 30분은 초기 기본값이지 충분성·정확성의 판정 기준이나 탐색 상한이 아니다.
2. **이어서 진행하는 판:** 직전 확인된 경기 종료부터 다음 경기 시작까지 준비 대화를 통째로 전달한다. 팀 재편성·보상·룰 변경이 생길 수 있으므로 첫 경기의 결론만 복사하고 생략하지 않는다. 새 시리즈라고 확정돼야만 넓게 읽을 수 있는 구조로 만들지 않는다.
3. **직전 종료나 같은 흐름인지 불분명한 판:** 앞 30분을 시작 범위로 제안하고, 조사자가 이유에 맞게 넓히거나 바꾼다. 현재 화면 지도의 시작은 후보이므로 오차와 출처를 함께 표시한다. 경계가 확인되지 않았다는 이유로 음성 확인을 통째로 생략하지 않는다.
4. **준비 대화 밖의 변경:** 전체 전사에 시간순 키워드 색인을 둔다. CK·랜드·대회·피어리스·몇 선승·펀딩 같은 직접 관련 표현과 표기 변형을 찾는 보조 수단이다. 주 패킷 밖의 검색 단서는 별도 후보 구간과 원문 이웃을 제시하고, 확인 필요성은 Claude가 판단한다. 검색이 없다는 이유로 자료 부재·변경 없음으로 결론 내리지 않는다.
5. **마지막 판 이후:** 종료·추가 판·보너스 판에 관한 실제 준비나 마무리 대화도 대상이다. 첫 경기 전만 읽고 이후 시리즈 변화가 없다고 가정하지 않는다. 기존 화면 탐색으로 확인한 마무리 구간 또는 남은 질문에 맞는 구간을 전달한다.

여기서 “경기 흐름”은 읽을 범위를 정하기 위한 조사 묶음이다. 같은 `series_id`나 `event_id`로 확정했다는 뜻이 아니다. 시간상 가깝다는 이유로 팀·CK 형식·펀딩 조건을 상속하지 않는다.

게임 시작 직전·직후에 걸친 ASR 청크는 문장 중간을 자르지 않고 함께 준다. 의도적으로 넓어진 범위를 표시한다. “게임 중” 화면에서도 다음 판을 조율하므로 그 라벨을 음성 제외 조건으로 사용하지 않는다. 성훈의 랜드 초대 발언 `5010초`도 지도상 게임 중 구간에 있었다.

이 권장안에서는 **선택한 시간창 안의 문장을 중요도에 따라 버리지 않는다.** 키워드가 없는 조건부 답변도 남는다. 전체 전사는 검색 가능한 원본이고, Claude가 방송 전체 대화를 읽었다고 표현하지 않는다.

## 5 준비와 실제 열람을 놓을 위치

```text
기존 VOD 및 이전 기록 조회
  → 기존 ck-local 화면 준비와 시간축 확인
  → SenseVoice 전체 전사 준비 또는 유효 캐시 재사용
  → 기존 개요·후보·결과창 판독
  → 조사할 경기 흐름의 준비 대화 원문 배정
  → 배정된 원문 필수 열람 또는 같은 원문 열람 기록 재사용
  → 분류·시리즈·보상 맥락 판단 및 필요한 추가 확인
  → 기존 창구로 해당 경기와 근거 즉시 저장
  → 다음 경기에서는 새 준비 구간과 바뀐 근거만 확인
```

음성 확보는 초기에 수행하고, 본문 열람은 **해당 경기의 결과 화면 판독 뒤와 대상 분류·시리즈 연결을 제출하기 사이**에 둔다. “VOD 전체를 다 조사한 맨 마지막”에 처음 읽지 않는다. 기존 이벤트를 잘못 만든 뒤 종류를 바꾸려 하면 현재 저장 보호와 충돌하기 때문이다.

원문을 모두 모을 때까지 모든 경기 저장을 미루지 않는다. 해당 판의 필수 자료 검토가 끝났으면 기존처럼 즉시 저장한다. 음성 확보 자체가 불가능하면 확인 불가를 기록하고 화면 근거로 진행할 수 있다. 음성 장애가 전체 조사·저장의 새 선행 승인 조건이 되어서는 안 된다.

새 필수 읽기는 결과창 탐색을 대신하지 않는다. 음성에서 새로운 대상·경계 단서가 나오면 관련 위치로 되돌아갈 수 있다. 결과창의 이름·KDA 같은 값을 전사에서 덮어쓰는 자동 경로는 만들지 않는다.

## 6 ck:listen의 확장 계약

아래는 **구현할 인터페이스**다. 현재 실행 가능한 신규 명령으로 안내하지 않는다.

| 호출 | 목적 |
|---|---|
| 기존 `ck:listen -- --vod N --at 시작:길이 [--engine qwen]` | 기존 사용법·기존 캐시 동작 보존. 새 전체 전사 캐시의 재사용은 prepare/read 경로에서 수행 |
| 신규 `ck:listen -- prepare --vod N` | 전체 HLS 시간축을 기준으로 음성 확보·SenseVoice 전사·캐시 검증·검색 색인 준비. 긴 본문은 stdout으로 내보내지 않음 |
| 신규 `ck:listen -- read --vod N --between A:B` | 준비된 캐시에서 해당 구간의 원문과 시간·출처·미확보 범위 제공. 네트워크 다운로드나 다른 모델 호출을 숨겨서 수행하지 않음 |
| 신규 `ck:listen -- status --vod N` | 기능 적용 상태, 전사 확보 범위, 미확보 범위, 패킷·열람 기록 위치, 재개 지점 확인 |

`prepare`는 원문·근거를 만들고 `read`는 그것을 보여 주는 역할이다. 생성 성공·출력 성공을 Claude의 실제 열람으로 간주하지 않는다. Qwen ASR은 명시적으로 선택한 불명확한 구간에만 사용하며, 저점수·키워드 일치 같은 규칙으로 자동 반복하지 않는다.

신규 구현은 `scripts/ck-listen/` 같은 독립 디렉터리에 둔다. 공용 진입점은 기존 선택 구간 경로와 신규 경로를 분기하는 정도로 제한한다. 재사용할 것은 HLS 시간축·오디오 추출·ASR 실행·범위 연산이며, 오래된 ck-context/Ollama 선택기를 가져오지 않는다.

## 7 원문 전달과 비용 관리

패킷은 최소한 다음을 가진다: VOD와 시간축 버전, 전사 엔진·설정·해시, 패킷 ID, 원문 구간 ID와 시작·끝, 수정하지 않은 텍스트, 요청 대비 미확보 범위, 그 구간을 요청한 이유와 근거 위치. 검색으로 찾은 경우에는 검색 표현을 표시한다. 자동 요약·화자 실명 추정·분류 결론·정답 확률은 넣지 않는다.

화면 자료는 기존 파일을 참조한다. 새 패킷이 이미지와 원문 전체를 여러 번 복사해 별도 보고서·JSON·요약으로 다시 읽게 하지 않는다. 읽을 본문과 기계용 메타데이터를 구분하고, ASR 진행 로그를 대화 입력으로 넘기지 않는다.

겹친 구간은 같은 VOD·시간축·전사 버전·구간 ID를 기준으로 합친다. 문장이 비슷하다는 이유로 서로 다른 시각의 발언을 삭제하지 않는다. 시간축에 공백이 있으면 하나의 연속 대화처럼 잇지 않는다.

패킷이 길면 페이지로 나누고 다음 페이지와 남은 범위를 표시한다. 출력 길이 제한으로 잘렸으면 미열람으로 남긴다. 조용히 상위 몇 개·몇 글자만 남기는 방식은 사용하지 않는다. 페이지 크기는 도구 출력 한도를 위한 값이며 경기 판단 규칙이 아니다.

같은 세션에서 읽은 원문은 다시 출력하지 않는 것이 기본이다. 새 세션·대화 압축 뒤에는 판단 근거와 짧은 인계, 원문 ID를 전달하고 필요한 원문을 다시 읽을 수 있어야 한다. 과거 열람 기록이 있다는 사실과 현재 세션이 원문을 갖고 있다는 사실은 다르다. “한 번 읽었으므로 이후 입력 비용은 0”이라고 가정하지 않는다.

정확한 Claude 입력량은 실제 모델 ID로 [토큰 카운트](https://platform.claude.com/docs/en/build-with-claude/token-counting)를 하거나 실행 usage에서 확인한다. 글자 수를 고정 비율로 Claude 토큰으로 단정하지 않는다. 프롬프트 캐시는 반복 입력 비용을 줄일 수 있지만, 세션 이력에 남은 텍스트가 컨텍스트 공간을 차지하는 문제까지 없애지는 않는다. 캐시 쓰기·읽기·비캐시 입력을 분리해 측정한다. [공식 캐시 문서](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

예를 들어 실제 추가 입력이 10,000토큰이면 Sonnet 4.6 표준 비캐시 입력 단가 $3/100만 토큰에서 **그 입력 1회분은 $0.03**이다. 이 예시는 한국어 1시간 전사가 10,000토큰이라는 주장도, 실제 세션 비용도 아니다. 출력·반복 호출·캐시 쓰기·기존 대화와 도구 입력은 별도이며, 구독 이용량을 API 청구액으로 단정하지 않는다. 단가는 2026-10-12 확인한 [공식 요금표](https://platform.claude.com/docs/en/about-claude/pricing) 기준이다.

## 8 실제 열람과 완료를 기록하는 방법

새 로컬 기록에는 준비된 범위, 전달한 패킷, Claude가 실제 읽었다고 기록한 패킷·원문 버전, 확인 불가 사유를 분리한다. 도구 출력 로그는 전달의 증거이고 의미 이해를 보증하지 않는다. `read` 호출 시 자동으로 “읽음”을 찍지 않는다.

실제 열람 뒤 조사자가 기존 저장 입력을 만들 때 읽은 패킷 ID를 함께 남긴다. 기존 `--finish`에 선택 입력으로 연결해 `scan.transcript_read` 범위를 기계적으로 조립하는 방식을 우선한다. 동일 구간의 새로운 전사 버전은 별도 확인 대상이다. 과거 `transcript_read` 시간 범위만으로 새 본문까지 읽었다고 처리하지 않는다.

실행 상태는 다음을 구별한다.

| 상황 | 처리 |
|---|---|
| 배정된 원문을 아직 안 읽음 | 필수 수행이 남음. 읽거나 재개 지점과 함께 `running`으로 기록 |
| 읽었지만 CK·랜드 등이 불명확 | 미해결 근거·질문 보존. 다른 필수 수행까지 끝났다면 분류 미확정만으로 `done`을 막지 않음 |
| 일시 오류로 음성 일부 확보 실패 | 구간·사유·남은 작업 기록. 성공한 부분을 버리지 않고 재개 가능하게 보존 |
| 소스에 음성이 없거나 접근 불가 등 확인 불가 | 실제 확인한 사유 기록. 음성 성공을 무한히 기다리지 않고 기존 조사로 진행 가능 |
| 기능을 끈 실행 | 비활성화 상태를 명시. 음성 완료·열람으로 기록하지 않고 기존 조사 계약 적용 |
| 같은 원문을 앞 세션에서 읽었음 | 출처·범위·버전과 근거를 재사용. 현재 판단에 필요한 부분은 다시 열 수 있음 |

미해결 후보를 `not_target`으로 바꿔 완료시키지 않는다. 키워드 0건·빈 전사·전사 실패도 경기 없음의 증거로 쓰지 않는다. 실패를 핑계로 읽을 수 있는 배정 원문까지 생략하지 않는다.

새 `ck:merge` 합격선이나 음성 점수 게이트는 만들지 않는다. 참조·범위·해시·표현 가능한 필드 같은 기계적 계약은 검사하되, 특정 결론·단서 개수·정해진 확인 문구를 검사하지 않는다. 종료 전 남은 패킷을 보여 주고 스킬이 처리하도록 한다. 실제 이해까지 코드가 강제할 수 있다고 주장하지 않는다.

## 9 전체 전사와 임시 용량

기능을 켠 VOD는 방송 시작부터 끝까지 SenseVoice 전사를 준비하는 것이 기본이다. **전체를 전사하는 범위와 Claude에게 읽히는 범위는 별개**다. 전체 전사를 확보하면 나중에 앞선 조율·변경 발언을 찾아도 매번 다운로드와 모델 실행을 반복할 필요가 없다.

VOD 하나씩 처리하되 전체 고화질 영상 파일을 영구 저장하지 않는다. 오디오 전용 HLS를 우선하고, 없으면 최저 화질의 작은 구간을 순차적으로 받아 음성만 추출한다. 성공·실패·중단 경로에서 원본 영상 임시 조각을 정리한다. 다운로드 누적량과 디스크의 순간 최대 사용량은 따로 보고한다.

오디오도 작은 처리 단위로 전사·체크포인트를 저장한 뒤 제거할 수 있도록 한다. 모델은 한 작업 안에서 재사용하고, 작은 조각마다 다시 로딩하지 않는다. 끝나지 않은 조각과 완료 원문의 서명이 다를 때만 해당 부분을 다시 처리한다. 전사·메타데이터가 원자적으로 저장된 것을 확인하기 전에 오디오를 삭제하지 않는다.

참고로 모노 16kHz 16비트 PCM은 시간당 약 115MB다. 이것은 보관 WAV의 산술값이며 원본 다운로드 용량이 아니다. 13시간 VOD의 오디오를 전부 계속 보관하면 약 1.5GB가 되므로, VOD 단위 삭제만 하는 것보다 완료 조각을 정리하는 구현이 낫다. 기존 ASR 스크립트의 WAV 의존 재개 방식부터 보완해야 한다.

디스크 부족·GPU 사용 불가·모델 환경 오류는 명시적인 준비 실패로 기록한다. 다른 ck-local 화면 준비와 GPU 작업을 무제한 병렬 실행하지 않는다. 동일 VOD 중복 작업을 막고 중단 신호를 자식 프로세스까지 전달한다. 재시도 횟수와 타임아웃은 실행 보호용이며 자료의 진위나 경기 존재를 판정하는 규칙으로 사용하지 않는다.

| 화면에서 읽은 명단·KDA를 ASR 오독이 덮음 | 준비 모듈은 경기값을 쓰지 않음. 충돌은 재확인 단서로 남기고 기존 필드 보호 유지 |
| `몇 개 빵`을 `몇 판`으로 오인 | 질문과 답변을 함께 제공. 단위·조건이 불명확하면 비움 |

| 펀딩을 새로운 이벤트 종류로 저장 | 기존 분류와 구별되는 보상 맥락으로 기록. 이번에 DB 종류를 추가하지 않음 |
| 기존 이벤트와 새 음성 판단이 충돌 | 저장 거부·검수 보호 결과를 확인하고 근거와 교정 질문을 남김. 우회 SQL·별도 이벤트 중복 생성으로 해결하지 않음 |
| 지도에 없는 시작·게임 중 조율을 놓침 | 기존 전체 화면 탐색 유지. 원문 시간창을 지도 라벨만으로 잘라내지 않으며 전체 전사 검색·추가 범위 열람 제공 |
| 긴 원문이 생각보다 비용을 많이 늘림 | 중복·진행 로그·같은 자료 재출력부터 줄임. 전송 범위·실제 사용량을 기록하고 조용한 원문 탈락 대신 페이지·재개 사용 |

## 11 구현 순서와 변경할 파일

1. **독립 준비·읽기 기능을 구현한다.** `scripts/ck-listen/`에 전사 준비·캐시·원문 패킷·상태·정리 기능을 둔다. 공용 ASR 변경이 필요하면 기존 선택 구간 호출의 입력·출력과 재개 동작을 회귀 검증한다.
2. **실험 호출과 기록 연결을 만든다.** `scripts/ck-listen.mjs`에 새 하위 명령을 연결하고, 기존 `--at` 호출을 그대로 시험한다. `ck:local --finish`에 선택적인 열람 기록 입력을 연결하되 새 분류 로직은 넣지 않는다.
3. **같은 VOD로 실제 분량·품질·비용을 비교한다.** 기존 성훈 전사의 근거 사례와 새로 확보한 연속 준비 구간을 구별해 검사한다. 기존 55분 부분 표본을 연속 30분 준비 창으로 간주하지 않는다.
4. **동작하는 명령만 스킬에 넣는다.** ck-local 본문에는 필수 열람 위치·판단 범위·실패와 재개·끄기 방법만 추가하고, 긴 사용법은 참조 문서 한 곳에 둔다. ck-research의 기존 선택 구간 안내와 충돌을 해소한다. 오래된 ck-context 실험 스킬을 운영 경로로 재사용하지 않는다.
5. **기능 설정을 읽는 실행 연결을 추가한다.** 자동·백필의 LoL 경로와 수동 조사에서 같은 설정을 사용한다. 준비는 기존 직렬 작업 안에서 실행하고 매번 재전사하지 않는다. FC 전용 흐름과 타이머 일정은 그대로 둔다.
6. **소수 실제 조사에서 사용한다.** 새 기능을 켠 조사와 기존 사용량을 비교해 유지·범위 조정·비활성화를 판단한다. 기존 `done` VOD를 전부 자동 재조사 대상으로 바꾸지 않는다.

설정은 프로젝트 로컬의 **단일 기능 설정**을 사용하며 값은 `on/off`로 한다. 기존 설정 체계를 확인해 한 곳에 두고, 자동·백필·수동이 서로 다른 기본값을 갖지 않게 한다. 설치 직후 검증 전에는 `off`, 시험 대상으로 켰을 때는 원문 열람이 필수다. 실제 CLI와 위치는 구현 완료 후 사용 안내에 반영한다. 아직 존재하지 않는 끄기 명령을 현재 가능한 명령으로 적지 않는다.

채택 판단은 “분류 공백이 줄고 잘못된 확정이 늘지 않는지”, “기존 경기·필드 품질이 유지되는지”, “재확인 왕복과 전체 사용량 증가를 감수할 가치가 있는지”로 한다. 고정 정확도·확인 횟수 합격선을 매 VOD의 저장 조건으로 옮기지 않는다. 단순히 모델이 빨리 돌거나 빈칸을 더 채웠다는 이유로 품질 향상이라고 보고하지 않는다.

사용 후 비용이 크면 먼저 매 판 겹친 원문, 새 세션의 불필요한 재출력, 과도하게 넓은 시작 창을 조정한다. 조율 누락이 크면 준비 구간을 넓히고 질문·답변이 끊기는 위치를 고친다. 유용성이 없으면 기능을 끈다. 새 로컬 판단 모델 도입은 별도의 근거가 생겼을 때 다시 검토한다.

## 13 끄기와 삭제

첫 중단 수단은 **신규 음성 맥락 기능을 off로 바꾸는 것**이다. 준비 작업과 필수 읽기 의무가 함께 해제돼야 한다. 이후 기존 ck-local 조사와 선택 구간 `ck:listen --at`이 정상 동작하는지 확인한다. 이미 진행 중인 음성 작업은 체크포인트를 보존하고 안전하게 종료한다.

완전히 제거할 때는 신규 모듈, 진입점 분기, 실행기의 선택 연결, `--finish`의 선택 입력, 스킬의 추가 절차와 해당 설정만 제거한다. 패키지의 `ck:listen` 명령 자체와 공용 ASR 환경·기존 FC 호출은 삭제하지 않는다. 다른 작업이 섞인 파일 전체를 예전 버전으로 되돌리지 않는다.

전사 캐시는 실제 경기 판단 근거로 채택한 원문과 출처를 별도 근거 산출물에 보존한 뒤 정리한다. 저장 기록이 참조하는 파일을 먼저 삭제해 검토할 수 없게 만들지 않는다. 임시 영상·미채택 오디오와 근거 원문은 삭제 대상을 구별한다.

기능을 꺼도 이미 저장된 분류·시리즈 연결은 자동으로 되돌아가지 않는다. 정정이 필요하면 근거와 영향받는 경기·이벤트를 특정해 기존 교정 경로로 처리한다. 도구 삭제를 이유로 경기 기록이나 scan 이력을 일괄 삭제하지 않는다.

## FC 백필 연결 (2026-10-13)

FC 백필(`ck-backfill.sh --game fconline`, 스킬 fco-match-context)에도 같은 준비를 연결했다. 스위치는 롤과 하나다(`ck:listen config`).
매일 FC API 맥락 조사(`ck-auto.sh --fc`)에는 여전히 연결하지 않았다.

- **전체 준비**: FC VOD 3개 실측에서 FC 구간이 91~94% — 구간만 골라도 줄지 않아 VOD 전체를 전사한다. 전사 캐시는 VOD 단위라 롤·FC 가 공유한다.
- **필수 열람**: FC 구간(`fc.json` blocks)마다 시작 전 대화 — 첫 구간 앞 30분, 다음 구간은 직전 구간 끝부터. 행사·시리즈 결론은 그 범위를 읽은 뒤.
  롤처럼 경기 사이 대화 전부를 의무로 두지 않았다 — FC VOD 는 경기가 11~19개라 사실상 전체 원문이 된다.
- **기록**: `fco:context scan --listen-read` → `raw.fco_scan.transcript_read`·`signals:asr`. 롤 `ck:local --finish` 와 같은 함수(`scanListen`, core.mjs).
  경기별 발언은 `apply` 근거 `kind:"audio"`(0032) — 화면 경기도 `fcs:<VOD>@<초>` 로 받는다. 마이그레이션 없음.
- **유지한 규칙**: 닉네임·스코어는 결과 화면이 정본. `best_of` 는 화면·공지 근거만 — 음성 발언은 근거로만 건다.

## 준비 실패 두 가지 수정 (2026-10-13)

실측: 롤 자동 조사 아침 회차 음성 준비 10건 중 8건이 "GPU 잠금"으로 즉시 실패(작업자 3개가 서로 부딪힘), 2건은 VOD 끝 조각에서 멈췄다
(209576017 "Truncated audio 270→269.27초", 205094477 "불완전한 ASR 응답"). 실패한 세션은 음성 없이 조사됐다.

- **잠금은 기다린다** — `flock -n` → `flock -w`(기본 3600초, `CK_LISTEN_LOCK_WAIT_SECONDS`). 기다리는 중에도 SIGINT/SIGTERM·스위치 off 로 바로 끝난다.
  대기 시간은 `sessions[].lock_wait_seconds`. 받아쓰기는 여전히 한 번에 하나라, 자동 작업자 3개는 받아쓰기만 줄을 서고 조사 세션은 병렬로 돈다.
- **1초 미만 부족은 무음으로 채운다** — 끝 조각의 소리가 HLS 시간축보다 짧은 경우. 채운 길이는 `pieces[].padded_seconds` 에 남긴다. 1초 넘게 짧으면 그 조각만 실패다.
- **조각 하나의 실패로 전체를 멈추지 않는다** — 예전엔 ASR 이 뜬 뒤의 실패가 남은 조각을 전부 중단했다(분할 VOD 는 뒤 파일이 통째로 빠질 수 있었다).
  지금은 실패를 `failures` 에 남기고 다음 조각으로 간다. 열지 못한 분할 파일은 그 파일만 건너뛴다. 멈추는 경우: ASR 프로세스가 죽음 · 연속 3조각 실패.
- 실행기 문장: 준비 종료 코드가 실패여도 `coverage` 는 읽는다(롤·FC 공통). FC 시험 1에서 "준비 실패"를 "원문 없음"으로 읽고 건너뛴 일이 있었다.

## 영상 조각 간격 시험 (2026-10-13)

음성 준비 시간의 대부분은 인식(2시간 VOD 32초)이 아니라 HLS 세그먼트 받기였다(같은 VOD 약 15분).
`soop-http.mjs` 의 vod-archive 간격 700ms 는 **요청 시작 사이의 최소 간격**이다(전송 시간이 그 안에 포함된다).
같은 VOD(207724625)를 700ms 로 받은 조각당 시간이 0.697초 — 전송이 간격보다 짧아 **간격이 병목**이었다.

- `SOOP_HLS_INTERVAL_MS` — 영상 서버 간격만 따로 조절한다(`SOOP_PACE` 는 게시판 등 다른 API 간격까지 바꾼다). 호출마다 읽는다.
- 차단 감지: 세그먼트·재생목록이 2xx 가 아니면 `HLS 세그먼트|재생목록 HTTP <코드>` 로 실패한다(예전엔 오류 본문을 영상으로 이어붙였다).
- 자동 감속: 403·429·503 이면 준비를 즉시 멈추고 `.local/ck-listen/hls-block.json` 을 남긴다. 1시간 동안 음성 준비는 받지 않고,
  그 뒤에도 사람이 표시를 지울 때까지 700ms 로만 받는다. 조각별 `segments`·`download_seconds`, 세션 `hls_interval_ms` 를 남긴다.
- 시험 순서(동시 다운로드 수는 늘리지 않는다): 700 기준 → **500 으로 VOD 하나 끝까지** → 오류·누락이 없으면 **300 으로 여러 VOD 연속**.
  비교: 조각당 시간, HTTP 오류, 전사 누락 구간. 차단 의심 응답이면 중단·700 복구·충분히 대기.
- 결과: 500ms 로 207724625(4.5시간, 조각 2,741개) 전체 — 오류 0·누락 0, 조각당 0.500초(700ms 때 0.697초), 앞·뒤 1/4 속도 차 없음(0.500→0.501).
  받기 1,369초(700ms 였다면 약 1,910초). 종료 코드 2 는 조각 경계 반올림 틈(0.007초·0.003초)이었다 → 한 샘플이라도 모자라면 무음 채움,
  0.05초 미만 틈은 누락이 아님(`GAP_TOLERANCE` — 완료 판정과 같은 값).
