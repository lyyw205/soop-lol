# 시드 명단

```bash
cp seed/streamers.example.json seed/streamers.json   # 손으로 채운다
npm run seed -- seed/streamers.json --dry-run        # 무엇이 바뀔지만 본다
npm run seed -- seed/streamers.json                  # 실제로 넣는다
```

같은 파일을 다시 돌려도 안전하다. `slug` 가 이미 있으면 갱신한다.

## 명단·계정을 어디서 얻나 (2026-08-09 확인)

### ★ SOOP 멸망전 FA 등록 — 계정 매핑의 정답 경로

스트리머가 **대회 참가 신청 때 본인 손으로 입력한 라이엇 ID** 다. SOOP 공식 데이터이고,
제출 시점에 SOOP 이 Riot 으로 실존 검증까지 한다. 전적 사이트도 위키도 아니다 —
`evidence.source = 'self_declared'` 로 쓰기에 충분한 유일한 경로였다.

```bash
curl -s -X POST https://gpapi.sooplive.com/api/v1/bjmatchfa/fa/list \
  -H 'Content-Type: application/json' \
  -d '{"orderType":"point_desc","filter":[],"searchBjNick":"","minPoint":0,"maxPoint":1000,
       "positionIdx":"","pageNo":1,"perPageNo":500,"seasonIdx":27}'
```

- `seasonIdx` 가 대회 회차다 (27 = 2026 LoL 멸망전 with Gen.G). 사람이 보는 페이지는
  `https://bjmatchfa.sooplive.com/fa/27` — 이게 `evidence.url` 이 된다
- 응답의 `gameNick` / `totalGameNickList` 가 라이엇 ID. 부계정까지 들어 있다
- `userId` 가 SOOP 채널 아이디, `userNick` 이 표시명
- **2026-08-09 기준 418명**이 등록돼 있다. 명단 확장의 1차 소스다

### SOOP 닉네임 → 채널 아이디

```
https://sch.sooplive.co.kr/api.php?m=bjSearch&v=3.0&szKeyword=<닉네임>
https://chapi.sooplive.co.kr/api/<id>/station     # 교차 확인용
```

### ⚠️ 반드시 Riot API 로 되짚어라

SOOP 표기가 라이엇 정본과 어긋난다. 실제로 겪은 것:
- 태그에 공백이 들어간 채 저장돼 있다 — `#산 본`, `#팀 운`
- 게임명 공백 수가 다르다 — SOOP `TT TT` ↔ 라이엇 `TT  TT`(두 칸)
- 48건 중 4건은 아예 해석되지 않았다 (계정 삭제·개명 추정)

그래서 `scripts/seed-streamers.ts` 는 `riot_id` 를 받아 **account-v1 으로 해석한 결과**를
정본으로 쓴다. 해석 실패한 건 넣지 않는다.

### ❌ 통하지 않은 경로 (다시 시도하지 말 것)

| 경로 | 결과 |
|---|---|
| 대회 로스터 이름을 라이엇 ID 로 간주 | **위험.** `스맵임`은 lv1 언랭 남의 계정, `뀨삐`는 공백 정규화로 `뀨 삐`가 잡힌다 |
| 뉴스·나무위키 | 인게임 ID 를 안 싣거나, 실어도 태그가 없다 |
| SOOP 채널 공지 게시판 | 스트리머 본인이 라이엇 ID 를 적어두지 않는다 (40명 표본에서 0건) |
| 전적 사이트 | 지침상 금지 (§11-9). ToS 위반이고 Production Key 심사 감점 |

### 승패를 어떻게 아는가

VOD 제목은 대진만 주고 승패를 안 준다. 대신 **진출 경로가 곧 결과**다.
이건 추측이 아니라 유도이고, 생성 스크립트가 **모순을 검사한 뒤에만** 시드를 만든다.

**더블 엘리미네이션** (`scripts/build-meljang-2026.mjs` — 2026 with Gen.G):
UB 1R 의 승자만 UB 2R 에 나타나고 패자는 LB 1R 로 떨어진다.
이미 2패한 팀이 다시 나오거나 승자가 대진에 없으면 거기서 멈춘다.

**GSL 조별 + 4강 + 결승** (`scripts/build-meljang-2026-s1.mjs` — 2026 시즌1):
```
승자전 = 1경기 승자 vs 2경기 승자        → 1·2경기 승자가 정해진다
패자전 = 1경기 패자 vs 2경기 패자        → 위와 어긋나면 대진 복원이 틀린 것 (검사)
최종전 = 승자전 패자 vs 패자전 승자      → 승자전·패자전 승자가 정해진다
4강 진출 = 승자전 승자(조1위) + 최종전 승자(조2위)
4강 대진 = A조1위 vs B조2위 / B조1위 vs A조2위 (크로스) → 조 순위 교차검증
결승 대진 = 4강 두 경기의 승자
```
13경기 중 **12경기가 유도**되고, 남는 결승 승자 하나만 언론으로 독립 확인한다.

### 로스터 닉네임 → 라이엇 계정 (근거 있는 유일한 경로)

나무위키 로스터의 닉네임을 **라이엇 ID 로 간주하면 안 된다**(아래 ❌ 표 참고).
대신 두 단계로 되짚는다:

1. SOOP 검색 API 로 닉네임 → **방송국 아이디**. 정확히 일치하는 게 하나일 때만 채택한다
   ```
   https://sch.sooplive.co.kr/api.php?m=bjSearch&v=3.0&szKeyword=<닉네임>&nPageNo=1&nListCnt=10
   ```
2. 그 방송국 아이디로 **FA 등록**(본인이 직접 입력한 라이엇 ID)을 찾는다. 없으면 넣지 않는다.

2026 시즌1 로스터 40명 중 **39명이 이렇게 해결**됐다 (10명은 이미 등록돼 있었고 29명이 신규).
남은 1명(`R0se`)은 닉네임이 바뀌어 방송국 아이디를 특정하지 못해 **뺐다**.

이 단계가 왜 필요한지는 실제로 걸린 예가 말해준다 —
`레이닝1`은 `김레인♥`이 아니고, `해기_`는 `하쿠^^`가 아니다. 닉네임만 봤으면 둘 다 틀렸다.

### 나무위키 인물 문서가 신원 키다 (`streamer.namu_page`)

위 두 단계로도 안 풀리는 표기가 많다. 옛 회차 로스터는 표기가 제각각이라서다 —
`이상호` · `BJ이상호` · `탈론장인이상호`. SOOP 검색으로는 못 가른다.
`이상호` 를 찾으면 `lshooooo(이상호)` 와 `tlshtkw(이상호^)` 가 같이 나오고,
`BJ이상호` 를 찾으면 **아예 다른 두 사람**(`wer00073`, `juhan0915`)이 나온다.
"유일할 때만 채택" 규칙이 이걸 전부 거부했고, **그 판단 자체는 옳았다** —
하나를 골랐으면 남의 전적이 됐다.

그런데 나무위키 로스터 셀은 인물 문서로 링크돼 있고, 위 세 표기가 전부 `/w/이상호`
하나로 링크된다. **출처가 직접 동일인이라고 말하는 것**이다. 닉네임 유사도 추측과 다르다.

```bash
npm run link:namu              # 붙인다
npm run link:namu -- --dry-run # 뭐가 붙을지만 본다
```

붙이는 규칙:

- **이미 확인된 스트리머에만** 붙인다. 표기 → 방송국 아이디 → 우리 DB 로 확정된
  사람의 문서만 기록한다. **문서에서 사람을 만들어내지 않는다.**
- 로스터에 이름이 오른 표기만 본다. 본문 아무 데나 걸린 링크는 쓰지 않는다.
- 충돌이면 **양방향 모두** 거부하고 보고한다 —
  한 문서를 두 스트리머가 다투는 경우(`UNIQUE` 인덱스)와,
  한 스트리머가 두 문서를 갖게 되는 경우 둘 다다.
  뒤쪽을 빼먹었다가 물렸다: 61건을 붙였는데 남은 건 58행이었고, 나중에 온 표기가
  앞의 문서를 조용히 밀어냈다. 밀려난 쪽이 맞았는지는 알 수 없었다.

빌더는 로스터 표기를 볼 때 **문서 링크를 SOOP 검색보다 먼저** 본다.
이걸로 `이상호` 는 7회차에서 13회차가 됐다. 풀린 건 이상호만이 아니다 —
`클리드` · `#민잔디/민찬기/민.찬.기` · `BJ.정윤종/정윤종..` · `염보성/A-염보성/찌개` ·
`하이요♥/하이요__` · `스맵` · `애디충` · `칸` 등 **50개 표기**가 대상이다.

## 규칙

1. **손으로 만든다.** op.gg·lolsoop·덥덥미를 긁어오지 않는다 —
   ToS 위반이고 Riot Production Key 심사에서도 감점이다 (docs/PLAN.md §11-9).
2. **근거 없는 계정은 적지 않는다.** `evidence.url` 이나 `evidence.note` 가 비면
   스크립트가 거부한다. 부계정 오노출은 실제 분쟁이 된다 (§11-2).
3. `confidence` 는 정직하게 매긴다.
   - `verified` — 본인이 공개적으로 밝혔고 그 출처가 남아 있다
   - `likely` — 정황은 강하지만 본인 확인은 없다
   - `unverified` — 제보만 있다
   이 값은 화면에 그대로 노출된다. 애매한 걸 `verified` 로 올리지 않는다.

| 2026 시즌1 / with Gen.G | 8 / 8 | 4 / 2 | 39 / 40 | 13 / 14 | 73 | 2,712 | 339 |
| **합계** | **420** | **260** | **499** | **473** | **776** | **7,799** | **999** |

2025 시즌2·2026 두 회차의 참가팀이 8 인 것은 예선 명단을 못 써서다 —
아래 '단, 그 표가 이 대회의 판인지 먼저 확인한다' 를 볼 것.

**옛 회차일수록 조우가 적다.** 경기는 다 들어갔는데 선수를 못 붙였기 때문이다 —
2018~2020 로스터는 SOOP 닉네임이 아니라 실명·옛 닉네임이라(`김민교`, `이상호`, `서리`)
지금 SOOP 검색으로 해석되지 않고, 해석돼도 FA 등록(2026년 것)에 없으면 계정이 없다.
경기 기록은 남아 있으므로 나중에 그 사람 계정이 붙으면 재파생으로 살아난다.

### 승패 근거는 회차마다 다르다

| 방식 | 회차 | 근거 |
|---|---|---|
| GSL 진출 경로 유도 + 나무위키 대조 | 2025 시즌1·2, 2026 시즌1 | 두 곳이 전건 일치 |
| 더블 엘리미네이션 정합성 + 나무위키 | 2026 with Gen.G | 두 곳이 전건 일치 |
| 나무위키 결과표만 | 나머지 14회차 | ⚠ **한 곳뿐** (풀리그라 유도 불가) |

풀리그 회차는 근거가 **한 곳뿐**이다. 라운드로빈은 이겨도 져도 남은 경기를 다 치러서
진출 경로에서 결과가 나오지 않는다. 그 사실이 각 시드의 `//승패근거` 에 그대로 적힌다.

### 전적은 두 종류다 — 팀 조우와 1:1 맞라인

한 경기에서 한 사람은 **상대 팀 5명 전부와** 조우가 맺힌다. 그중 같은 라인에서
맞붙은 한 명이 1:1 맞라인이다. 둘은 다른 사실이라 따로 센다:

- **팀 상대전적** — 상대편에 있었던 전부. "그 사람 팀을 이겼나"
- **1:1 맞라인** — 같은 포지션끼리. "그 사람을 직접 이겼나"

맞라인을 가르려면 포지션이 필요하고, 포지션은 나무위키 참가팀 표(`TEAM | TOP | JGL |
MID | BOT | SUP`)에서 읽어 `roster_positions` 로 싣는다. 이게 없던 동안 대회 맞라인은
**0건**이었다 — 커스텀 큐(0)라 맞라인 대상에서 빠졌고 포지션도 안 넣고 있었다.

대회 포지션은 Riot 추론값이 아니라 주최측이 발표한 로스터라 오히려 단단하다.
다만 **'로스터상 포지션'이지 '그 판의 실제 포지션'은 아니다.** 포지션을 모르는
대회 경기는 여전히 맞라인으로 세지 않는다(§11-10 — 애매하면 판정하지 않는다).

### 결승 승자는 반드시 두 곳에서 확인한다

나무위키의 회차별 문서와 역대 우승 표가 **실제로 어긋난 적이 있다** —
2025 시즌2 문서를 요약하면 "jJ이야 우승"으로 읽히는데, 역대 표와 검색 결과와
결승 당일 공식 VOD 클립(`[클립]깐숙 인터뷰 결승`, 깐숙은 킹깐만 소속)은 전부 킹깐만이다.
세트 스코어의 좌우가 뒤집혀 읽히기 쉽다. 한 곳만 보고 적으면 우승팀을 반대로 쓴다.

그래서 **요약 모델을 거치지 않는다.** 나무위키는 원문 HTML 을 그대로 주므로
`scripts/lib/namu.mjs` 가 표를 직접 읽는다.

교차 확인이 잘 되는 곳:
- 공식 VOD 제목 — `[클립]멸망전 2모3촌 최종우승 !`, `으딜나대나 팀 우승 트로피 세레머니`
- 결승 당일·다음날 언론 기사
- 나무위키 참가팀 표의 **행 배경색** (우승/준우승/4강/8강 범례) — 2025 시즌1 우승을 이걸로 확인했다

### ⚠️ 문서 제목은 회차마다 확인한다 — 제목만 보고 "없다" 하지 말 것

`2014 LoL 멸망전 시즌1` · `2015 LoL BJ멸망전` 같은 패턴을 돌려보고
**2014·2015·2017 은 나무위키에 없다**고 두 번 단언했다. 틀렸다. 실제 제목은:

| 회차 | 문서 제목 |
|---|---|
| 2014 | **천하제패 BJ 멸망전** |
| 2015 | **멸망전 LoL 2015** |
| 2017 | **멸망전 LoL 2017** |
| 2019 시즌2 | **KT 10GiGA 멸망전 LoL 2019시즌 2** |
| 2019 시즌3 | **KT 5G 멸망전 LoL 2019시즌 3** |
| 2020 앙코르 | **2020 LoL BJ멸망전 앙코르 이벤트전** |

2019 두 회차는 **스폰서명이 제목 앞에 붙어** 있어 한참 못 찾았다.

**회차 목록을 얻는 확실한 방법**: `멸망전/리그 오브 레전드` 문서에서
`/w/...` 링크를 전부 뽑는다. 역대 회차 문서가 거기 다 걸려 있다.

```bash
curl -s -A "Mozilla/5.0" "https://namu.wiki/w/멸망전/리그 오브 레전드" \
  | grep -oE "href=./w/[^\"']+" | ...
```

패턴 몇 개 돌려보고 "없다" 고 단정하지 않는다 — 실제로 두 번 틀렸다.

### 결과표 형식이 일곱 가지다

회차마다 표 모양이 달라서, 하나만 읽으면 그 회차가 통째로 비어 보인다.
지금 받는 형식:

| # | 모양 | 쓰는 회차 |
|---|---|---|
| 1 | `팀A \| 2 \| 1 \| 팀B` | 다전제 결과표 (2021~2026) |
| 2 | `팀A \| 패 \| 승 \| 팀B` | 단판 풀리그 (2022~2023) |
| 3 | `1 \| 3 \| 팀A \| 팀B` | 결승 배너 (앞에 날짜가 온다) |
| 4 | `팀A \| 승 \| 팀B \| 패` | 2021 이전 '팀명/결과' 표 |
| 5 | `팀A \| O \| X \| 무 \| 팀B \| X \| O \| 무` | 2014~2020 세트별 O/X 표 |
| 6 | `팀A \| vs \| 팀B` + `패 \| 0 \| RESULT \| 2 \| 승` | 2020 앙코르 |
| 7 | `구분 \| 1경기 \| … / 팀 \| … / 승리팀 \| …` | 2019 시즌3 8강 (행렬형) |

7번은 팀명이 `<br>` 로 쪼개져 여러 줄이 된다('기바견' + '분양중'). **문서에 실제로
적혀 있는 팀 이름과 맞을 때까지만** 되붙인다 — 조각을 임의로 이으면 없는 팀이 생긴다.

형식을 추가할 때는 **기존 회차 파싱 결과를 스냅샷과 대조**한다. 새 패턴이 옛 회차를
조용히 망가뜨리면 알 방법이 없다. 실제로 두 번 걸렸다(승패 기호 `○ ×`,
순위표의 `vs 라스투댄스`·`+4`·`2 : 0` 이 팀명 자리로 들어왔다).

### 2018년 이전 회차는 무승부가 있다

조별리그가 **2세트제**라 1:1 로 끝나는 경기가 회차당 4건씩이다.

- **세트 단위로는 무승부가 없다** — 각 세트는 누군가 이긴다
- **시리즈로 접었을 때만** 무승부가 생긴다

집계에서 이걸 패로 세면 그 회차 전적이 통째로 틀어진다. 승/무/패 세 갈래로 센다.
승률의 분모에서도 무승부를 뺀다 — 1승 1무는 50% 가 아니라 100% 다. 진 게 아니다.
대신 화면에는 `1승 1무` 로 무승부 수를 항상 같이 적는다.

또 이 회차들은 표에 **세트별 O/X** 가 있어 어느 세트를 이겼는지까지 알 수 있다.
다른 회차는 시리즈 스코어만 있어 세트 순서를 우리가 지어내야 하지만, 여기는 진짜다.

### 순위(우승·준우승·4강·예선탈락)는 어디서 오나

나무위키 참가팀 표는 순위를 **텍스트가 아니라 행 배경색**으로 적는다. 표 위 범례
(`■우승 ■준우승 ■4강 ■8강 ■2차예선 탈락`)의 색과 각 행의 배경색을 맞춰 읽는다.

대진에서 유도하지 않는 이유는 라운드 이름이 백 가지가 넘어서다 —
`8강 A조 승자전` · `풀리그 3일차 B조 5경기` · `10강 A조 재경기`. 게다가 풀리그
회차는 '어디까지 갔나' 가 대진에 안 드러난다. 색은 출처가 직접 매긴 순위다.

색이 없는 회차(2026 세 회차)는 대진의 `결승`·`4강` 라운드에서 우승·준우승·4강만
유도한다. **둘 다 안 되면 비워 둔다** — 뱃지가 안 보이는 게 틀린 순위가 보이는 것보다 낫다.

| 회차 | 순위 확보 |
|---|---|
| 2021 시즌1·시즌2·앙코르, 2022 두 회차, 2023 두 회차, 2024·2025 시즌1 | 나무위키 색 |
| 2025 시즌2, 2026 시즌1·with Gen.G | 대진에서 유도 (우승·준우승·4강만) |
| **2018·2019·2020 일곱 회차** | ❌ 색도 없고 결승 라운드 표기도 없다 |

요약 카드는 **순위를 모르는 대회를 합계에 섞지 않고**
"순위를 확인하지 못한 대회 N회는 세지 않았습니다" 로 따로 적는다.

### 예선에서 떨어진 팀도 전부 적재한다 (경기가 0건이어도)

멸망전은 예선 참가팀이 30~40개인데 본선에 오르는 건 8~12개다.
한때 **결과표(=본선)에 나온 팀만** 적재했다. 그러면 예선에서 떨어진 회차가 통째로 사라진다.

이걸로 실제로 틀렸다. 이상호는 2021 시즌2(`(전)수찬`)와 2021 앙코르전(`하마생명e스포츠`)에
나갔는데, 두 팀 다 예선에서 떨어져 결과표에 없다는 이유로 우리 화면에서는
**출전하지 않은 사람**이 됐다. 0경기는 '기록 없음' 이 아니라 **'떨어졌다'** 다.
안 적으면 우리가 모르는 게 아니라 없었던 일이 된다.

나무위키 참가팀 표는 `1차예선 탈락` 까지 순위를 매겨 주므로 근거도 있다.
그래서 참가팀 표의 팀은 결과표에 나오든 안 나오든 **전부** 넣는다.
경기가 0건인 팀은 조우를 안 만들 뿐이고, 로스터는 프로필에 남는다.

손으로 적은 `season.teams`(본선 명단)가 있어도 참가팀 표를 **같이 읽는다**.
손으로 적은 쪽이 언제나 이기고, 거기 없는 팀만 표에서 더한다.
예전엔 손으로 적었으면 표를 아예 안 봐서, 2025 시즌1 은 나무위키에 40팀 순위가
있는데도 8팀만 들어갔다.

#### ⚠️ 단, 그 표가 이 대회의 판인지 먼저 확인한다

회차에 따라 문서의 '참가팀' 표가 **본선과 전혀 다른 팀 집합**이다.

| 회차 | 본선 8팀 중 표에 있는 팀 | 표의 순위 | 판정 |
|---|---|---|---|
| 2025 시즌1 | **8 / 8** | 39팀 | 같은 판 → 합친다 |
| 2025 시즌2 | 1 / 8 | 없음 | 확인 불가 → **안 쓴다** |
| 2026 시즌1 | 2 / 8 | 없음 | 확인 불가 → **안 쓴다** |

2025 시즌2·2026 시즌1 은 본선이 드래프트로 재편돼 예선 팀명이 남지 않는다.
이걸 모르고 합쳤다가 이상호를 본선 팀 `왜자꾸이기는건데` 에서 예선 표기 `바밤바*` 로
옮겼고, **한 대회 한 팀 제약(PK) 때문에 본선 경기가 성적에서 통째로 사라졌다.**
예선을 살리려다 본선을 지운 셈이다.

그래서 합치기 전에 근거를 둘 중 하나 요구한다 —
**본선 팀이 표에 절반 이상 있거나, 표가 순위를 매기거나.**
둘 다 없으면 그 표가 무엇인지 우리가 모르는 것이므로 쓰지 않고 이유를 로그에 남긴다.

한 겹 더: 모든 로스터 배정은 `place()` 하나를 지난다.
**한 대회에서 한 사람은 한 팀이다**(`event_team_member` PK 가 그렇다).
이미 배정된 사람이 다른 팀에 또 나오면 먼저 것을 지키고 **반드시 보고한다** —
조용히 덮어쓰면 하필 경기를 가진 쪽이 지워져도 아무도 모른다.

#### 대회 도중 이름을 바꾼 팀은 하나로 합친다

참가팀 표에 `togings ▶ 토없기왕` 처럼 적힌다. 두 이름이 **결과표에도 둘 다** 나오면
한 팀이 두 팀으로 쪼개지고, 로스터는 한쪽에만 붙어(한 대회 한 팀 제약) 다른 쪽 경기는
아무의 전적도 아니게 된다. 2019 시즌1 의 `kimmingyo` 가 7경기 중 2경기만 인정받고 있었다.
같은 팀이라고 출처가 직접 말했으므로 앞 이름으로 합친다. 전 회차에 이 경우는 1건이다.

화면은 0경기의 이유를 **세 가지로 갈라 적는다** — 뭉뚱그리면 예선에서 떨어진 사람이
데이터 결함처럼 보인다:

| 상태 | 문구 |
|---|---|
| 순위 = 예선 탈락 | 예선에서 탈락해 본선 경기가 없습니다 |
| 순위 미상 | 예선에서 탈락했는지, 우리가 경기를 못 붙였는지 확인하지 못했습니다 |
| 본선 순위가 있는데 0경기 | 명단에는 있으나 경기 기록을 붙이지 못했습니다 (우리 쪽 구멍) |

⚠️ 팀 이름이 `togings ▶ 토없기왕` 처럼 둘 다 적힌 경우, 결과표에 나온 표기가 있으면
그쪽으로 걸고 없으면 **바꾼 뒤 이름 하나만** 쓴다. 양쪽 다 넣으면 한 팀이 두 팀으로
불어나 참가 횟수가 부풀려진다.

### 세트 순서는 우리가 만든 것이다 — 화면에 세트 이력을 두지 않는다

출처(나무위키 결과표)가 주는 건 **시리즈 스코어뿐**이다 — `2:1`. 세트별로 누가
이겼는지는 없다. 그래서 적재할 때 승자 세트를 앞에 몰아 넣는다. 지금 DB 의 모든
2:1 경기는 예외 없이 승·승·패 순이다. **합계는 맞고 순서는 지어낸 것이다.**

한때 라이벌 펼침 목록에 '매치 / 세트' 탭을 뒀다가 지웠다. 이유가 둘이다:
- `2:1` 이 이미 같은 정보를 담고 있어 **길이만 세 배**가 된다
- 무엇보다 '1세트 승 / 2세트 승 / 3세트 패' 는 **모르는 걸 아는 척**하는 표시다

`match.series_game_no` 컬럼은 남긴다 — 한 시리즈 안에서 세트를 구분하는 키로
필요하고, `(series_id, series_game_no)` 유니크 인덱스가 판수 부풀림을 막는다.
컬럼 주석에 "실제 순서가 아니다" 를 박아 뒀다(마이그레이션 0009).

나무위키 **본문**에는 세트별 WIN/LOSE 가 있는 회차가 있다. 그걸 긁어오면
세트 이력이 뜻을 갖게 되고, 그때 화면에 되살리면 된다.

### 경기 날짜가 원본에 없으면 그렇다고 적는다

한동안 2018~2020 일곱 회차의 **모든 경기가 회차 시작일 하루에 몰려** 있었다.
나무위키 회차마다 날짜 표기가 달라(`2022년 4월 6일` · `날짜: 2020-3-12`) 한 형태만
읽고 있었고, 못 읽으면 조용히 시작일로 채웠기 때문이다. '마지막으로 만난 날'이 전부
틀렸다. 표기 두 형태를 다 받게 고쳐 일곱 회차 모두 실제 날짜가 들어갔다.

그래도 날짜를 못 찾는 경기가 남으면 **회차 시작일로 채우되 그 사실을 시드의
`//승패근거` 에 적는다.** 지어낸 날짜가 진짜인 척하는 게 제일 나쁘다.

### 로스터에 사람이 빠져 있어도 넣는다

계정 근거를 못 찾은 사람은 그 자리를 비운 채 경기를 넣는다. 팀 전원을 못 찾아
**로스터가 통째로 빈 팀도 그대로 둔다** — 그 팀이 나온 건 사실이고, 상대 팀 안의
'같은 팀' 조우는 여전히 성립한다. 나중에 계정이 연결되면 `seed:tournament` 를
다시 돌려 **그 사람의 조우가 되살아난다**(§11-5 재파생).

옛 회차일수록 닉네임이 바뀌어 SOOP 검색으로 해석되지 않는 사람이 많다.
근거 없이 채워 넣는 것보다 비워 두는 게 낫다.

## `seed/streamers*.json` 은 커밋하지 않는다

저장소가 공개라서다. 스트리머의 부계정 목록이 git 히스토리에 들어가면
나중에 삭제 요청이 와도 **되돌릴 수 없다.** 히스토리는 지워지지 않는다.

근거는 DB 의 `streamer_account.evidence` 에 남고, 그쪽은 `visibility` 로 숨기거나
행을 지울 수 있다. 그게 삭제 요청 경로를 살려두는 유일한 방법이다.

파일 자체는 로컬이나 비공개 백업에 보관한다.
