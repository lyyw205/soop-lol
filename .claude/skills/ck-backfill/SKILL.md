# 과거 VOD 수동 백필

사용자 요청으로만 실행한다. 화면 판독 규칙은 [ck-research](../ck-research/SKILL.md)가 정본이다.
**FC 백필(`--game fconline`)** — 넥슨 API 는 최근 30일만 주므로 그 이전 FC 경기는 VOD 결과 화면으로 채운다.
조사 세션은 [fco-match-context](../fco-match-context/SKILL.md)의 'VOD 에서 출발하기', 준비는 공용 지도 + FC 전용 판별기(fc.json),
진척 도장은 `fco_scan`(롤 도장과 따로 — 롤로 끝낸 VOD 도 FC 로는 다시 본다), 마지막 요청 기간도 게임별이다(0055).
FC 방송 채널 중 다시보기 대부분이 재생 파일 없음(구독자 전용으로 보임)인 곳이 있다 — 접근 불가로 남고 채울 수 없다.
VOD 하나의 세션과 진척 확인이 끝나면 셸이 그 VOD 의 **결과 화면 앞뒤 원본**(−2분·−1분·−20초·+20초·+1분·+2분)을 뽑아 둔다(`fco:frames --vod`) — 검수 작업대가 앞뒤 맥락을 원본으로 넘겨 보는 재료다. 실패해도 백필은 계속하고, 롤 백필에는 붙지 않는다.
화면 경기는 숨긴 채 저장되고 공개는 검수 뒤다.

**조사 세션은 기본으로 [ck-local](../ck-local/SKILL.md)이다** — VOD 마다 로컬 판별기 준비를 먼저 돌리고, 긴 VOD는 저장 경계에서 여러 세션으로 나눠 조사한다
(2026-10-01 비교 시험 결과, docs/CK-LOCAL-DETECTOR.md). 예전 방식이 필요하면 `CK_BACKFILL_SKILL=ck-research` 를 붙인다(준비도 꺼진다).
이 스킬에 결과창 탐색·경기 연결 규칙을 복사하지 않는다.

## 원리 — 진척은 VOD 도장 하나뿐

- 요청한 **기간**(KST, VOD 종료일 기준)의 목록을 매번 SOOP 에서 다시 받고, 조사 도장
  (`event_lead.raw.scan`)이 완료가 아닌 VOD 만 최신순으로 조사한다. 커서·백필 표시는 없다.
- 그래서 같은 기간을 다시 요청하면 **멈춘 곳부터** 이어지고, 자동 조사가 놓친 빈틈도 같이 메워진다.
- 완료 판정은 자동 조사와 **같은 함수**(`vodWork`, core/metrics/ck-vod-status)다. 한쪽이 끝낸 VOD 는
  다른 쪽이 다시 보지 않는다. 경기만 연결되고 조사 도장이 없는 VOD 는 미조사다.
- 저장하는 건 "마지막 요청 기간" 하나다. 진척 기록이 아니라 기간을 생략했을 때의 기본값이다.
- 기본은 기간의 VOD를 다 볼 때까지 계속 돈다. `--session-games`는 대조 시험 전 **기본 0(분할 목표 끔)**이다.
  시험 실행에서 분할 수를 지정하면 저장된 DB 요약으로 잇는다. 소량 운영 검증은 `--max-sessions 1`로 한 세션의 저장·진척 확인 뒤
  멈출 수 있다(기본 0은 제한 없음). 이 종료는 기간 완료를 뜻하지 않는다.
- 이미지 제한 시험은 `--image-limit-mib 12`로 켠다(기본 꺼짐, LoL). 8 MiB 안내 후 중간 저장하고 종료하며 12 MiB 초과 사진은 실행기가 거부한다. 차단 뒤에는 새 탐색 없이 기존 `ck:merge`로 저장·종료한다. `--vod <번호>`를 함께 주면 요청 채널·기간의 해당 VOD 하나만 조사한다.

## 실행

1. 스트리머를 확인한다. 정확한 이름·slug·SOOP 채널 ID를 쓴다. 동명이인·복수 채널이면 확인한다.
2. 이전 상태를 읽는다: `npm run ck:backfill -- status --streamer <이름>`
3. 기간을 정한다. "한 달 치" 같은 요청은 날짜로 바꿔 사용자에게 보여준다. "이어서"면 기간을 생략한다.
   오늘 이후 날짜는 받지 않는다. 와치리스트 대상의 최근 3일은 자동 조사 몫이지만, 겹쳐도 도장으로 걸러진다.
4. 백그라운드로 실행하고 로그를 전한다:
   ```bash
   scripts/ck-backfill.sh --streamer <이름> --from YYYY-MM-DD --to YYYY-MM-DD   # 새 기간
   scripts/ck-backfill.sh --streamer <이름>                                    # 마지막 기간 이어서
   scripts/ck-backfill.sh --streamer <이름> --model haiku ...                # 조사 세션만 다른 모델로
   scripts/ck-backfill.sh --streamer <이름> --game fconline --from … --to … # FC 과거 백필
   ```
   종료 코드 75 면 다른 조사(자동 포함)가 잠금을 잡고 있다. 알리고 시작하지 않는다. 대기 작업을 만들지 않는다.
   사용자가 특정 모델을 지정하면(예: "Haiku로") `--model`을 붙인다. 전역 기본 모델은 그대로 두고 이 백필의
   조사 세션에만 적용된다 — 판독 정확도가 낮아질 수 있음을 미리 알린다.
   백그라운드 종료를 기다릴 때 `pgrep -f "<패턴>"` 루프를 쓰지 않는다(자기 명령줄에 걸린다). 실행 도구의 종료 알림을 쓴다.
5. 끝나면 `status` 를 다시 읽고 보고한다: 완료·접근 불가·남은 VOD·목록에서 사라진 VOD(`missing`)와 종료 사유.
   셸 종료 코드나 모델의 완료 선언만으로 완료 수를 말하지 않는다.

## 멈추기

| 사용자 말 | 할 일 |
|---|---|
| "멈춰"·"그만" (기본) | `scripts/ck-backfill.sh --stop` — 지금 VOD 를 저장까지 마친 뒤 멈춘다 |
| "지금 당장 멈춰" | 백필 셸에 TERM(Ctrl-C). 조사 중이던 VOD 는 마지막 중간 저장 지점부터 다음에 다시 한다 |

셸이 알아서 멈추는 경우도 있다. 그대로 사용자에게 전한다:

- **진척 없음(종료 4)** — 세션이 끝났는데 남은 일(못 본 범위·실패 구간·미해결 후보)이 줄지 않았다.
  같은 VOD 에서 반복되면 원인을 보고한다. 영구적으로 못 푸는 구간이면 `scan.resolved_failed` 로 닫는다.
- **Claude 실패** — 사용량 한도·로그인 만료 등. 진척과 무관하게 멈춘다.
- **열람뿐인 반복(종료 4)** — 저장·후보 결론·남은 범위 감소 없이 열람만 이어진 세션이 연속 3회면 미완료로 멈춘다.
  백필 재실행에도 횟수가 유지된다. 원인을 해결한 뒤 `--reset-stall`로 첫 미완료 VOD만 명시적으로 재개한다.
  완료로 표시하거나 근거 없는 후보 결론으로 제한을 피하지 않는다. 정상 결과 진척은 횟수를 초기화한다.
- **목록 조회 실패·잘림** — 일부만 받은 목록으로 "기간 완료"라고 하지 않는다. 기간을 나눠 다시 요청한다.

`running` 으로 멈춘 VOD 는 와치리스트 채널이면 **자동 조사가 먼저 이어받을 수 있다**(의도한 정책).
중복이 아니라 먼저 끝낸 쪽이 도장을 찍는 것이다.
병렬 실행의 워커 채널 잠금(75)은 건너뛰고 다음 채널을 처리한다. 실행기 공통 잠금(75)은 전체 시작을 막는다.
`run.log`에는 조사 응답 요약과 `session-N.json` 원본 경로가 함께 남는다.

## 접근 불가

자식 조사가 삭제·비공개를 실제로 확인하면 잠금을 상속한 환경에서 기록한다:

```bash
npm run ck:backfill -- access --vod <번호> --status unavailable --reason "확인한 응답·근거"
```

일시 오류는 `temporary` 로 남기고 그 세션을 끝낸다(→ 진척 없음으로 멈춤). 네트워크 실패 한 번으로 영구 접근
불가를 선언하지 않는다. 사유·확인 시각은 `raw.access` 에 남고 자동 조사도 이를 존중한다.
비공개가 풀렸을 수 있어 재확인을 요청받으면 다른 조사가 없을 때 같은 잠금 아래 `--status retry` 를 남긴 뒤 다시 실행한다.
잠금 실행 예는 [운영 문서](../../../docs/CK-BACKFILL.md)를 본다.
