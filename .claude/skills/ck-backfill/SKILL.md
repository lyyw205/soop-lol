# 과거 VOD 수동 백필

사용자 요청으로만 실행한다. 화면 판독 규칙은 [ck-research](../ck-research/SKILL.md)가 정본이다.
이 스킬에 결과창 탐색·경기 연결 규칙을 복사하지 않는다.

## 실행

1. 스트리머를 확인한다. 정확한 이름·slug·SOOP 채널 ID를 쓴다. 동명이인·복수 채널이면 확인한다.
2. 이전 진행을 읽는다:
   `npm run ck:backfill -- status --streamer <이름>`
3. 수동 실행 셸을 호출한다:
   `scripts/ck-backfill.sh --streamer <이름> --limit 5 --max-video-hours 20`
   분량 지정이 없으면 5개·영상 합계 20시간이다. 20시간 초과 VOD는 단독 선택된다.
4. 셸이 출력한 로그를 확인하며 종료까지 진행 상황을 전한다. 잠금 사용 중(종료 코드 75)이면
   다른 조사가 실행 중임을 알리고 이번에는 시작하지 않는다. 자동 예약·무한 대기를 만들지 않는다.
5. 종료 후 상태를 다시 읽고 실제 완료·기존 근거 재사용·접근 불가·미완료와 다음 재개 지점을 보고한다.
   큐 길이나 Claude 종료 코드만으로 완료 수를 추정하지 않는다.

셸이 같은 flock을 잡고 큐를 만든 뒤 `claude -p`로 **ck-research만** 실행한다.
자식에게 이 백필 셸을 재귀 호출하게 하지 않는다. SOOP 조사 도구를 병렬 실행하지 않는다.
사용자가 중단하면 셸에 종료 신호를 보내 자식 조사도 함께 중단한다.

## 재개와 경계

- watch 대상은 최초 실행일의 자동 최근 3개 KST 날짜 밖부터 시작한다. 다른 대상은 최초 요청 시각부터다.
- 상한은 고정이다. 새 VOD나 watch 변경으로 최신 목록부터 다시 시작하지 않는다.
- 큐 등록은 조사 완료가 아니다. DB에 저장된 상태를 도구가 확인해 연속 처리된 곳까지만 진행한다.
- 자동 실행 몫인 오래된 running을 만나면 그 지점에서 멈춘다. 수동으로 가져오거나 커서를 넘기지 않는다.
- raw.backfill 표시가 있는 VOD는 자동 큐가 재개하지 않는다. 다음 사용자 요청에서만 이어간다.
- 같은 DB로 진행은 이전할 수 있지만 VOD 조사 실행 컴퓨터는 한 대다. 변경 시 이전 자동 타이머와
  조사를 중지하고 환경변수·out/ 근거 파일을 별도로 옮긴다.

## 접근 불가

자식 조사에서 삭제·비공개를 확인하면 잠금을 상속한 환경에서 기록한다:

```bash
npm run ck:backfill -- access --streamer <slug> --vod <번호> --status unavailable --reason "확인한 응답·근거"
```

일시 오류는 `temporary`로 남기고 이번 조사를 중단한다. 네트워크 실패 한 번으로 영구 접근 불가를
선언하지 않는다. 사유를 `scan.failed` 배열에 넣지 않는다. 진행 커서는 모델이 직접 수정하지 않는다.

재확인이 명시적으로 요청되면, 다른 조사가 없는 상태에서 같은 잠금 아래 access의 `retry`를 사용한다.
필요한 잠금 실행 예와 설치 안내는 [운영 문서](../../../docs/CK-BACKFILL.md)를 읽는다.
