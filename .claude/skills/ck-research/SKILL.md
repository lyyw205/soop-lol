# 내전·CK 조사 (ck-research)

**"○○ 6월 조사해줘"** 한 줄이 들어오면 이 순서로 돈다. 각 단계는 앞 단계의 산출물을 전제하므로 **건너뛰지 않는다.**

**★ 수집 → 판단 → 적재를 한 번에 끝까지 간다. 중간에 멈춰 묻지 않는다.**
애매한 자리는 11단계 규칙으로 정하고, **물어봤을 법한 것은 전부 체크리스트로 남긴다**(10단계).

핵심 원칙 세 개만 먼저 말한다. 나머지는 이걸 지키기 위한 절차다.

1. **정본은 롤 최종 결과 화면이다.** 채팅 공지·오버레이·제목은 전부 단서일 뿐이다.
2. **모르면 모른다고 쓴다.** 못 읽은 챔피언, 근거 없는 사람, 추정한 승자는 그렇게 적는다. 지어내면 나중에 구분이 안 된다.
3. **한 채널만 보면 그 채널이 알트탭한 판은 사라진다.** 교차검증은 선택이 아니다.

## 0. 전제 확인

```bash
ffmpeg 확인          # ck:collect 이 시작할 때 스스로 검사하고 없으면 멈춘다
```

⚠ 예전에 ffmpeg 이 없는 채로 돌아 **세그먼트 3GB 를 받고 프레임 0장**으로 끝난 적이 있다. 지금은 멈추지만, 조용히 실패하는 자리가 또 있는지 항상 의심한다.

## 1. 후보 수집 — `ck:collect`

```bash
npm run ck:collect -- --channel <채널> --date <폴더용날짜> --from <시작> --to <끝> --board-budget 0 --chat-budget 0
```

- 롤 **카테고리 본방 전부**를 썸네일 시트로 훑는다. **제목 필터는 쓰지 않는다** — 실측 회수율 10% 였다("이상호 피파" 안에 롤 내전 2개가 있었다)
- 경기 구간이 잡힌 VOD만 `event_lead` 로
- **경기 구간마다 확인 프레임 1장**(VOD당 6장 상한)을 원본 해상도로 남긴다

> 실측(이상호 7월): 226시간 ≈ 30분 · VOD 64건 · 확인 프레임 137장 / 26MB

## 1.5 이미 기록된 경기 걸러내기 — `ck:seen`

```bash
npm run ck:seen -- --channel <채널> --range <시작>:<끝>          # 본다
npm run ck:seen -- --channel <채널> --range <시작>:<끝> --mark   # 덮인 건 건너뛴다
```

**내전은 한 판을 평균 6명이 방송한다.** 이상호를 조사하며 김민교가 낀 판을 이미 다
기록했는데, 다음에 김민교를 조사하면 같은 판을 처음부터 다시 판다 — 교차검증까지 또
돌리면 시간도 토큰도 두 배다. 그런데 그 판엔 **김민교가 이미 참가자로 들어가 있다.**

```
✓ 판독함 2026-07-05 VOD 197xxxxxx  군이루 CK 맞밸 스맵     ← VOD 번호 일치(정확)
? 날짜만 2026-06-26 경기2 ≤ 기록3   이상호 vs 학살         ← 같은 날 다른 판일 수 있다
· 새것   2026-07-08 경기1           군이루 솔랭
```

- **판독함** → `--mark` 로 `ignored`. 2~9단계를 통째로 건너뛴다
- **날짜만 / 일부** → 사람이 본다. **자동으로 안 건너뛴다**
- **새것** → 평소대로

⚠ **날짜만 맞은 건 믿지 마라 — 실제로 두 번 틀렸다(2026-08-19).**
- `06-26 02:34 학살CK` 를 같은 날 `21:50 깐부CK` 로 덮였다고 했다. **다른 판이다.**
  그대로 건너뛰었으면 3판을 통째로 잃었다
- `06-14` 단서는 이미 적재된 **06-13 호진CK 와 같은 VOD** 인데 날짜가 달라 '새것' 으로 나왔다

→ 지금은 **VOD 번호**(`event_lead.url` ↔ `match.source_url`)를 먼저 본다. 이건 근사가 아니다.

## 2. 게임 종류 판정 — `ck:sheet` + 사람 눈

```bash
npm run ck:sheet -- out/confirm/<날짜> --cols 4 --rows 4
```

**시트 훑기는 롤과 FC온라인을 못 가른다**(실측 오탐 67%). 격자로 붙여 한 번에 본다.

| 보이는 것 | 판정 |
|---|---|
| `스크림) 상호팀 0:0 ○○팀` 류 **본인 시리즈 오버레이** | 남긴다 |
| `마스터 443호` | 솔랭 → 기각 (공개 큐는 match-v5 백필 담당) |
| 공식 중계 오버레이 · `멸망전 응원` · 프로 선수 이름 | **시청** → 기각 (협곡 화면이라 픽셀로는 못 거른다) |
| 축구장 · 이적시장 · 오리게임 | 롤 아님 → 기각 |
| 아레나 | 기각 (협곡 5v5 아님) |

기각은 `state='rejected'` + **사유를 note 에 남긴다.** 뒤 단계가 이걸 보고 건너뛴다.

★ **기각하는 건 '본인 경기다' 라는 판정이지 프레임이 아니다.**
시청 구간에도 **결과창이 통째로 잡힌다** — 스트리머가 남의 방송을 크게 띄워 놓기 때문이다.
2026-08-19 조사에서 결과창 **10장 중 5장**이 그렇게 나왔고(Peanut·서도일·칸_김동하·김민교·클리드),
06-15 전야제 3판은 **본인 VOD 에 결과창이 아예 없어** 김민교 시점으로만 회수됐다.
본인이 **한 판도 안 뛴** 내전(04-28·04-30 클상도)도 진짜 스트리머 대결이라 그대로 적재했다.

→ 시청 구간은 **그 단서를 본인 경기로 세지 않을 뿐**, 프레임은 7단계에서 똑같이 판독한다.

## 3. 매치 카테고리 **잠정** 판정 ← 여기서 먼저 잡는다

카테고리에 따라 **뒤 단계에서 무엇을 봐야 하는지가 달라진다.** 그래서 판독 전에 정한다.
근거는 제목 · 오버레이 문구 · 채팅 공지 형식 · 로스터 고정 여부다.

| 카테고리 | 표시 | 뒤에서 할 일 |
|---|---|---|
| **CK** | `3/2)` `5/3)` 오버레이, 팀명 두 개 고정 | 승부가 난 시점을 찾는다. 그 뒤 판은 세트가 아니다 |
| **대회**(멸망전 등) | 공식 중계 오버레이, 대회 브래킷 | **이미 등록된 event 가 있는지 먼저 본다.** 중복 적재 금지 |
| **랜드** | 같은 10명인데 매 판 팀이 섞임 | 시리즈로 묶지 않는다. 판마다 팀을 새로 읽는다 |
| **스크림** | 2시간 단위로 상대가 바뀜 | 시간 경계에서 끊긴 판을 찾아 **버린다** |
| **미정** | 위 어느 것도 확실치 않음 | **그대로 둔다** |

⚠ **애매하면 `미정` 으로 둔다.** 잘못 확정한 카테고리에 억지로 끼워 맞추면 세트 수·승패가 통째로 틀어진다. `미정` 은 7단계에서 판독 결과를 보고 확정한다.

규칙 상세는 `docs/CK-COLLECTION.md §3.5`.

## 4. 로스터 확보 — 5단계의 입력

결과창 하나만 읽어 **10명 인게임명**을 뽑고 사람을 붙인다. `ck:cross` 가 이 명단으로 채널을 훑으므로 먼저 해야 한다.

- 인게임명 → `npm run ck:who -- <이름>` → `streamer` (7단계와 같은 방법)
- **근거 없으면 매핑하지 않는다.** 로스터에서 빼고 이름만 근거에 적는다
- 등록 계정과 **다른 계정**이면 `unlinked_account` — 안 그러면 안 뛴 계정에 판이 달라붙는다
- 메모장·팀뽑기·밴픽 화면이 잡히면 그게 로스터 정답표다 (`탑 써밋 애디 / 정글 상호 도일 …`).
  뿌리 화면의 `해기vs꾸티뉴 / 상호vs스맵 / …` 처럼 **맞라인 표**가 통째로 나오기도 한다

⚠ **팀 이름으로 로스터를 추정하지 마라.** 멤버 약칭 조합처럼 보여도 실제와 다르다 —
`넛저밧` 에 저라뎃도 준밧드도 없었고, `클상도` 에 이상호가 없었다.

## 5. 교차수집 — `ck:cross` **(최소 3 POV)**

```bash
npm run ck:cross -- --event <대회 slug>
```

로스터 **전원**의 SOOP 채널을 그 기간으로 훑는다. 채널 없는 선수는 이름을 찍어 알린다.

**★ 판마다 최소 3개 시점을 확보하고, 과반수가 같은 결과를 말할 때 확정한다.**

- 3개가 안 모이면 → 확정하지 말고 **이슈로 기록**한다(10단계)
- 시점끼리 어긋나면 → **결과 화면이 있는 쪽이 이긴다.** 채팅·오버레이는 진다
- 그래도 안 갈리면 → `winner` 를 비우고 이슈로 남긴다

> 왜 이렇게까지 하나: **결과창의 절반이 남의 방송 화면에서 나온다**(2단계 참조).
> 교CK 1·2세트는 1채널만 돌려서 끝내 못 찾았다.

## 6. 결과창 대량 추출 — `ck:prep`

```bash
npm run ck:prep -- --date <날짜> --only <채널>          # 기본. 그 채널만
npm run ck:prep -- --date <날짜> --sessions 6 --per-session 5   # 대표 선정에 맡길 때
```

**한 채널을 파는 중이면 `--only <채널>` 이 맞다.** 대표 선정은 "지금 누구를 조사 중인지"를
몰라서 긴 VOD 를 밀어낸다 — 2026-08-19 조사 30건은 전부 `--only` 로 돌렸다.
기각된 단서는 건드리지 않는다.

⚠ **`결과 화면 N/N 확보 ✓` 는 탭까지 보장하지 않는다.** 7단계 첫 줄 참조.

**★ 오래 걸린다 — 백그라운드로 돌리고 그동안 앞 구간을 판독한다.**
SOOP 을 1배속으로 페이싱해서 날짜 하나에 5~15분이다. 월 단위로 묶어 던져 두면
프레임 추출(I/O)과 판독(사람 눈)이 겹친다. 실측으로 이게 전체 시간을 반으로 줄였다.

## 7. 판독 + 카테고리 **확정**

### 7-1. 결과창에도 두 탭이 있다 — **점수판이어야 라인업을 읽는다**

| 탭 | 보이는 것 | 쓸모 |
|---|---|---|
| **점수판** | 10명의 인게임명·챔피언·KDA·골드 + 팀 합계 | 전부 읽힌다 |
| **그래프** | 승리/패배와 막대그래프뿐 | **승패만** |

`ck:prep` 이 `결과 화면 8/8 확보 ✓` 라고 해도 전부 그래프 탭일 수 있다.
02-28 스크림은 클러스터 8개 중 **2개만 점수판**이라 나머지 6판은 승패밖에 못 넣었다.
**시트로 훑을 때 탭부터 가른다.**

### 7-2. 가려진 칸은 **같은 클러스터의 다른 프레임**을 먼저 본다

클러스터는 6초 간격 6장이다. 아이템 툴팁·별풍선 애니메이션·얼굴캠·리플레이 안내는
**다음 프레임에서 걷힌다.** 2026-08-19 조사에서 가려진 4건 중 2건은 다른 프레임에
값이 통째로 있었다(학살CK 3세트 KDA 5명, 06-17 라파엘팀 KDA 5명).

```bash
# 한 칸을 클러스터 전체에서 잘라 가로로 붙여 한 번에 본다
for t in <프레임시각들>; do ffmpeg -i <프레임> -vf "crop=…,scale=…" -y k_$t.png; done
ffmpeg -i k_1.png -i k_2.png … -filter_complex hstack=inputs=N -y k_all.png
```

그래도 안 보이면 팀 합계에서 **역산하고 "역산"이라고 적는다.**

### 7-3. 이름은 **`ck:who` 로 되짚고, 0건이면 확대한다**

```bash
npm run ck:who -- 난벌레팡이다 붕어에옹 달리아
```

정확히 없으면 **편집거리 2 이내의 후보**를 사람·챔피언으로 나눠 내놓는다(한글은 자모까지 본다).

⚠⚠ **인게임명으로 SOOP 을 검색해 사람을 찾지 마라.** 인게임명은 SOOP 닉네임이 아니다.
2026-08-19 에 '시락이' 로 검색해 나온 채널(닉네임이 **정확히 일치**, 방송 0건)을 보고
"방송인이 아니다" 로 결론냈는데 **전혀 다른 사람**이었다 — 정답은 이미 등록돼 있던
**다누리**(인게임명 '오땅이')였다. **닉네임이 딱 맞을수록 위험하다.**
→ 사람은 `ck:who`(등록 계정 대조) · 팀 이름 · **참가자 본인 방송 제목**으로 찾는다.
   그날 방송 제목이 로스터를 통째로 적어 두기도 한다:
   `「상호피유옥맨민교누리 vs 눈길수야클템경민다쁘 CK」` 한 줄로 열 명이 풀렸다.

⚠⚠ **조회 0건은 '미등록' 이 아니라 '잘못 읽었다' 는 신호다.**
2026-08-19 조사에서 0건이 난 이름 9개를 확대해 고쳐 읽었더니 **전부 편집거리 2 이내**였고,
그중 **여섯은 진짜 사람**이었다. 정확 일치만 봤으면 여섯 명을 버렸다:

```
난벌레팡이다→난벌레곰팡이다(꿀템은죽었다)   붕어에옹→붕어에몽(감블러)
바드앵용→바뜨엥용(준밧드)                똥딴지구독점yo→뚱딴지구독점yo(아뚱)
뒈레이→둬레이(한둬얼)                   떼깔룩→떼껄룩(뿌리)
사나이목직한주먹→사나이묵직한주먹(김민교)     달리아→탈리야 · 라산드라→리산드라
```

**후보는 답이 아니다. 확대해서 확인하고 쓴다.**

```bash
ffmpeg -i <프레임> -vf "crop=260:60:250:335,scale=1560:-1" -y zoom.png   # 이름 칸만
```

⚠ **닉네임 오독은 사람을 바꾼다.** `쏴봐쏴` 는 나는상윤의 **등록 계정**인데
`쌱뽜쌱` 으로 읽는 바람에 부계정으로 오해해 11판에서 puuid 를 떼어냈다.

### 7-4. 나머지

- **팀 합계 K/D/A 로 검산한다.** 안 맞으면 잘못 읽은 것
- 채팅 공지가 충돌(`conflict`)했으면 **결과창이 정본이다**
- **`played_at` 은 결과창의 화면 시계를 따른다** — `event_lead` 날짜가 아니다.
  심야 방송이라 단서는 다음 날로 잡힌다. 2026-08-19 조사에서 새 대회 **16개 중 12개**가
  단서 날짜와 실제 경기일이 달랐다 (단서 03-01 → 실제 02-28, 04-02 → 04-01, 06-30 → 06-29 …)

여기서 3단계의 카테고리를 **확정**한다. 잠정과 다르면 고친다 — 억지로 맞추지 않는다.
`미정` 이었던 것도 여기서 정한다. 그래도 안 정해지면 `미정` 인 채로 이슈에 남긴다.

## 8. 적재 — `seed:tournament`

- `result_evidence` **필수**. 무엇을 보고 정했는지 그대로 쓴다
- 못 읽은 건 못 읽었다고 쓴다: `⚠ 결과창 없음` · `산술 추정` · `초상화만` · `역산`
- 대회 카테고리면 **기존 event 에 합친다.** 새로 만들지 않는다
- ⚠ **멸망전 라인업은 시드를 직접 고치지 마라.** `seed:meljang` 이 나무위키에서 시드를
  통째로 다시 만들어 손으로 적은 게 사라진다. `seed/lineups/<event>.json` 에 두고
  `npm run seed:meljang-lineup -- --apply` 로 병합한다 (로스터 보강은 `seed:meljang-roster`)
- 끝나면 `event_lead` 를 `confirmed` + note. **VOD 를 판독했으면 event 를 연결한다** —
  1.5단계가 `match.source_url` 로 중복을 걸러내는 근거가 이것이다

## 10. 기록 ← **빼먹지 않는다**

두 곳에 남긴다.

### 10-1. `out/report/CHECKLIST.md` — **매치별 체크리스트** (필수, 누적)

물어보지 않고 정한 것을 여기에 전부 적는다. **이 파일이 "물어봤을 것들" 의 목적지다.**
조사할 때마다 **위에 덧붙인다**(최신이 위). 형식은 고정이다:

```markdown
## 2026-06-25 · CK · 이상호 vs 학살 (3판 2선승)
`ck-leesangho-2026-06-25-haksal` · **상호팀 2:1** · 3판 적재 (2·3세트 완전 판독)

- [ ] 1세트는 결과창이 없어 **로스터를 2·3세트와 같다고 추정**했다 — 뒤집을 근거가 나오면 고친다
- [ ] 서포터 `듀 비` → `듀단.`(dudadi770) 으로 넣었다. 근거는 디스코드 통화방 명단 + 이름 첫 글자.
      **본인 확인은 못 했다**
- [x] `단판 3천개빵)` 은 팀이 섞여 §3.5-1 로 제외 — 판 자체를 버렸다
```

- 머리줄은 **`날짜 · 매치구분 · 매치명`**, 다음 줄에 **`slug · 결과 · 적재량`**
- 매치구분은 3단계 카테고리 그대로: `CK` `대회` `랜드` `스크림` `미정`
- 체크 항목은 **다음 사람이 손댈 수 있는 단위**로. 이미 판단이 끝나 되돌릴 일이 없으면 `[x]`
- 기각한 단서도 한 줄씩 남긴다 (왜 기각했고, 나중에 다시 볼 이유가 있는지)

### 10-2. `out/report/<채널>-<기간>.md` — 조사 서사

다음에 이어서 할 사람(=나)이 읽을 문서다. 체크리스트가 '무엇이 미결인가' 라면 이쪽은 '무슨 일이 있었나' 다.

**요약** — 단서 N건 → confirmed C · rejected R / 대회 K개 · 경기 G판 · 조우 P쌍

**미해결** — 있는 것만 쓴다. 표 한 줄이면 표 한 줄로 쓴다.
- 사람을 못 붙인 인게임명 (어느 팀·포지션 · 후보 · 왜 못 정했나)
- 근거가 약한 판 (무엇이 없나 · 지금 근거가 뭔가)
- 교차검증 3 POV 미달 · 카테고리 미정

**다음에 할 일** — 다음 사람이 바로 손댈 수 있는 단위로.
예: 미등록자 등록 → 재파생하면 조우가 살아난다

⚠ **이슈를 코드 커밋 메시지에만 적고 끝내지 않는다.** 다음 조사 때 이 파일부터 읽는다.

## 11. 물어보지 않고 정한다 — 판단 규칙

멈춰서 묻고 싶어지는 자리는 정해져 있다. **아래대로 정하고 체크리스트에 올린다.**

| 상황 | 정한다 | 체크리스트에 적을 것 |
|---|---|---|
| 인물 후보가 **둘 이상** | 로스터에서 **뺀다** | 후보 전부 · 왜 못 정했나 · **기존 시드가 다르게 매핑했으면 그것도** |
| 인물 후보가 **하나 + 정황 2개 이상** | `unlinked_account` 로 **넣는다** | 근거 사슬을 그대로 |
| 결과창 **2장 이상**에서 10명이 같다 | 그 사이 세트도 **같은 로스터**로 넣는다 | "로스터는 추정" |
| 결과창이 **1장뿐** | **그 판만** 넣는다 | 못 넣은 판 수와 이유 |
| `blue`/`red` 근거 없음 | 다른 세트 기준으로 **가정** | 가정이라는 사실 |
| 세트 번호가 안 갈림 | `series`·`set_no` **없이** 판 단위로 넣는다 | 왜 안 갈렸나 |
| 추가 세트(`단판)` · 범인찾기 · 자리 바꿔서) | **시리즈에는 넣지 않되, `series`·`set_no` 없이 판 단위로 적재한다.** 단 **그 판의 로스터를 새로 읽었을 때만** — 팀이 섞이는 게 보통이다 | 로스터를 못 읽어 버렸다면 그 사실 |
| 본인이 **한 판도 안 뛴** 내전 | **넣는다** (스트리머 대결이 목적) | — |
| **무효·재경기** | **넣지 않는다** | 무엇을 보고 무효로 봤나 |
| 3 POV 미달 | 결과창이 있으면 **넣는다** (결과창이 정본) | 확보한 POV 수 |
| 승패만 알고 챔피언·KDA 를 모름 | 승패만 **넣는다** | 무엇이 비었나 |
| 등록 안 된 사람이 껴 있다 | 그 사람만 **빼고** 넣는다 (참가자 9명) | 인게임명 · 어느 팀·포지션 |

★ **추가 세트를 통째로 버리지 마라.** `docs/CK-COLLECTION.md §3.5-1` 이 막으려는 것은
**시리즈 스코어 오염**이지 경기 자체가 아니다. 진짜 스트리머 5v5 이고, 이 사이트의 존재 이유가
"누가 누구를 이겼나" 다. `series` 를 안 붙이면 스코어는 안 더럽히면서 조우는 살아난다.
⚠ 다만 추가 세트는 **팀이 섞인다**(§3.5-2 랜드와 같다). 그 판의 로스터를 결과창에서
새로 읽지 못했으면 넣지 않는다 — 앞 세트의 팀을 재사용하면 없는 대결을 만든다.

⚠ **넣지 않기로 한 것도 체크리스트에 남긴다.** 조용히 버리면 다음 사람이 그게 있었는지도 모른다.

★ **오버레이 팀명은 그 방송의 팀명일 뿐이다 — 대회 이름이 아니다.**
같은 판을 참가자마다 **자기 팀장 이름**으로 부른다. 2026-06-26 깐부CK 한 시리즈가 이렇게 보였다:

```
이상호 화면    깐부CK) 상호팀 1 : 2 스맵팀 (5/3)
진성준짱 화면  5/3 성준팀 0 : 1 성훈팀
해기 화면      (5/3) 해기팀 1 : 2 티뉴팀
```

→ 팀명이 다르다고 다른 시리즈로 갈라 놓으면 한 대회가 셋이 된다.
**로스터와 시각으로 맞춘다.** 반대로 팀명이 같아도 로스터가 딴판이면 다른 시리즈다
(05-11 과 05-12 의 '넛상도 vs 클저밧' 이 그랬다).
