# 내전·CK 조사

VOD 에서 **스트리머끼리 누가 누구를 이겼나**를 찾아 기록한다.

자동 최근 VOD 조사와 수동 과거 백필이 공유하는 분석 절차다. 과거 목록 선택·재개 요청은
[ck-backfill](../ck-backfill/SKILL.md)을 사용한다. 백필 셸의 자식 실행에서는 전달된 큐를 이 스킬로
조사하며 백필 셸을 다시 호출하지 않는다. 커서는 외부 도구가 DB 저장 결과로 갱신한다.

저장한 경기는 **곧바로 공개된다.** 초안도, 승인 대기도, 조사 종료 도장도 없다.
대신 [`/admin/ck`](../../../apps/web/app/admin/ck) 가 사후에 고치고 빼는 자리다 —
틀린 것은 거기서 고치면 되고, 그래서 여기서 완벽할 필요가 없다.

> **조사 범위와 발견한 후보를 방치하지 않고, 실제 수행과 근거를 기록하는 것은 필수다.**
> 조사 방법·순서·자료 해석은 스스로 판단한다. 기존 근거를 재사용할 수 있지만 범위와 출처를 남긴다.
> 확인에 실패할 수는 있어도, 미수행을 완료로 기록해서는 안 된다.

## 반드시 하는 것 / 네가 정하는 것

| 자리 | 반드시 수행·기록 | 네가 정한다 |
|---|---|---|
| 대상·범위 | VOD와 이전 기록 조회. 요청 범위를 조사·근거 재사용·미확인으로 빠짐없이 처리 | 조사 순서, 샘플 간격, 추가 탐색 위치 |
| 경기 추적 | 롤 화면을 보면 맥락 확인. 대상 경기의 판별 경계·결과 탐색을 방치하지 않음 | 대상 여부, 경기 경계, 같은 판인지 |
| 중복 조회 | 깊게 파거나 새 경기를 만들기 전에 기존 경기 조회. 재사용 구간·경기·출처 연결 | 같은 판인지, 기존 근거를 어디까지 재사용할지 |
| 교차검증 | 추가로 들어온 시점도 정해진 조사 절차를 수행하고, 직접 읽은 값과 사진을 제출한다. 도구가 기존 값과 비교하고 빈칸을 채운다. 결과 근거가 부족하거나 자료가 충돌하면 도움이 될 다른 시점(와치리스트 밖 포함)을 찾는다. 못 찾으면 시도와 한계 기록 | 시점 선택, 추가 조사 수단·깊이 |
| 통합 | 같은 판은 같은 경기 ID에 연결. 출처와 불일치 보존 | 사람·팀·시리즈 매핑, 채택할 값, 미해결 판단 |
| 마무리 | 저장 응답 확인. 후보별 종료 사유·남은 범위·재개 지점 기록 | 근거에 맞는 종료 상태, 후속 조사 순서 |

**수행 완료와 정보 확보 성공은 다르다.** 결과창 발견 성공은 의무가 아니지만,
대상 경기마다 [탐색 종료 사유](#결과-화면을-찾는-기본-방법)를 남겨야 한다.
필수 조사가 남은 채 시간이 끝나면 `running`으로 저장한다. 없는 사람·승패·KDA를
DB 제약에 맞추려고 만들지 않는다. 모르면 비우거나 후보로 보존한다.

## 흐름 — 단계마다 무엇을 보고 넘어가나

| 단계 | 수행과 다음 단계로 넘어가는 판단 |
|---|---|
| 1. 대상·이전 기록 | VOD 식별·이전 실행(`ck:record --lead`)을 확인하고 **훑기 전에 `ck:merge --find-match --vod <번호>`** 로 이 방송에 이미 기록된 경기의 VOD 구간과 공백을 본다. 중단된 조사면 남은 지점부터. 기존 경기가 나와도 **구간을 건너뛰지 않는다** — 그 경기도 처음부터 읽고 6단계 방식으로 낸다 |
| 2. 미확인 범위 훑기 | 요청 범위 중 재사용하지 못한 곳에 대표 화면을 두고 실제로 연다. 롤 화면이 보이면 3단계로 간다. 나머지는 관찰과 확인 범위를 남긴다 |
| 3. 맥락 확인 | 화면 속 경기가 수집 대상인지 판단한다. 대상이면 4단계, 아니면 해당 구간만 근거와 함께 `not_target`, 불명확하면 추가 확인 또는 미해결로 남긴다 |
| 4. 판·시리즈 구분 | 각 판의 경계·순서와 시리즈 관계를 확인한다. 확인된 경계는 재사용한다. 확인 불가 범위는 이유를 남기고, 조사 가능한 잔여 작업은 재개 대상으로 남긴다 |
| 5. 판별 결과 탐색 | 판마다 결과창 탐색을 종료 사유까지 수행한다. 저장 가능한 경기는 즉시 반영하고, 필수 정보가 미해결이면 후보로 보존한다 |
| 6. 다른 시점 | 이미 기록된 경기라고 판단하면 그 `match_id` 로 **이 화면에서 직접 읽은 칸만** `match` 제출한다. 같다·다르다는 저장 도구가 계산한다([다른 시점](#같은-경기의-다른-시점을-다루는-방법)) |
| 7. 나머지 구간 | 기록된 경기 구간 밖(판 사이·시리즈 전후·보너스 단판·다른 게임)은 평소대로 훑고 추적한다 |
| 8. 저장·마무리 | 저장 응답·근거 연결을 확인하고 필수 수행 종료 여부로 실행 상태를 남긴다. 시리즈 전체 완료를 기다리지 않고 첫 경기부터 누적 반영한다 |

단계는 의존관계다. 새 단서가 나오면 앞 단계로 돌아갈 수 있다. 다른 시점 조회 전에
첫 VOD에서 확인한 경기를 반영해, 같은 실행의 다음 VOD도 최신 기록을 활용하게 한다.

**현재 도구:** `ck:record --lead`로 이전 기록을, `ck:merge --find-match --vod <번호>`로 이 방송에
이미 기록된 경기(방송 주인이 참가자인 것)의 VOD 어림 구간·이 사람의 팀·챔피언·빈칸을 본다.
이건 **어느 경기에 제출할지 고르는 자료**다. 탐색을 줄이는 근거가 아니다.
VOD 초는 "경기 시작 절대시각 − 방송 시작 절대시각" 어림이라 VOD 가 끊겼으면 어긋난다 — 그 초의 화면으로 확인한다.
날짜만 확실한 경기는 VOD 초가 안 나온다. 그 판은 구간을 건너뛰지 않고 평소대로 본다.
후보를 새로 찾으면 근사 시각으로 `ck:merge --find-match <시각>`도 쓴다.
종료 상태 강제 검사는 [설계 문서 §6.1](../../../docs/CK-RESEARCH-PLAN.md#61-시리즈-교차검증과-구간-재사용--후속-구현)의 후속 작업이다.

**첫 훑기는 30분을 기본 간격으로 쓰되 조절한다.** 짧은 경기나 보너스 단판이 격자 사이에
있을 수 있다. 짧은 꼬리·재사용 구간 사이의 잔여 범위에도 대표 지점을 두고, 단서가 있으면
추가로 연다. 양옆이 게임과 무관하고 추가 단서도 없으면 더 파지 않을 수 있으나 판단 범위를 남긴다.
30분·5분할·2~3초 마무리는 기본 전략이지 경기 유무나 완료의 합격선이 아니다.

**시각은 VOD별 전체 초로 쓴다.** 다른 VOD의 같은 오프셋은 같은 시각이 아니다.
프레임·전사·후보에 출처 VOD를 유지한다. API와 HLS 길이 불일치·누락으로 절대시각 대응이
불확실하면 확인 전까지 다른 VOD의 생략 구간으로 투영하지 않는다.

## 경기 추적 — 반드시 끝까지

2026-09-27에는 CK 화면을 본 VOD 6개를 좁히지 않았고, 과거 a57187a에서도 반복 수행을
빠뜨렸다. 이를 막는 의무는 판별 추적·기록이며, 동일한 작업을 모든 VOD에서 반복하는 것이 아니다.

1. **맥락을 확인한다.** 한 장으로 불명확하면 로비·밴픽·결과창·오버레이·채팅 등 필요한
   자료로 게임 모드와 맥락을 확인한다. 솔랭 등 대상 밖이면 해당 구간만 근거와 함께 닫는다.
   **시청·중계라는 이유만으로 제외하지 않는다.** 방송 주인의 참가 여부와 화면 속 경기의
   수집 대상 여부를 구분한다. 대상 경기의 결과창이면 다른 방송을 비춘 화면도 근거로 쓸 수 있다.
2. **경기 경계를 확인한다.** 앞뒤 프레임을 좁혀 판 수·순서·경계를 조사한다. `--divide 5`는
   기본 방법이며, 정확한 채팅 시각이나 기존 근거가 있으면 그 지점부터 본다. 연속 경기에서
   한 판만 찾고 멈추지 않는다. VOD가 잘렸다면 확인 불가 경계와 이유를 남긴다.
   기존 경계는 현재 시점과 같은 판임·시간축을 확인한 뒤 재사용하고 불확실한 부분만 좁힌다.
3. **판마다 결과창 탐색의 종료 사유를 남긴다.** [아래 네 사유](#결과-화면을-찾는-기본-방법)
   중 하나에 닿지 않은 대상 판이 있으면 `done`으로 내지 않는다. 다른 시점의 근거를 재사용하면
   경기 ID와 실제 결과 프레임을 참조한다. 조사 시간이 끝나면 남은 구간·질문·다음 행동을 저장한다.

## 명령

```bash
# 전 범위 훑기 — 기본 30분 간격. 짧은 꼬리 파일도 본다. 간격은 기본값이지 판정 규칙이 아니다
npm run ck:probe  -- --vod 207602969 [--interval 1800] [--dry-run]

# 후보 주변 파기 — 채팅·전사·앞 프레임이 "여기 보라" 고 한 시각을 그대로
npm run ck:probe  -- --vod 207602969 --at 16812,16817,16940

# 확실한 경기 진행 화면과 종료 후 화면 사이를 5분할한다. 확인한 뒤 새 구간으로 반복한다
npm run ck:probe  -- --vod 207602969 --between 19400:19560 --divide 5

# 5분할로 더 좁혀지지 않는 마지막 짧은 조각만 2~3초 간격으로 확인한다
npm run ck:probe  -- --vod 207602969 --between 19496:19510 --step 2

# 고른 구간 음성 (보조). 오디오 트랙을 먼저 찾고 없으면 최저 화질로 간다
npm run ck:listen -- --vod 207602969 --at 16800:120 [--engine qwen]

# 이름 → 사람. 정확히 없으면 가까운 후보를 내놓는다
npm run ck:who    -- 이상호93 "소년가장 원딜" Radiohead

# 이 방송의 어느 시간대가 이미 기록돼 있나 — VOD 를 훑기 전에 먼저 묻는다
npm run ck:merge  -- --find-match --vod 207602969

# 이 판 이미 들어와 있나 — 후보를 깊게 파거나 새 경기를 만들기 전에 묻는다
# 정확한 시각을 기다리지 않는다. VOD 시각+구간 오프셋의 근사값이면 기본 90분 창으로 충분하다
npm run ck:merge  -- --find-match 2026-09-19T12:42:00Z --with leesangho,kimmingyo

# 채널별 VOD 보존 성향. 다른 POV 선택용 힌트이며 목록 조회를 끄지 않는다
npm run watch -- --vod-usually-unavailable <이름또는채널>
npm run watch -- --vod-usually-available <이름또는채널>
npm run watch -- --vod-unknown <이름또는채널>

# 기록·반영 (유일한 창구)
npm run ck:merge  -- --result out/ck/207602969/result.json [--dry-run]

# 되짚기 (읽기 전용) — 공개 값·근거 프레임(VOD 시각)·조사 기록·남은 질문·수정 이력
npm run ck:record -- --match <match_id> | --lead vod:207602969 | --event <slug>
npm run ck:record -- --todo    # 이어서 할 일: 연결 없는 반영 후보 · 미해결 후보 · 못 본 구간
```

**조사 상태는 검수 화면에 없다.** 사람 검수 화면은 공개될 값·비교 프레임·수정/숨김만 다룬다.
후보 결론·미해결·질문·못 본 구간은 `ck:record` 로 본다. 대회 시드 뒤의 확인도
`ck:record --event <slug>` 다(근거 없는 경기가 있으면 종료 코드 1).

**`ck:probe` 와 `ck:listen` 은 DB 에 아무것도 쓰지 않는다.** 로컬 산출물만 만든다.
그리고 **'읽음' 을 붙이지 않는다** — 파일이 생긴 것은 근거가 아니다. 여는 것이 근거다.

**추출한 프레임은 읽은 프레임이 아니다.** 탐색·좁히기·결과창 찾기로 **뽑은 프레임은 전부 연다.**
결과창을 찾았어도 같이 뽑은 옆 프레임을 연다 — 더 잘 보이는 탭이나 다음 판 시작이 거기 있다
(2026-09-23 "뽑고 왜 안 읽냐" 로 지적받았다). 안 연 프레임은
`ck:merge`가 `read_at = NULL`로 등록한다 — 연 것과 안 연 것은 `ck:record --lead` 가 따로 보여준다.

채팅 `!공지` 는 `scripts/lib/soop-vod.mjs` 의 `loadChat`·`gameEndsFromNotice` 로 본다.
10채널 중 1채널에만 있지만, 있으면 경기 경계와 시리즈 구조가 통째로 나온다.

**실제로 연 화면에 FC 온라인이 보이면** 가벼운 교차 단서만 넘긴다:

```bash
npm run fco:context -- clue --vod 207602969 --at 2400 --observed "FC 인게임, 스코어보드에 호날두"
```

단서는 위치와 관찰뿐이다 — FC 경기·행사를 여기서 확정하지 않고(그건 `fco-match-context` 의
일이다), **LoL 탐색의 나머지 범위를 생략할 이유도 아니다.** 프레임을 뽑기만 한 것은 단서가
아니다 — 연 것만 넘긴다. LoL 결과 파일(`scan-draft.json`)에 FC 행사를 넣지 않는다.

## 입력 창구 — `ck:merge --result`

한 파일에 배열로 여러 개를 담아도 된다. `resultType` 으로 갈린다.

| | 하는 일 |
|---|---|
| `scan` | 실행 기록 · 후보 결론 · 근거 프레임. **실행 종료 전용이 아니다** — 중간에도 낸다 |
| `match` | 경기·참가자·대회 연결 |
| `identify` | 기존 참가자에 사람을 붙인다 |

`ck:probe` 가 `out/ck/<vodId>/scan-draft.json` 초안을 만들어 둔다. **열어서 읽은 뒤**
`scan.opened`·`frames[].note`·`candidates` 를 채운다.

기록의 뜻:

- **'읽음' 은 `scan.opened` 에 그 시각이 있거나 `frames[].read: true` 일 때만이다.**
  메모(`note`)를 적었다고 읽음이 되지 않는다 — 예전엔 그랬고, 옆 프레임 설명을 붙여 적은 것까지
  읽음으로 찍혔다. 메모는 있는데 `opened` 에 없는 프레임은 `ck:merge` 가 경고한다
- **`scan.opened` 는 실제로 연 시각**이다. 뽑은 장수가 아니다
- **`scan.sampled` 는 대표 샘플을 둔 범위**다. 전 프레임을 봤다는 뜻이 아니다
- **`scan.failed` 는 못 본 범위**다. 있으면 그 VOD 의 결론은 완결이 아니다
- **`scan.status: done` 은 「계획한 탐색을 하고 후보들의 현재 결론을 적었다」**다.
  필수 탐색·교차검증 처리는 끝났지만 승패·신원 등이 미해결이면 `done`일 수 있다.
  미수행 조사가 남으면 `running`이다. 실행 실패는 `failed`와 실패 범위·원인을 남긴다.
  자동 큐는 와치리스트 채널의 `running`을 기간과 무관하게 다시 넣는다. 재개 대상 VOD도 최종 보고에 명시한다
- **`candidates[].conclusion`** — `match` · `linked`(기존 경기에 붙임) ·
  `not_target`(우리 경기 아님) · `unresolved`(더 봐야 한다)
- **`match`·`linked` 는 `match_id` 가 있어야 한다.** 없으면 병합이 거부한다 — 어느 경기인지
  모르면 `unresolved` 로 남긴다
- `linked`는 중복 자동 판정이 아니다. 시각·참가자·승패 등 읽은 근거로 조사자가 같은 판이라고
  판단했을 때만 쓴다. **같은 파일에 그 경기의 `match` 시점 제출이 있어야 한다** — 없으면 병합이
  거부한다(메모만 남고 사진·비교가 빠진 임아니 VOD 사례). **한 후보에는 한 경기의 좁은 구간만** 넣고 `match_id`, `observed`,
  `why`를 남긴다. 여러 경기를 아우르는 넓은 구간을 한 경기에 연결하면 어드민의 경기 막대와
  프레임 선택 범위까지 잘못 넓어진다
- 넓은 후보를 여러 현재 후보로 나눴으면 각 새 후보의 **`supersedes`** 에 원래 후보 id를
  적는다. 원래 후보는 한 글자도 고치지 않는다. 화면은 자신을 가리키는 자식이 있는 부모를
  계산해 기본 큐에서 숨기되 조사 이력은 보존한다
- **`candidates[].observed` 는 본 것, `why` 는 그래서 어떻게 봤나.** 섞지 않는다 —
  검수자가 네 해석을 관찰로 착각한다
- 입력의 **`match.result_evidence` 없이는 안 받는다.** 무엇을 보고 승패를 정했는지 그대로 쓴다.
  저장 정본은 `review_record(type='final_evidence')`다. "결과창 못 찾음, 공지만 있음"도
  정당한 기록이다
- **승자를 모르면 경기로 넣지 않는다.** 후보에 `unresolved` 로 남긴다
- 근거 프레임은 **경로로** 건다(`evidence_frames: ["out/ck/…/g0016940.jpg"]`)
- **결과창 프레임은 `frames[].kind: "result"`** 로 낸다. `other` 로 두면 `--find-match` 가 그 판을
  "결과 화면 없음" 으로 보여 다른 시점이 같은 판을 다시 판다(2026-09-27 CK 3판이 전부 그랬다)
- **챔피언은 읽을 수 있으면 채운다.** 결과창 아이콘이 작으면 밴픽·인게임 탭 화면에서 확대해 읽는다.
  비우면 다른 시점이 그 칸을 채운다. 못 읽었으면 추측해 채우지 않는다
- **`event.name` 에 날짜를 넣지 않는다.** 날짜는 `event.slug` 가 담당한다
  (`ck-2026-09-19-sangho-mansik`). 이름은 화면에 그대로 찍히는데 그 줄에는 이미 날짜가
  따로 있어서 **같은 날짜가 두 번** 나오고, 그만큼 이름 칸이 밀려 잘린다.
  같은 사람들이 여러 번 해서 이름이 겹쳐도 괜찮다 — 구분은 slug 가 하고, 화면에서는
  "이 조합이 여러 번 있었다" 로 읽히는 편이 낫다.
  `name: "상호팀 vs 만식팀 CK — 니가가라 하와이"` · `slug: "ck-2026-09-19-sangho-mansik"`
- **이미 있는 대회(멸망전 등)에 붙일 때는 `event.slug` 만 적는다.** `ck:merge` 는 기존 대회를
  **읽기만** 하고 이름·분류·주최·기간을 고치지 않는다. `event.kind` 를 적었는데 기존 값과
  다르면 파일 전체가 되돌려진다. 대회 정보가 틀렸으면 조사 결과가 아니라 시드·관리자에서 고친다.
  (예전엔 여기서 멸망전 4개가 'ck' 로 덮여 153경기가 내전으로 집계됐다 — 0035)
- **새 대회를 만들 때는 `event.name` 과 `event.kind` 가 둘 다 필수다.** 기본값이 없다.
  `ck`=보상 걸린 스트리머 간 내전 · `scrim`=대회 준비 연습게임 · `tournament`=공식 대회 ·
  `showmatch`=이벤트전 · `other`
- `lead.kind` 는 적지 않는다(저장 안 된다). VOD 의 분류는 그 VOD 에서 나온 경기의 대회가 정한다
- **`match.played_at_precision` 은 필수다.** `"datetime"`=경기 시작 절대시각까지 확인,
  `"date"`=날짜만 확실. 확인된 방송 시작과 연속성이 확인된 VOD 시간축의 경기 시작 오프셋으로
  계산했으면 `"datetime"`이다. 결과창 시각을 경기 시작으로 쓰지 않는다. 방송 시작 또는 시간축이
  불확실하면 정밀도를 올리지 않는다. 구간 재사용에는 시작뿐 아니라 확인된 종료 경계도 필요하다
- **`match.set_order_known: true`** 는 그 시리즈의 세트 순서를 VOD 에서 **직접 확인했을 때만** 적는다
  (화면의 세트 표기·같은 방송에서 차례로 본 판). 모르면 비운다 — 화면은 "N세트" 대신 「세트」로 쓴다.
  한 번 true 가 된 시리즈를 자동 수집이 false 로 내리지는 않는다
- **VOD 판독 경기(`match`)는 그 VOD 의 `scan` 결과와 같이 넣는다.** 이미 조사해 넣은 VOD 면
  `source_url` 로 이어진다. 둘 다 없으면 파일 전체가 되돌려진다 — 경기만 들어가면 검수 화면에서
  그 VOD 로 갈 길이 없다. `evidence_frames` 의 경로도 scan 으로 먼저 기록돼 있어야 한다(없으면 거부)
- 결과 파일 하나는 **한 트랜잭션**이다. 후보의 `match_id` 가 가리키는 경기는 같은 파일 안에 있거나
  이미 DB 에 있어야 한다 — 없으면(오타 포함) 파일 전체가 되돌려진다

재전송은 중복을 만들지 않는다. 후보는 `id` 로, 프레임은 경로로, 경기는 `match_id` 로 합쳐진다.
**검수된 경기는 자동 수집이 못 덮는다** — 그때 `ck:merge` 가 `⏭` 로 알린다. 성공으로 세지 마라.

## 갈리는 판단 — 정답을 정해 두지 않는다

이 질문들은 **매번 다르게 답이 난다.** 근거를 보고 네가 정하고, 정한 이유를 적는다.

- 이 화면은 플레이인가, 리플레이인가, 남의 방송 시청인가? 어느 경기의 근거로 쓸 수 있나?
- 앞뒤 구간이 같은 경기인가, 다음 세트인가, 팀이 바뀐 다른 판인가?
- 이 이름을 그 사람에게 걸 근거가 있나? 더 확인할까, 미해결로 둘까?
- 결과 화면·오버레이·음성이 다르면 — 시각 차이인가, 다른 판인가, 오독인가?
- 더 보면 이 결론이 바뀔 가능성이 있나?

**결과 판독의 우선 근거는 그 경기의 최종 결과 화면이다.** 채팅 공지·오버레이·전사는
탐색과 맥락에 쓴다(오버레이는 공지를 비추는 위젯이라 독립된 증거가 아니다).
화면이 없거나 자료가 어긋나면 **숨기지 말고 적는다.**

### 결과 화면을 찾는 기본 방법

정상 종료라면 결과 화면이 나타날 가능성과 정보 가치가 높으므로, 다른 보충 조사보다 먼저
충분히 시도한다. 마지막으로 확실한 **현재 경기 진행 화면**과 처음으로 확실한 **그 경기 종료
후 화면** 사이를 기본적으로 `--divide 5`로 나누고, 좁히기 판단에 쓸 지점을 실제로 연다. 결과 화면이 없으면 가장 뒤의
확실한 진행 화면과 가장 앞의 확실한 종료 후 화면을 새 기준점으로 삼아 반복한다.

브라우저·로딩·다른 창·판단하기 어려운 리플레이는 기준점이 아니다. 이런 화면 때문에 안 연
구간을 버리지 말고 미확정으로 남긴다. **5분할을 반복해 더 좁혀지지 않는 짧은 구간**이 남으면
그 조각을 기본 `--step 2`(길면 3)로 확인한다. 결과창은 보통 몇 초 이상 떠 있다. 짧게 스친 단서가 있으면
더 촘촘히 봐도 된다. **미발견으로 닫을 때는 마지막 탐색 간격을 기록한다.**
채팅·음성이 정확한 시각을 주면 그곳부터 시작할 수 있다.

다음 경우에만 탐색을 닫는다.

- 결과 화면을 읽음 → **충분한 결과 화면 / 부분 결과 화면**
- 5분할을 반복하고 마지막 조각을 기본 2~3초 간격으로 모두 열었으나 없음 → **결과 화면 미발견** (그 간격에서의 관찰)
- 다른 참가자 시점에서 같은 경기의 동등하거나 더 좋은 결과 화면을 확보함
- VOD 끝·HLS 누락·지속적인 가림으로 확인할 수 없음 → **결과 화면 확인 불가**

확인 불가는 미발견과 다르다. 못 연 범위를 `scan.failed`와 남은 질문에 기록한다. 결과 화면을
찾으면 인접 프레임에서 가장 잘 보이는 것을 고르고, 실제로 읽힌 값만 쓴다. 네 상태 중 어느
것이든 `done`을 막지 않는다. 그러나 **네 상태 중 하나에 닿지 않은 판이 있으면 `done`이 아니다.**
안 연 프레임을 근거로 종료하거나 애매한 화면만으로 미발견을 선언하지 않는다.
이 네 사유는 해당 시점의 결과창 탐색 종료다. 부분 결과·미발견·확인 불가만으로 다른 시점의
조사까지 생략하지 않는다. 남은 공백은 다음 절의 교차검증에서 처리한다. 현재 큐는 `done`이어도
`scan.failed`가 남으면 재시도하므로 영구적 확인 불가와 재시도 가능 실패를 메모에서 구분한다.

### 같은 경기의 다른 시점을 다루는 방법

한 CK 를 여럿이 방송하므로 같은 경기가 VOD 여러 개에서 나온다. **모든 VOD 는 같은 방식으로 경기를 읽고
`match` 로 낸다.** 이미 있는 경기면 저장 도구가 **시점을 더한다** — 경기 값은 한 벌로 두고, 이 VOD 의
사진과 이 화면에서 직접 읽은 값이 그 경기 아래 붙는다. 같다·다르다는 도구가 계산한다. 조사자는 일치를
선언하지 않는다([설계](../../../docs/CK-MULTI-POV-PLAN.md)).

**지금은 기존 경기라도 처음부터 읽는다** — 경기 추적 3단계, 판마다 결과창 탐색. 기존 기록을 보고
탐색을 줄이지 않는다. 여러 시점이 각자 읽어야 교차 확인이 된다(토큰 절약 단계는 아직 없다).

**시점 하나여도 조사 완료와 검수가 가능하다.** 다른 시점을 기다리지 않는다. 다른 시점이 나중에 붙으면
저장 도구가 반드시 비교하고, 새 불일치가 생기면 검수 완료를 풀어 다시 검수 대상으로 올린다.

#### 어느 경기인가 — 조사자가 정한다

- `--find-match --vod` · `--find-match <시각>` 가 후보를 보여준다. 같은 경기인지는 화면으로 판단한다.
- 판단 근거를 `pov.link_basis` 에 적는다 — 시각, 로스터, 챔피언, 세트 표기, 스코어 등 본 것.
- **±30분 안이라는 건 같은 경기의 증명이 아니다.** 연속 판·보너스 단판은 30분 안에 여럿 있다.
- 날짜만 확실한 기존 경기인데 같은 로스터의 연속 판이면, 세트 표기·챔피언 등 추가 근거 없이는 잇지 않는다.
- 확신이 없으면 기존 경기에 붙이지도, 새로 만들지도 말고 후보를 `unresolved` 로 남긴다.

#### 기존 경기에 시점을 더하는 제출

```json
{ "resultType": "match", "match_id": "<기존 경기 id>",
  "pov": { "source": "own", "link_basis": "같은 10명 로비, 결과창 31:05 · KDA 일치" },
  "winning_team": 100,
  "participants": [
    { "streamer_slug": "clid1", "team_id": 200, "champion_name": "나르", "kills": 13, "deaths": 1, "assists": 7 },
    { "observed_name": "붕어에몽", "team_id": 200, "kills": 11 }
  ],
  "evidence_frames": ["out/ck/208179061/g0017400.jpg"] }
```

- **이 화면에서 직접 읽은 칸만 낸다.** 못 읽은 값을 기존 기록에서 옮겨 적지 않는다 — 확인하지 않은
  값이 "일치" 로 보인다. 승자·길이·세트도 이 화면에서 본 것만.
- **생략 = 안 읽음 · `0` = 읽은 값 · `null` = 철회.** 재제출은 보낸 칸만 바꾸고, 바뀌거나 철회한 값은 이력에 남는다.
- 참가자는 `participant_id`·줄 순서가 필요 없다. 사람(`streamer_slug`·`observed_name`)으로 맞춘다.
  `team_id`·`winning_team` 은 **이 화면에서 보인 대로** 적는다(결과창은 자기 팀이 위다) — 도구가 사람으로 경기 쪽 팀에 대응시킨다.
- `pov.source` — `own`(방송 주인 본인 클라이언트) · `rebroadcast`(남의 방송을 띄운 화면, 몇 시간 뒤 다시 보기 포함).
  본인 화면인데 방송 주인이 그 경기 참가자에 없으면 거부된다.
- `pov.link_basis` 는 필수다.
- 사진은 밴픽·로딩·인게임·결과창 모두 붙인다. 이 VOD 사진만 붙고, 사람이 떼어 낸 사진은 되돌아가지 않는다.
- 본인 화면이고 경기 시각이 확인돼 있으면, 경기 ±30분 밖 사진은 **모순으로 거부**된다. VOD 가 중간에
  끊겨 시각을 믿을 수 없으면 `pov.time_reliable: false` 로 알린다.
- 파일에 scan 이 여럿이면 `pov.source_key: "vod:<번호>"` 로 어느 VOD 시점인지 적는다.

#### 저장 도구가 하는 일 (조사자가 하지 않는다)

- 경기 쪽 칸이 비어 있으면 채운다. **다른 값은 덮어쓰지 않는다** — 불일치로 남고 검수에서 사람이 고른다.
- 검수된 경기는 값이 잠긴다. 시점·사진은 붙는다.
- 경기를 만든 VOD 만 붙어 있을 때는 그 VOD 가 필수 정보를 다 채워 다시 내면 고칠 수 있다(같은 조사 중
  세트 순서 수정 등). 다른 시점이 붙은 뒤에는 비교만 한다.
- 출력의 `⚠ 불일치 N` 은 다시 볼 신호다. 내 오독이면 재제출로 고치고(이력 남음), 확실하면 그대로 둔다 — 사람이 고른다.
- `⚠ 경기에서 찾지 못한 사람` 은 이름 오독이거나 다른 판이다. 확인한다.

**신원(미등록 인게임명)은 빈칸이 아니다.** 결과창에서 읽은 이름을 `observed_name` 으로 남기면
[`/admin/ck/unknown`](../../../apps/web/app/admin/ck/unknown) 에 모이고 사람이 붙인다. 신원을 찾으러
다른 시점을 뒤지지 않는다.

- **추가 시점을 일부러 찾아 나서는 건** 결과 근거가 부족하거나 자료가 충돌할 때다 — 와치리스트 밖
  참가자 VOD 도 포함한다. 확보하지 못하면 시도와 한계를 기록한다. 재송출은 독립된 확인이 아니다.
- **판별로 통합한다.** 같은 판은 같은 `match_id`, 같은 시리즈의 판들은 같은 `series_id`. 앞 세트의 로스터를
  다음 판에 복사하지 않는다. 보너스 단판은 별도 경기다.
- **시리즈 전체를 하나로 덮지 않는다.** 판 사이·시리즈 전후·보너스 단판은 따로 조사한다.

검수는 경기 화면(`/admin/ck/match/<id>`)에서 시점별로 본다 — 스트리머마다 사진과 읽은 값이 나란히 나오고,
다른 칸은 미해결/검수 완료로 구분된다. 통합 결과는 첫 경기부터 누적 반영한다.

`vod_availability`는 채널별 운영 힌트다. `usually_unavailable`이어도 매일 VOD 목록 조회는
계속한다. VOD가 없다는 사실은 불참 증거가 아니며, 다른 참가자 시점에서 참여를 확인할 수 있다.

⚠ `결과 화면 N장`·`정황 N개`·`다른 시점 N개` 같은 **합격선을 만들지 마라.**
`후보가 둘이면 제외` · `조회 0건이면 오독` · `중계면 기각` 같은 **자동 결론도 만들지 마라.**
옛 스킬이 그렇게 했고, 정형 문구로 도장을 찍는 일이 판단을 대신하지 못했다.
([경기 추적](#경기-추적--반드시-끝까지)은 합격선이 아니다 — "몇 장 봤으면 됐다" 가 아니라
"종료 상태에 닿을 때까지 한다" 는 **수행**이고, 무엇을 봤는지의 해석은 여전히 네 몫이다.)

## 끝내기

```bash
npm run verify:db        # 스키마·질의를 건드렸을 때만
npm test                 # 조사 끝에 한 번
```

반영한 뒤 `ck:merge` 가 찍어 주는 **남은 일**을 그대로 전한다. 수를 지어내지 않는다.
`/admin/ck` 에서 무엇이 보이는지(읽은 프레임 / 경기 / 미해결 후보 / 못 본 구간)도 같이 말한다.

⚠ **경기 0 은 「경기 없음」이 아니다.** 아직 안 봤을 수도, 후보가 미해결일 수도 있다.
그 결론은 숫자가 아니라 네가 남기는 것이다.
