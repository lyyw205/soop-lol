# FC 경기 맥락 조사

경기 사실(누가 이겼나)은 **넥슨 API가 이미 안다.** 여기서 알아내는 것은 **무슨 판이었나**다 —
단순 친선인가, CK인가, 대회인가. VOD 화면으로 API 값을 다시 판독하지 않는다.

> **반드시 정해진 것은 「무엇을 수행하고 무엇을 기록하나」뿐이다.**
> 그 자료가 무슨 뜻인지, 어떤 결론을 내릴지, 더 조사할지는 **네가 판단한다.**

## 반드시 하는 것 / 네가 정하는 것

| 자리 | 반드시 수행·기록 | 네가 정한다 |
|---|---|---|
| 대상 | `fco:context list` 로 API 경기·기존 판단·행사 연결을 조회한다 | 어느 경기·VOD·시점부터 볼지 |
| 탐색 | 실제로 연 VOD 지점과 사용한 공지, 못 연 범위를 남긴다 | 후보 시간창, 프레임·채팅·음성의 범위 |
| 대조 | 후보 VOD 가 그 `matchId` 경기인지 화면 사실로 확인한다 | 같은 경기인지의 판단과 그 이유 |
| 기록 | 경기마다 결론(`casual`/`event`) **또는 미해결 사유**를 `apply` 로 반영한다. **실제로 연 프레임은 `frame_path` 로 근거에 건다** | 행사 분류·메타데이터·시리즈 경계 |
| 마무리 | 저장 결과와 ⏭(충돌·검수 보호) 항목을 구별해 보고한다 | 조사 중단 위치 |

**검수자는 입력하지 않는다 — 승인한다.** `/admin/fco` 는 네가 남긴 제안과 프레임을 대조해
도장을 찍는 자리다. 그래서 조사 대상마다 **결론 제안과 근거를 완결해서** 반영해야 한다 —
좌표만 남기고 프레임을 안 걸면 검수자가 화면을 다시 찾아야 하고, 그건 조사를 두 번 하는 것이다.

**행사 결론은 행사 단위로 검수된다.** 검수 화면은 그 행사의 전 경기를 한 묶음으로 놓고
프레임을 시간 순으로 넘긴다. 그래서 행사로 결론 내릴 때는 **대회의 시작부터 끝까지의 서사**가
프레임으로 따라와야 한다 — 시작(안내·브래킷·오버레이), 경기마다 그 matchId 경기임을 확인한
장면, 종료(최종 결과·시상·마무리 발언). 몇 장인지는 네 판단이지만, 검수자가 프레임만 넘겨도
"이 경기들이 정말 이 행사였다"를 따라갈 수 있어야 한다. 각 근거는 해당 경기의 `evidences` 에
건다 — 행사 공통 장면(개막 화면 등)은 시간상 가장 가까운 경기에 건다.

**모드와 맥락은 별개다.** `mode_key`(매치 타입)는 단순 친선의 증거가 아니다 — 친선 모드로도
컵·CK 를 한다(실측: 피온시식컵이 모드 40 이었다). **VOD 가 없어도 API 경기는 남는다** —
그건 `맥락 미확인`이지 `경기 없음`도 `단순 친선`도 아니다. `N장 확인` 같은 합격선은 없다.
없는 행사명·주최자를 지어내지 않고, 근거가 부족하면 `unresolved` 로 남긴다.

## 흐름

```
fco:context list --vods        미조사 경기 + 후보 VOD 시간창
  → fco:context locate          경기마다 VOD 몇 초인가 + 뽑을 명령 (4종 · 결과 화면)
  → ck:probe --vod … --at/--between  프레임      (네가 연다)
  ↔ ck:listen · 채팅 !공지       필요한 구간만
  → fco:context draft --vods …  **뽑은 프레임 전량이 열거된 초안**
  → 초안을 채운다               연 것은 observed 를 쓰고, 안 연 것은 줄을 지운다
  → fco:context apply --file    반영 (유일한 창구, --dry-run 지원)
  → fco:context show            저장 결과 확인 → 사람이 /admin/fco 에서 프레임 대조 후 승인
```

**초안부터 시작한다 — 빈 파일에서 근거를 떠올려 적지 마라.** 빈 배열에서 시작하면 기록이
기억에 의존하고, 실제로 그렇게 **26장을 읽고 2장만 걸었다**(2026-08-25 뿌챔스 조사).
`draft` 는 `out/ck/<vod>/` 의 프레임을 전부 열거하고 `observed` 를 비워 둔다.
빈 `observed` 는 저장이 거부하므로 **읽은 것은 채우고 안 읽은 것은 지워야** 반영된다 —
그 지점이 「뽑음」과 「읽음」을 가르는 자리다(`ck-research` 의 `scan-draft.json` 과 같은 구조).

시간창 초기값은 실측(docs/FCO-TIME-SAMPLES.md)에서 온다: **matchDate 는 경기 종료 시각**,
경기 구간 ≈ [matchDate−12분, matchDate]. 판정 규칙이 아니라 탐색 시작점이다.
프레임·전사의 시각은 전부 **VOD 전체 초** 하나로 쓴다(ck:probe 와 같은 축).

## 경기마다 뽑는 장면 — 4종 + 결과 화면

경기 시작은 넥슨 `matchId` 앞 8자리(16진 유닉스 초), 종료는 `matchDate`, VOD 0초는
`broad_start` 다. `locate` 가 이 셋으로 경기마다 VOD 초를 계산해 명령을 찍어 준다.

| role | 장면 | 무엇을 보여주나 |
|---|---|---|
| `pre` | 경기 전 (대기실·브래킷·대진 안내) | 이 대진이 예정돼 있었다 |
| `start` | 킥오프 직후 | 그 두 사람이 그 경기를 시작했다 |
| `end` | 종료 직전 경기 화면 | 경기가 끝까지 갔다 |
| `post` | 종료 후 (반응·다음 안내) | 끝난 뒤 흐름 |
| `result` | **결과 화면** (최종 스코어·득점자) | API 스코어와 같은 경기다 |

**결과 화면은 모든 포함 경기에 필수다.** 검수 화면은 경기를 고르면 `result` 프레임을 먼저
띄운다 — 검수자는 스코어를 API 값과 대조하는 것으로 판단을 시작한다. 무승부·연장·승부차기는
API 가 승자를 못 가리는 경우가 있어 결과 화면이 **유일한 근거**가 된다. `apply` 는 결과 화면
근거가 없는 경기를 경고로 찍는다. `locate` 의 4종 지점은 보정한 초기값이지 정답이 아니다 —
열어 보고 그 장면이 아니면 앞뒤를 더 본다. 연 프레임에는 본 장면대로 `role` 을 단다
(장면이 아니면 비운다. 추측해서 채우지 않는다).

### 결과 화면을 찾는 기본 방법

`locate` 가 주는 첫 구간 [종료−20초, 종료+60초] 을 `--divide 5` 로 나누고, **뽑은 지점을
모두 연다.** 결과창이 없으면 마지막으로 확실한 **경기 진행 화면**과 처음으로 확실한 **종료
후 화면**(다음 대기실·방송 화면)을 새 기준점으로 삼아 그 사이를 다시 `--divide 5` 한다.
더 좁힐 수 없는 마지막 짧은 구간만 `--step 1` 로 소진한다. 채팅·음성이 정확한 시각을 주면
거기서 시작해도 된다. 로딩·다른 창·리플레이는 기준점이 아니다.

다음 경우에만 탐색을 닫는다.

- 결과 화면을 읽음 → `role: "result"`, observed 에 **읽힌 스코어·이름 그대로**
- 좁혀진 구간의 모든 초를 열었으나 없음 → **결과 화면 미발견** (note 에 연 범위)
- 다른 참가자 VOD 에서 같은 경기의 결과 화면을 확보함
- VOD 끝·조각 누락·가림으로 확인할 수 없음 → **확인 불가** (못 연 범위를 note 에)

미발견과 확인 불가는 다르다. 결과창이 여러 장이면 가장 잘 읽히는 것을 `result` 로, 나머지도
연 것이면 근거로 건다(역할은 같게 둬도 된다). 뽑고 안 연 프레임으로 탐색을 닫을 수는 없다.

## 명령

```bash
npm run fco:context -- list [--from 2026-09-20 --to 2026-09-23] [--streamer slug] [--vods]
npm run fco:context -- locate --vods 205292057,205320949 (--event slug | --match-id id,… | --from/--to)
npm run fco:context -- draft  --vods … (--event slug | --from/--to) [--out out/fco/x.json]
npm run fco:context -- draft --vods 205292057,205320949 --event <행사slug> [--out out/fco/x.json]
npm run fco:context -- show --match-id <넥슨matchId>
npm run fco:context -- apply --file out/fco/0923.json [--dry-run] [--admin]
npm run fco:sync -- --streamer slug --nickname 감독명   # 계정 연결·경기 수집 (일일은 워커 engine_e_fco)
```

`ck:probe`/`ck:listen` 은 그대로 쓴다 — DB 에 아무것도 쓰지 않고, 추출한 프레임은 읽은
프레임이 아니다. **연 것만** 근거다.

## 반영 파일 — `apply` 입력

```jsonc
[{
  "provider_match_id": "6aafaa2f3d823566b1f0cca9",
  "conclusion": "event",              // "casual" | "unresolved" | "event" | 생략(근거만 추가)
  "note": "…",                        // casual/unresolved 의 근거·남은 질문 (필수)
  "event": {                          // conclusion=event 일 때
    "slug": "fc-sisik-cup-2026-09",
    "name": "고세구 피온시식컵",
    "kind": "ck",                     // ck | scrim | tournament | showmatch | other
    "source_url": "https://…"         // 확인 근거 URL 필수
  },
  "evidences": [{
    "evidence_key": "vod:207643193@1479",   // 멱등 키 — 네가 정한다
    "kind": "vod_frame",                     // vod_frame | chat | audio | notice | url
    "vod_title_no": 207643193, "channel_id": "phonics1", "at_sec": 1479,
    "frame_path": "out/ck/207643193/g0001479.jpg",  // 네가 실제로 연 파일 — 검수 화면이 띄운다
    "role": "end",                                   // pre|start|end|post|result — 본 장면. 아니면 생략
    "observed": "인게임 88:23, 교로텔리 3:4 호날두",   // 본 것
    "why": "matchDate 16초 전 88분 — 이 matchId 경기다"  // 해석. observed 와 섞지 않는다
  }]
}]
```

- **다전제(시리즈)**: 같은 두 사람이 연속 세트로 한 판의 승부를 가렸으면 세트마다 `series` 를 붙인다.
  ```jsonc
  "series": {
    "id": "fc-sisik-cup-2026-09-20:kimmingyo-doochiwa",  // 시리즈 정본 키
    "game_no": 2,                                         // 몇 번째 세트인가
    "best_of": 3,                                         // 모르면 비운다
    "best_of_evidence": "방송 공지 '3판 2선승'"            // best_of 를 줄 때만 필수
  }
  ```
  **상대가 바뀌면 시리즈가 아니다** — 그건 대회 안의 다른 매치업이라 `event` 로 묶는다(저장이 거부한다).
  `best_of` 는 화면·공지에서 읽은 근거 없이는 못 넣는다. **「연속 3경기니까 Bo3」는 추측이다** —
  형식을 모르면 비우고, 그래도 세트는 시리즈로 묶인다. 시리즈 승패는 저장하지 않고 세트에서 파생한다.
- **근거는 「실제로 연 것 전부」다.** 결론을 설득할 최소한이 아니다. 판단에 쓴 화면, 쓰지 않았지만
  열어서 확인한 화면, 어긋나 보였던 화면까지 전부 건다 — 검수자는 네 결론이 아니라 **네가 본 것**을
  대조한다. 뽑아 놓고 안 건 프레임이 있으면 `apply` 가 ⚠ 로 알린다.
- **결론과 근거의 뜻**: `casual`(단순 친선으로 판단, 근거 필수) · `unresolved`(모름, 남은 질문 필수) ·
  `event`(행사를 만들어 연결 — CK 면 `kind: "ck"`). CK/대회 결론은 문자열이 아니라 **event 연결**이다.
- 재전송은 중복을 만들지 않는다. 판단은 이력으로 쌓이고(최신이 현재), 근거는 `evidence_key` 로 합쳐진다.
- **admin 판단은 자동 반영이 못 덮는다** — ⏭ 로 알려주며 성공으로 세지 마라.
- 같은 slug 다른 이름·다른 kind 의 행사는 **거부된다**. 덮어쓰지 말고 확인하라.
- 시리즈에 속한 세트는 `match_series.event_id` 가 정본이라 직접 연결이 거부된다.
- 여러 POV 근거는 전부 남긴다. 경기당 하나로 관리되는 것은 **현재 최종 판단**뿐이다.

## LoL 조사와의 경계

- LoL 전량 조사 중 FC 화면을 **실제로 열어** 봤다면: `npm run fco:context -- clue --vod … --at … --observed "…"`.
  단서일 뿐 FC 경기 연결이 아니다. LoL 탐색의 나머지 범위를 생략할 이유도 아니다.
- FC 조사 대상은 LoL 스캔 결과로 제한되지 않는다 — API 에만 있는 경기도 후보다.
- VOD 화면에 FC 가 보여도 API `matchId` 와 대조하기 전에는 그 경기로 묶지 않는다.

## 갈리는 판단 — 정답을 정해 두지 않는다

- 이 화면은 본인 플레이인가, **남의 방송 시청/중계인가**? (실측: 김민교가 고세구 방송을 보던 화면이 있었다)
- 연속된 경기들이 같은 행사인가, 행사 중간의 연습인가? CK 안의 연습 경기와 행사 경기를 구별할 근거가 있나?
- 채널이 미등록이면 `VOD 없음`이 아니라 `조사 불가`다 — 채널 등록이 먼저인지 판단하라.
- 더 보면 결론이 바뀔 가능성이 있나? 낮으면 어디서 멈출지.

## 끝내기

`apply` 출력의 **남은 일**(미조사·미해결 수)을 그대로 전한다. 수를 지어내지 않는다.
`npm run verify:fco-context` 는 스키마·계약을 건드렸을 때만 돌린다.

⚠ **FC 화면 부재는 부정 증거가 아니다.** 방송을 안 켰거나, VOD 를 안 남겼거나, 다른 채널에서
했을 수 있다. 그 결론은 숫자가 아니라 네가 남기는 것이다.
